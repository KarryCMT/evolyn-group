# 远程组件与插件运行时功能设计V1

> 文档状态：V1.0
> 适用项目：Evolyn / 灵衍云企业级低代码平台
> 适用范围：Vue 3 表单设计器、表单运行时、低代码组件插件、插件中心
> 前端基线：Vue 3.5 + TypeScript + Element Plus + Vite/Rolldown + Turborepo + pnpm workspace
> 后端基线：Go 1.25 + Gin + PostgreSQL + Redis + MinIO
> 设计目标：建立一套从**插件设计 → 开发 → 本地调试 → 自动测试 → 编译 → 制品校验 → 上传 → 审核 → 发布 → 租户安装 → 表单设计使用 → 运行时加载 → 版本升级/回滚 → 下架治理**的完整组件扩展机制。

---

## 1. 文档目标

Evolyn 当前前端已经具备 Vue 3、Element Plus、TypeScript、Monorepo 与共享 UI 包基础。随着表单设计器与表单运行时逐步落地，仅依赖平台内置组件会很快遇到以下问题：

1. 平台团队无法长期承担所有行业组件开发。
2. 企业客户需要接入自己的 CRM、ERP、MES、WMS、OA、地图、签章、扫码、打印等业务组件。
3. 不同行业需要不同的字段组件、展示组件和业务选择器。
4. 内置组件每次增加或修改都跟随主站发布，会降低平台迭代效率。
5. 第三方组件直接进入主工程会污染依赖、增加安全风险，并导致版本不可控。
6. 表单设计阶段与运行阶段对组件能力要求不同，需要统一协议。
7. 已发布表单必须保持可重复运行，不能因为组件最新版变化而自动改变行为。

因此，Evolyn V1 不将“远程组件”设计成简单的 CDN JavaScript 加载能力，而定义为：

> **Evolyn Component Extension Runtime（Evolyn 组件扩展运行时）**

其核心由以下能力组成：

- Component Definition：统一组件定义协议
- Component Registry：组件注册中心
- Component SDK：插件开发 SDK
- Component Manifest：插件制品描述协议
- Federation Runtime：可信远程组件加载器
- Sandbox Runtime：非可信插件隔离运行时
- Designer Adapter：设计器适配层
- Renderer Adapter：运行态适配层
- Property Schema Engine：属性面板 Schema 引擎
- Event / Action Contract：事件与动作协议
- Plugin Registry Service：后端插件注册与版本管理
- Plugin Center：插件安装、升级、卸载入口
- Artifact Repository：MinIO 插件制品仓库
- Version Snapshot：表单依赖冻结
- Security / Audit / Observability：安全、审计与可观测能力

## 2. V1 核心设计原则

### 2.1 表单 Schema 不感知物理部署地址

错误方式：

```json
{
  "type": "remote",
  "remoteEntry": "https://cdn.example.com/remoteEntry.js",
  "component": "CustomerSelector"
}
```

推荐方式：

```json
{
  "id": "field_customer",
  "type": "crm.customer-selector",
  "field": "customerId",
  "label": "客户",
  "props": {
    "multiple": false
  }
}
```

组件实际部署位置由 Component Registry 解析。

这样可避免：

- CDN 域名变化影响历史表单；
- 开发、测试、生产地址写入业务 Schema；
- 插件升级后无法控制表单版本；
- 插件下架导致 Schema 被污染；
- 组件部署策略与表单定义强耦合。

---

### 2.2 内置组件与远程组件使用同一注册协议

Renderer 不允许通过大量 `if / switch` 区分：

- input
- select
- date
- built-in
- remote
- iframe

统一：

```ts
const definition = componentRegistry.resolve(node.type);
```

然后由 Runtime Loader 负责物理加载。

---

### 2.3 设计器与运行时分离

一个组件至少存在两个角色：

```text
Component
├── Designer
└── Runtime
```

Designer 负责：

- 设计器画布预览；
- 属性变化响应；
- 设计时占位；
- 禁止危险业务动作；
- 数据源模拟；
- 异常提示。

Runtime 负责：

- 真实数据读取；
- 双向绑定；
- 权限控制；
- API 调用；
- 真实业务事件；
- 校验；
- 用户交互。

当组件未提供 Designer 时：

```text
Designer Adapter
    ↓
Runtime Component
    ↓
readonly / designMode
```

作为降级策略。

---

### 2.4 不可信 JavaScript 不进入主页面执行上下文

Module Federation 不是安全沙箱。

因此 V1 明确区分：

| 信任等级 | 运行模式      | 典型来源                      |
| -------- | ------------- | ----------------------------- |
| system   | builtin       | Evolyn 内置                   |
| trusted  | federation    | Evolyn 官方、企业内部审核组件 |
| sandbox  | iframe        | 第三方、未知代码              |
| reserved | web-component | V2 跨框架扩展                 |

---

### 2.5 表单发布时冻结组件依赖

Form Definition 推荐：

```json
{
  "schema": {},
  "dependencies": {
    "evolyn.input": "1.0.0",
    "crm.customer-selector": "1.2.0",
    "erp.material-selector": "2.4.1"
  }
}
```

运行时永远按照已发布版本依赖解析。

插件发布新版本不能自动改变历史表单。

# 6. Component Definition 协议

## 6.1 基础类型

```ts
export interface EvolynComponentDefinition {
  key: string;
  version: string;

  meta: EvolynComponentMeta;

  runtime: EvolynRuntimeDefinition;

  designer?: EvolynDesignerDefinition;

  props: EvolynPropDefinition[];

  events?: EvolynEventDefinition[];

  slots?: EvolynSlotDefinition[];

  capabilities?: EvolynComponentCapability[];

  defaultProps?: Record<string, unknown>;

  validation?: EvolynValidationDefinition;

  lifecycle?: EvolynLifecycleDefinition;
}
```

---

## 6.2 Component Key 规范

格式：

```text
namespace.component-name
```

例如：

```text
evolyn.input
evolyn.select
evolyn.date-picker

crm.customer-selector
erp.material-selector
mes.work-center-selector
map.location-picker
signature.e-signature
```

规范：

- 全局唯一；
- 只允许小写；
- namespace 不少于 2 个字符；
- 不允许使用 `evolyn` 命名空间，除非官方插件；
- 发布后 key 不允许修改；
- 展示名称可以修改；
- key 与版本共同定位制品。

---

## 6.3 元数据

```ts
export interface EvolynComponentMeta {
  name: string;
  title: string;
  description?: string;
  category: string;
  icon?: string;
  keywords?: string[];
  author?: string;
  homepage?: string;
  license?: string;
}
```

# 7. 字段组件统一 Runtime Contract

表单字段组件必须遵循：

```ts
export interface EvolynFieldComponentProps<T = unknown> {
  modelValue: T;
  fieldId: string;
  fieldKey: string;

  disabled?: boolean;
  readonly?: boolean;
  required?: boolean;

  designMode?: boolean;

  context?: EvolynRuntimeContext;
}
```

标准事件：

```ts
export interface EvolynFieldComponentEmits<T = unknown> {
  (e: 'update:modelValue', value: T): void;
  (e: 'change', value: T): void;
  (e: 'blur'): void;
  (e: 'focus'): void;
}
```

远程字段组件不得自行约定：

```text
value
data
selectedValue
current
```

等非统一值协议。

# 8. Component SDK

## 8.1 SDK 的职责

第三方组件不能直接依赖宿主：

- Pinia store；
- Vue Router；
- Axios 实例；
- 全局变量；
- 用户 token；
- tenant store；
- document.cookie；
- localStorage；
- Evolyn 内部 API 目录。

所有平台能力通过 SDK 提供。

---

## 8.2 SDK 示例

```ts
import {
  defineEvolynComponent,
  useEvolynContext,
} from '@evolyn.do/component-sdk';

export default defineEvolynComponent({
  key: 'crm.customer-selector',

  setup() {
    const ctx = useEvolynContext();

    async function search(keyword: string) {
      return ctx.http.request({
        resource: 'crm.customer',
        action: 'search',
        params: { keyword },
      });
    }

    return {
      search,
    };
  },
});
```

---

## 8.3 Runtime Context

```ts
export interface EvolynRuntimeContext {
  tenant: {
    id: string;
  };

  app: {
    id: string;
  };

  form: EvolynFormContext;

  user: EvolynUserContext;

  http: EvolynHttpClient;

  actions: EvolynActionClient;

  events: EvolynEventBus;

  ui: EvolynUIBridge;

  logger: EvolynPluginLogger;
}
```

---

## 8.4 Form Context

```ts
export interface EvolynFormContext {
  getValue(field: string): unknown;

  setValue(field: string, value: unknown): void;

  getValues(): Record<string, unknown>;

  validate(field?: string): Promise<boolean>;

  getFieldState(field: string): EvolynFieldState | undefined;
}
```

V1 对 `setValue` 做权限限制：

插件原则上只能修改：

- 自己绑定字段；
- Manifest 声明允许写入的字段；
- 用户在设计器明确授权的字段。

# 9. 属性 Schema

## 9.1 原则

插件不直接提供完整 `PropertyPanel.vue`。

首选：

```text
props schema → Evolyn Property Engine → 平台统一属性面板
```

这样保证：

- UI 风格统一；
- 暗黑模式统一；
- 国际化统一；
- 校验统一；
- 权限统一；
- 设计器升级不受插件实现影响。

---

## 9.2 示例

```json
[
  {
    "key": "placeholder",
    "title": "占位文本",
    "editor": "input",
    "group": "basic"

  {
    "key": "multiple",
    "title": "允许多选",

    "default": false,
    "group": "basic"
  },
  {
    "key": "maxCount",
    "title": "最多选择数量",
    "editor": "number",
    "visibleWhen": {
      "multiple": true
```

# 11. Evolyn Plugin Manifest

Evolyn 不直接把 Module Federation 的 `mf-manifest.json` 当作完整业务 Manifest。

应额外定义：

```text
evolyn-plugin.json
```

Module Federation Manifest 负责技术运行时。

Evolyn Manifest 负责平台业务协议。

---

## 11.1 示例

```json
{
  "schemaVersion": "1.0",

  "plugin": {
    "key": "crm-components",
    "name": "CRM 组件包",
    "version": "1.2.0",
    "publisher": "example",
    "license": "commercial"
  },

  "runtime": {
    "type": "federation",
    "manifest": "./mf-manifest.json",
    "minEvolynVersion": "1.0.0"
  },

  "components": [
    {
      "key": "crm.customer-selector",
      "title": "客户选择器",
      "runtimeExpose": "./CustomerSelector",
      "designerExpose": "./CustomerSelectorDesigner",
      "category": "CRM",
      "icon": "./assets/customer.svg",
      "propsSchema": "./schema/customer-selector.props.json",
      "eventSchema": "./schema/customer-selector.events.json"
    }
  ],

  "permissions": ["network:crm"]
}
```

# 12. 插件包与组件关系

V1 推荐：

```text
Plugin 1 : N Components
```

例如：

```text
CRM Component Plugin
├── CustomerSelector
├── ContactSelector
└── OpportunitySelector
```

数据库里需要分离：

```text
Plugin
Plugin Version
Component
Component Version
```

原因：

- 一个插件可以发布多个组件；
- 插件整体升级；
- Component Key 独立引用；
- 表单可以只使用某个组件；
- 依赖扫描按 Component Version 完成。

# 102. 为什么 V1 选择 Module Federation

Module Federation Runtime 可以运行时动态注册和加载远程模块，非常符合：

```text
租户安装插件后
无需重新编译 Host
即可增加组件
```

的低代码平台场景。

生产者 Manifest 能描述：

- remote entry；
- exposes；
- assets；
- shared；
- types；

适合作为技术层 Remote Descriptor。

Evolyn 再在其上增加业务 Manifest。

---

# 103. 为什么不优先选择 qiankun / single-spa

它们更适合：

```text
Application Micro Frontend
```

即页面 / 子应用级编排。

Evolyn 当前核心需求是：

```text
Field / Component Dynamic Extension
```

粒度更细。

因此 Module Federation 更匹配。

未来插件提供完整页面时，可以另设：

```text
micro-app runtime
```

不与表单组件 runtime 混在一起。

---

# 104. 为什么不在线编译 Vue SFC

拒绝：

```text
用户上传 .vue
   ↓
浏览器 @vue/compiler-sfc
   ↓
execute
```

主要原因：

- 安全；
- 性能；
- 编译器体积；
- 依赖解析；
- CSP；
- sourcemap；
- 错误隔离；
- 版本治理；
- 可重复构建。

平台负责：

```text
执行经过构建和审核的制品
```

而不是：

```text
在终端浏览器编译第三方源码
```

# 117. V1 数据一致性原则

数据库状态更新与 MinIO 操作不能简单放在一个“假事务”里。

推荐：

```text
DB create upload record
   ↓
MinIO upload
   ↓
complete callback
   ↓
DB validating
```

删除制品等异步清理可使用：

```text
Outbox / Asynq
```

但正式发布状态必须以 PostgreSQL 为事实源。

# 118. 发布不可变原则

一旦：

```text
plugin_version.status = released
```

禁止：

- 替换 artifact；
- 修改 Manifest；
- 修改 component expose；
- 修改 integrity；
- 修改 permission contract。

只能：

```text
publish new version
```

# 122. 最终建议

Evolyn 当前阶段不要把目标描述为：

> “给 Vue3 表单设计器增加远程组件加载。”

正确目标应该是：

> **建立 Evolyn Component Extension Runtime，让表单设计器和运行态能够安全、可治理、可版本化地使用平台内置组件、官方远程组件和未来的第三方插件。**

V1 的真正技术核心不是 Module Federation 本身，而是：

```text
统一 Component Contract
          +
Component Registry
          +
Component SDK
          +
Plugin Manifest
          +
Version Snapshot
          +
Artifact Governance
          +
Trusted / Sandbox Runtime
```

Module Federation 只是其中“可信远程 JavaScript 模块加载”的实现手段。

只要前面这些协议稳定，未来无论替换 Remote Loader、增加 Web Components、接入 iframe、增加移动端插件，Form Schema、Designer 和 Renderer 都不需要推倒重做。

---

# 123. 推荐实施优先级

最终执行顺序建议严格保持：

```text
P0
Component Contract
Component Registry
Form Renderer Registry 化
Designer Registry 化

P1
Component SDK
Property Schema
Event Schema
Plugin Manifest

P2
Federation Runtime
Remote Designer
Remote Renderer
Error Boundary

P3
Plugin CLI
Playground
Contract Test

P4
Go Plugin Registry
PostgreSQL
MinIO Artifact

P5
上传 / 校验 / 审核 / 发布
Tenant Install

P6
Form Dependency Snapshot
Upgrade / Rollback / Block

P7
Sandbox Runtime
Third-party Plugin
```

其中：

> **P0 + P1 是所有后续能力的架构地基。**

不要先做上传页面，也不要先做插件市场 UI，更不要先把 `remoteEntry.js` 写死到 Form Schema。
