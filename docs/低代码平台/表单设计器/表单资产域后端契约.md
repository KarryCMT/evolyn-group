# 表单资产域后端契约（P0 协议冻结交付物）

本文件冻结表单资产域（表单资产 / 草稿 / 不可变发布版本 / 记录提交）的数据模型、API
契约、错误码、权限、配额与版本策略，供 P1/P2 后端实现与前后端联调对齐。域归属与结构
遵循 ADR-007 域模块化：`internal/platform/form/`（controller → service → repository
小三层 + 域根 `errors.go`），装配点 `internal/platform/server/server.go`。

## 1. 数据模型

### 1.1 forms（表单资产 + 草稿，迁移 000037/000044/000045）

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGSERIAL PK | | 内部主键，仅供表内关联与菜单 target_id 使用，不出网 |
| tenant_id | BIGINT NOT NULL DEFAULT 1 | | 租户归属（GORM Callback 过滤） |
| application_id | BIGINT NOT NULL REFERENCES applications(id) | | 所属应用；服务层同租户校验，归档应用禁止新建/发布 |
| code | varchar(64) NOT NULL | 租户内未软删唯一，`form_` 前缀 | 稳定公开编码；路由、API 与菜单 target 出网统一使用 |
| name | varchar(128) NOT NULL | | 表单名称（trim 后 1–128 字符）；**表单名称不进入协议 content** |
| form_type | varchar(16) NOT NULL DEFAULT 'standard' | `standard/workflow` CHECK | 表单类型，创建后不可变；存量统一回填 standard，设计器能力只以此字段为准 |
| draft_content | JSONB NOT NULL | `jsonb_typeof = 'object'` | 目标协议草稿全文（根结构 `{content:{type,items}}`）；完整校验在 Service |
| draft_revision | BIGINT NOT NULL DEFAULT 1 | | 草稿乐观锁口令：每次草稿保存条件递增，客户端原样回传 |
| protocol_version | INT NOT NULL DEFAULT 4 | | 协议版本外部承载（文档内无版本字段，v4 增加子表单权限与端侧展示配置） |
| latest_version_id | BIGINT NULL REFERENCES form_versions(id) | | 最新发布版本；NULL=从未发布 |
| published_version | INT NOT NULL DEFAULT 0 | | 冗余最新发布号（0=未发布），供列表展示免 JOIN |
| creator_member_id | BIGINT NOT NULL | | 创建者（审计语义） |
| created_at / updated_at / deleted_at | timestamptz | | 软删单轨 |

索引：`idx_forms_tenant_app ON forms(tenant_id, application_id, id DESC) WHERE deleted_at IS NULL`；
`uk_forms_tenant_code ON forms(tenant_id, code) WHERE deleted_at IS NULL`。

### 1.4 与既有资产的关联

- **应用菜单（M2-资产-1 最小纵切已落地）**：`application_menu_entries.entry_type='form'`
  的 `target_id` 即 `forms.id`。表单创建在**同一事务内**自动挂菜单节点（`menu_` 编码
  服务端生成、sort 同父最大 +1024）并递增 `applications.menu_revision`：创建请求可选
  `parentEntryCode`（同应用分组节点编码，即侧栏资产 code）传入时挂到该分组下，为空挂
  应用根级；非法分组（不存在/非分组/跨应用）返回 `APP_MENU_PARENT_INVALID` 并整体回滚。
  改名同事务同步节点名；软删表单同事务软删节点。菜单读接口侧经表单目录窄端口
  （`FormDirectory.ExistingFormTargets`）做存在性裁剪，并把 form 节点 `target.code`
  投影为 `form_` 前缀公开编码（与工作区路由参数一致）、`target.formType`
  投影为 `standard/workflow`。跨域经装配层窄端口双向适配
  （form→application 用 `MenuMaintenance`，application 读侧用 form 仓储适配），
  域间不直接依赖。菜单管理写接口（分组/移动/重排）仍随 M2-菜单-3 落地。
- **配额**：`tenant` 域 `QuotaForms("forms")` 键（套餐默认：免费 10 / 试用 50 / 专业 -1）。
  创建表单走 `QuotaService.CheckAndReserve`（同应用域 §10 口径）；软删释放名额。
  `QuotaService` 增加表单计数器与到期守卫键 `forms`（权益解析器键一致）。

## 2. API 契约

统一前缀 `/api/v1`，响应 `{code,msg,data}`（httpx 统信封）。鉴权经租户域中间件链；
URL 首段即 RBAC 资源名（`/forms` → `forms`、`/form-records` → `form-records`、
`/applications/...` → `applications`）。

### 2.1 P1：表单资产与草稿

| 方法与路径 | 动词（权限） | 说明 |
| --- | --- | --- |
| POST /forms | forms:create | 创建表单资产：`{applicationId, name, formType, parentEntryCode?}`，`formType` 必须为 `standard/workflow`（非法返回 400 `FORM_TYPE_INVALID`）；parentEntryCode 为同应用分组节点编码，菜单节点挂到该分组下，为空挂根级；非法分组 400 `APP_MENU_PARENT_INVALID`；事务内配额占位；草稿初始化为空协议文档 `{content:{type:"form",items:[]}}`；返回 FormDetail |
| GET /forms?applicationId=&limit=&cursor= | forms:list | 应用内表单游标分页（不含草稿全文，FormSummary） |
| GET /forms/:code | forms:get | 按 `form_` 公开编码读取详情（含 formType、草稿全文、draftRevision、publishedVersion） |
| PATCH /forms/:code | forms:patch | 白名单更新 `{name?, icon?, color?}`（ADR-011「修改名称和图标」单一权限点）：名称 trim 后 1–128 字符（400 `FORM_NAME_INVALID`）；图标/颜色为稳定键（空串清空，超长 400 `FORM_ICON_INVALID`），经菜单维护端口同事务同步到菜单节点展示属性（出网投影为 null） |
| PUT /forms/:code/draft | forms:update | 保存草稿 `{draftRevision, protocolVersion, content}`：只接受当前 v3（历史 v1/v2 读取后先迁移），支持表单默认列布局、`multitab` 布局定义与顶层/页内字段引用；先按字段字典严格校验（失败 400 + issues），再条件递增 revision（冲突 409）；返回新 `{draftRevision}` |
| DELETE /forms/:code | forms:delete | 软删表单；已发布版本行保留（历史记录仍可追溯），配额释放 |

FormDetail 出网：`{applicationId, code, name, formType, draftRevision, publishedVersion, draft, createdAt, updatedAt}`，
其中 `draft` 即协议全文，`protocolVersion` 为外部版本口令。全量替换式保存（非增量补丁），保证「未编辑属性不丢失」由
客户端原样回传 + 服务端原样落库共同保证。

### 2.2 P2：发布、运行时 bootstrap、提交

| 方法与路径 | 动词（权限） | 说明 |
| --- | --- | --- |
| POST /forms/:code/publish | forms:create（POST 动词；一期不拆独立发布权） | 发布：`{draftRevision}`；校验草稿 revision → 白名单校验（白名单外控件 400 + path）→ 严格字典校验 → 事务内创建不可变快照并回写 latest；返回 `{publishedVersion, schemaRevision}` |
| GET /applications/code/:appCode/forms/:formCode/runtime | applications:get（全体成员可读） | 运行时 bootstrap：校验 appCode↔form 归属、应用 active、表单已发布；返回 `{formCode, name, publishedVersion, schemaRevision, content}` |
| POST /form-records | form-records:create（authenticated 基线授予） | 提交：`{formCode, publishedVersion, schemaRevision, values}`；服务端先按公开编码解析内部 form_id，再按 `(form_id, version_no)` 定位快照并复核 schemaRevision（不符 409 FORM_VERSION_CONFLICT，历史版本合法）；逐字段校验值（失败 400 FORM_RECORD_INVALID + `fieldErrors{widgetName:[msg]}`）；落库返回 `{recordId}` |

提交值校验按字典 §4：未知键、白名单外控件值、类型不符、选项外值、必填空值、
`separator` 携值均拒绝；服务端以快照为准，不信任浏览器结果。

**`SubmitFieldValue.visible` 口径（v6 起，`docs/低代码平台/表单设计器/不可见字段
赋值前后端设计方案.md`）**：每个非布局字段必须显式携带 `visible` 且等于服务端
计算的有效可见性——`静态 widget.visible ∧ 权限矩阵可见（addFields/editFields 投影）
∧ 显隐规则求值结果`；有效不可见字段不得携带 `data`（携值即 `FORM_RECORD_INVALID`
按 widgetName 回填），其落库值由不可见字段赋值策略决议（`clear` 类型化空值 /
`preserve` 事务内锁定基线 / `recompute` 服务端执行器，执行器交付前 `3` 不可配置）。
新建提交、编辑提交（API 开放时）与流程写回（WorkflowRecordStore，以记录基线 +
受信 patch 合并值重算）共用同一值决议器 `ResolveSubmittedValues` /
`ResolveMergedRecordValues`；编辑提交以 `publishedVersion + schemaRevision` 定位
目标快照、记录基线在事务内锁定。v6 前的历史发布快照保持旧静态可见语义提交，
不做批量迁移；落库 `tn_form_records.values` 保留全部可处理字段键（类型化空值
而非删除键）。

### 2.3 菜单按钮动作（ADR-011，docs/低代码平台/应用管理/菜单按钮权限与节点状态设计方案.md）

| 方法与路径 | 动词（权限） | 说明 |
| --- | --- | --- |
| POST /forms/:code/switch-type | forms:create + 动作键 `form-actions:switch-type` | 切换表单类型：`{formType}`；standard↔workflow 互转（ADR-011 起类型可切换，流程表单切标准后原流程数据保留，仅不可再发起流程）；与当前类型相同 400 `FORM_TYPE_UNCHANGED`；草稿与发布快照不受影响；返回 FormDetail |
| POST /forms/:code/copy | forms:create + 动作键 `form-actions:copy-in-app`（目标为空或等于源应用）/ `form-actions:copy-cross-app`（跨应用） | 复制表单：`{targetApplicationId?, parentEntryCode?}`；复制草稿全文与表单类型（不复制发布快照与记录），名称追加「（副本）」超长截断；目标应用须 active 且 400 `FORM_APP_INVALID`；事务内占目标配额并挂目标应用菜单（非法分组 400 `APP_MENU_PARENT_INVALID`）；返回 FormDetail（201） |
| GET /forms/:code/references | forms:get | 引用视图：跨应用反查引用该表单的菜单节点，返回 `[{applicationCode, applicationName, entryId, entryName, parentEntryId}]`；只读诊断信息，不做应用可见性裁剪 |

## 3. 稳定错误码（域根 errors.go，ADR-008）

| errCode | HTTP | 场景 |
| --- | --- | --- |
| FORM_NOT_FOUND | 404 | 表单不存在或无权访问（跨租户同口径） |
| FORM_NAME_INVALID | 400 | 表单名称非法（1–128 字符） |
| FORM_TYPE_INVALID | 400 | 表单类型非法（只允许 standard/workflow） |
| FORM_TYPE_UNCHANGED | 400 | 切换类型时目标类型与当前相同（ADR-011） |
| FORM_ICON_INVALID | 400 | 图标/颜色稳定键非法（空串清空，其余最长 32 字符） |
| FORM_APP_INVALID | 400 | 应用不存在/跨租户/已归档，或表单不归属该应用 |
| FORM_SCHEMA_INVALID | 400 | 草稿协议校验失败；data 携带 `issues:[{path,message}]`（JSON Path 级） |
| FORM_REVISION_CONFLICT | 409 | 草稿修订号过期（他人已保存），客户端刷新后重试 |
| FORM_PUBLISH_UNSUPPORTED_FIELD | 400 | 发布命中白名单外控件；data 携带 `issues:[{path,message}]` |
| FORM_NOT_PUBLISHED | 404 | 表单尚未发布（bootstrap） |
| FORM_VERSION_CONFLICT | 409 | 提交的 publishedVersion/schemaRevision 与快照不符 |
| FORM_RECORD_INVALID | 400 | 提交值校验失败；data 携带 `fieldErrors` |
| QUOTA_EXCEEDED / FORBIDDEN | 403 | 复用通用码（配额/越权） |

## 4. 权限模型

- 资源注册：`forms`（ClusterScope 同 applications 口径）+ `form-records`，均在
  `iam/repository.Init()` 种子登记。
- 基线规则：新租户 `seedTenantBaseline` 追加 `tenant-admin: {forms, *}`、
  `authenticated: {form-records, create}`；存量租户经迁移 000037/000038 补授
  （tenant-admin 按「管理员规则签名」（members:\*+roles:\*+departments:\*，与角色名
  无关）补授，authenticated 按系统角色名补授，口径同 000014/000035）。
- 服务层复核：写路径（创建/改名/草稿/发布/删除）在 Service 内按
  `forms:create|patch|update|delete` 复核；bootstrap 不要求 forms 权限（普通成员经
  applications:get + 发布状态门控）；提交按 form-records:create 复核。
- 管理组（admin-groups）不间接放行 forms/form-records（如需委派另立数据范围设计，
  口径同 enterprise-logs）。
- 菜单按钮动作（ADR-011）：新增 `form-actions` 资源（不对应任何 URL 首段，
  中间件 URL 门永不命中），动作键 `switch-type/copy-in-app/copy-cross-app/hide`
  在本域 Service 内按权限集复核（切换类型/复制），菜单读取经
  `authorization.MenuActionsOf` 投影按钮能力；新租户 tenant-admin 基线补
  `{form-actions, *}`，存量租户经迁移 000047 按管理员规则签名补授。动作授权
  键独立于 forms 资源，自定义角色可单独授予/回收按钮能力。

## 5. 事务、审计与并发

- 事务边界：创建（配额 CheckAndReserve 内建应用行+初始草稿）、草稿保存、发布、提交
  均经 `TxManager.WithinTransaction`；仓储一律 `infrastructure.ResolveDB` 加入 ctx 事务。
- 审计：提交后 best-effort，`Module: "form"`，Action：`create` / `update-draft` /
  `publish` / `delete` / `submit`（ResourceType `form` / `form_record`）。
- 乐观锁：草稿保存按 `draft_revision` 条件更新（`revision+1` SQL 表达式，0 行即 409），
  口径同 tenantproduct；发布 additionally 校验草稿 revision，防止「发布他人并发保存的
  旧草稿」。
- 不可变性：form_versions 无更新路径；发布只追加快照 + 回写 forms.latest_version_id，
  不触碰历史快照，已提交记录关联的版本永不被覆盖（阶段交接纪律）。

## 6. 前端消费（apps/web）

- `src/api/form.ts`：createForm / listForms / getForm / updateFormName / saveFormDraft /
  publishForm / getFormRuntime / submitFormRecord，与上表一一对应。
- 设计器页（/app/:appCode/form/:formCode/design）：工作区外壳单次加载详情并通过上下文供子路由复用；保存走 PUT draft；
  发布走 publish；预览经 sessionStorage 传递草稿全文（发布通道落地前的预览机制）。
- 预览页（/form/:formCode/preview）：优先 GET bootstrap（已发布 → 真实提交闭环）；
  未发布回退 sessionStorage 草稿本地回放（提交本地通过，不落库）。
