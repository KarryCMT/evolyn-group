# 管理后台-产品中心开发文档

## 1. 文档目的与范围

本文定义租户管理后台“产品中心”的后端开发契约。该页面面向租户管理员，管理平台内置产品在当前租户的启停状态与可用成员范围。

一期以“灵衍云”一个内置产品为展示对象，但模型和接口必须支持后续增加多个内置产品。本文覆盖：

- 产品卡片列表及当前版本、可用成员数的读取；
- 租户维度的产品启用与停用；
- 全部成员、部分部门和部分成员的可用范围配置；
- 实际产品入口和产品内受保护接口的访问判定；
- 数据模型、Migration、RBAC、事务、审计与测试约束。

本文不管理租户自建低代码应用。`applications` 是租户内一级业务应用资源；产品中心管理的是平台内置产品的租户级配置，两者不能共用表、接口或权限资源。

## 2. 现状与设计结论

当前前端路由为 `/tenant/product-center`，页面卡片、版本、成员数、部门和成员选择数据都来自本地常量；启用开关和可用范围只修改内存状态；“查看”和“进入产品”均仅提示入口建设中。因此它不是可持久化的业务功能。

已有能力可复用，但不能替代产品中心配置：

| 已有能力 | 接口 | 产品中心中的用途 |
| --- | --- | --- |
| 当前租户版本信息 | `GET /api/v1/editions/current` | 读取当前套餐名称和状态，作为产品卡片的“当前版本”。 |
| 当前租户成员 | `GET /api/v1/members` | 供选择器加载成员；全部成员时可用于统计有效成员总数。 |
| 当前租户部门树 | `GET /api/v1/departments/tree` | 供选择器加载部门树。 |

本期结论：

1. 新建 `tenantproduct` 业务域，放在 `internal/platform/tenantproduct/`，遵循 controller → service → repository 分层。
2. 产品目录是平台级资源，租户配置是租户级资源；成员与部门范围采用关联表，而不是 JSONB ID 数组。
3. 当前版本是 edition 域的事实，不在产品配置中冗余存储。
4. 产品可用范围必须在服务端执行。前端隐藏入口只是体验优化，不能作为授权边界。
5. 产品配置更新必须走乐观锁和统一事务，审计仅在提交成功后 best-effort 记录。

## 3. 领域术语与边界

| 术语 | 含义 |
| --- | --- |
| 内置产品（Product Catalog） | 平台提供、可被多个租户启用的产品，例如灵衍云。不是租户自行创建的 `Application`。 |
| 租户产品配置（Tenant Product Config） | 某个产品在一个租户中的启用状态与分发范围。 |
| 全部成员范围（`all`） | 当前租户内所有有效成员均可使用产品。 |
| 部分成员范围（`partial`） | 仅直接选中的有效成员，或位于选中部门（含子部门）的有效成员可使用产品。 |
| 产品可用成员 | 同时满足“产品已启用”与“范围命中”的有效租户成员。 |
| 产品入口 | 由产品目录定义的站内路径或后续受控跳转地址；只有通过可用性判定后才可返回或访问。 |

产品配置不承载以下概念：套餐权益、资源配额、低代码应用菜单、应用管理员分组、成员角色或部门结构。这些分别属于 edition、application、iam 域。

## 4. 模块位置与依赖

```text
apps/evolyn-core/internal/platform/tenantproduct/
├── controller/
│   └── tenant_product.go
├── model/
│   ├── product.go
│   └── dto.go
├── repository/
│   ├── tenant_product.go
│   └── interface.go
├── service/
│   ├── tenant_product.go
│   ├── access.go
│   └── interface.go
└── errors.go
```

| 依赖域 | 依赖方向与责任 |
| --- | --- |
| `edition` | 只读查询当前 `CurrentEdition`，组装卡片版本信息；不修改订阅或配额。 |
| `iam` | 验证成员和部门属于当前租户、查询有效成员数，并由产品访问判定器消费成员身份。 |
| `tenant` | 租户开通事务中初始化默认产品配置。 |
| `audit` | 事务提交后记录启停和范围变更流水。 |
| `infrastructure` | 使用 `TxManager` 与 `ResolveDB`，不绕开上下文事务和租户 Callback。 |

Service 不得依赖 Gin 或 HTTP 细节；Repository 仅通过 GORM 持久化。Controller 只做请求解析、当前成员取得、统一响应与中文 Swagger 注释。

## 5. 数据模型

### 5.1 ER 关系

```text
product_catalogs 1 ──── * tenant_product_configs * ──── 1 tenants
                                      │
                   ┌──────────────────┴──────────────────┐
                   ▼                                     ▼
tenant_product_departments                       tenant_product_members
                   │                                     │
                   ▼                                     ▼
             departments                              users
```

### 5.2 `product_catalogs`：平台产品目录

该表是平台级资源，使用 `PlatformBaseModel`，不受租户 Callback 过滤。

| 列 | 类型/约束 | 说明 |
| --- | --- | --- |
| `id` | `BIGSERIAL PK` | 内部稳定主键。 |
| `code` | `VARCHAR(64) UNIQUE NOT NULL` | 稳定机器码，如 `lingyanyun`；创建后不可修改。 |
| `name` | `VARCHAR(64) NOT NULL` | 产品展示名称。 |
| `icon` | `VARCHAR(64) NOT NULL` | 稳定图标键，不存前端组件名。 |
| `entry_path` | `VARCHAR(255) NOT NULL` | 站内产品入口路径；外部地址能力后续单独设计。 |
| `status` | `VARCHAR(16) NOT NULL` | `active` / `inactive`；平台停用后租户不能访问。 |
| `sort_order` | `BIGINT NOT NULL DEFAULT 0` | 卡片展示排序。 |
| `created_at`、`updated_at`、`deleted_at` | 基础字段 | 继承 `PlatformBaseModel`。 |

一期可以由代码中的只读注册表提供唯一产品，再仅创建租户配置表；但一旦需要平台运营动态上架、下架或排序多个产品，必须迁移到本表，不能把目录配置散落在前端常量中。

### 5.3 `tenant_product_configs`：租户产品主配置

该表嵌入 `TenantBaseModel`，业务查询始终通过当前租户上下文过滤。

| 列 | 类型/约束 | 说明 |
| --- | --- | --- |
| `id` | `BIGSERIAL PK` | 内部稳定主键。 |
| `tenant_id` | `BIGINT NOT NULL` | 继承自 `TenantBaseModel`。 |
| `product_id` | `BIGINT NOT NULL` | 引用平台产品目录。 |
| `enabled` | `BOOLEAN NOT NULL DEFAULT TRUE` | 租户是否启用该产品。 |
| `scope_mode` | `VARCHAR(16) NOT NULL DEFAULT 'all'` | 仅允许 `all` / `partial`。 |
| `revision` | `BIGINT NOT NULL DEFAULT 1` | 配置乐观锁版本；每次成功写入递增。 |
| `created_at`、`updated_at`、`deleted_at` | 基础字段 | 继承 `TenantBaseModel`。 |

建议约束：

```sql
CREATE UNIQUE INDEX uk_tenant_product_configs_tenant_product_active
    ON tenant_product_configs (tenant_id, product_id)
    WHERE deleted_at IS NULL;

ALTER TABLE tenant_product_configs
    ADD CONSTRAINT ck_tenant_product_configs_scope_mode
    CHECK (scope_mode IN ('all', 'partial'));
```

### 5.4 部门与成员范围关联表

| 表 | 关键列 | 约束与说明 |
| --- | --- | --- |
| `tenant_product_departments` | `tenant_product_config_id`、`tenant_id`、`department_id` | `(tenant_product_config_id, department_id)` 唯一。`tenant_id` 用于租户归属校验与查询；写入前由 Service 校验部门属于当前租户且有效。 |
| `tenant_product_members` | `tenant_product_config_id`、`tenant_id`、`member_id` | `(tenant_product_config_id, member_id)` 唯一。写入前校验成员属于当前租户且状态为 `active`。 |

两张表只在 `scope_mode=partial` 时有记录。`all` 范围不物化全部成员，避免成员增减时配置漂移和无意义的大量写入。

### 5.5 数据完整性和生命周期

- `partial` 必须至少有一个部门或成员关联；空范围返回业务错误，不能退化为“无人可用”或“全部成员”。
- 已选部门的子部门与其成员通过读时递归查询或部门树展开命中；不得在配置表复制子部门 ID。
- 成员离职、禁用、跨租户不存在时，读取和访问判定均忽略该成员；历史关联可保留供审计，不授予访问。
- 部门删除、停用或跨租户不存在时，读取和访问判定均忽略该部门；不可因此把 `partial` 扩大为 `all`。
- `enabled=false` 时保留范围配置，以便重新启用后恢复原范围。

## 6. HTTP API 契约

所有接口挂在既有租户 API 组中，实际前缀为 `/api/v1`，并经过 Authentication → Tenant → TenantStatus → Authorization 中间件链。

### 6.1 读取产品中心

```text
GET /api/v1/tenant-products
```

需要 `tenant-products:get`。返回当前租户可管理的产品卡片；版本字段来自 edition 域，成员数量按真实有效成员计算。

```json
{
  "items": [
    {
      "code": "lingyanyun",
      "name": "灵衍云",
      "icon": "product",
      "enabled": true,
      "revision": 3,
      "edition": {
        "planCode": "trial",
        "planName": "试用版",
        "status": "active"
      },
      "accessScope": {
        "mode": "partial",
        "eligibleMemberCount": 18,
        "departmentIds": [12],
        "memberIds": [35],
        "selections": [
          { "type": "department", "id": 12, "label": "研发部" },
          { "type": "member", "id": 35, "label": "李同学" }
        ]
      },
      "entryPath": "/workspace"
    }
  ]
}
```

若产品数量或范围选项将来明显增大，可将 `accessScope` 的完整选择项拆为 `GET /tenant-products/:code/access-scope`；一期一个产品时无需增加一次前端请求。

### 6.2 启用或停用产品

```text
PUT /api/v1/tenant-products/:code/enabled
```

```json
{
  "enabled": false,
  "revision": 3
}
```

服务端锁定并检查当前配置的 `revision`，更新 `enabled` 后将版本号加一，返回最新产品卡片。版本不匹配返回 `TENANT_PRODUCT_REVISION_CONFLICT`（HTTP 409）。

### 6.3 全量替换可用范围

```text
PUT /api/v1/tenant-products/:code/access-scope
```

```json
{
  "mode": "partial",
  "departmentIds": [12, 19],
  "memberIds": [35, 42],
  "revision": 3
}
```

`mode=all` 时 `departmentIds` 与 `memberIds` 必须为空或省略；`mode=partial` 时两者合计至少一个。接口在同一事务内校验全部 ID 的当前租户归属、更新主配置和替换范围关联，提交后返回最新卡片。

### 6.4 产品访问判定

产品中心不提供“前端校验即放行”的接口。产品真实入口、工作台路由的后端数据接口，或后续跨服务网关，都必须调用以下域内接口：

```go
type TenantProductAccessEvaluator interface {
    CanAccess(ctx context.Context, productCode string, memberID uint) (bool, error)
}
```

判定顺序为：平台目录 `active` → 租户产品 `enabled` → 成员为当前租户有效成员 → `all` 或命中直接成员 / 选中部门（含子部门）。任何一步不满足均拒绝。

若产品入口需要由后端签发短期跳转信息，可后续增加 `POST /tenant-products/:code/launch`；在此之前，不应为了页面跳转伪造一个没有安全价值的 launch 接口。

### 6.5 错误码

| 错误码 | HTTP | 场景 |
| --- | --- | --- |
| `TENANT_PRODUCT_NOT_FOUND` | 404 | 产品不存在、未初始化或不属于当前租户。 |
| `TENANT_PRODUCT_SCOPE_INVALID` | 400 | 范围模式非法，或 `all` 携带 ID。 |
| `TENANT_PRODUCT_SCOPE_EMPTY` | 400 | `partial` 未选择任何部门和成员。 |
| `TENANT_PRODUCT_MEMBER_INVALID` | 400 | 成员不存在、不属于当前租户或不是有效成员。 |
| `TENANT_PRODUCT_DEPARTMENT_INVALID` | 400 | 部门不存在、不属于当前租户或不可用于范围。 |
| `TENANT_PRODUCT_REVISION_CONFLICT` | 409 | 乐观锁版本过期。 |
| `TENANT_PRODUCT_DISABLED` | 403 | 访问时产品被租户停用。 |
| `TENANT_PRODUCT_ACCESS_DENIED` | 403 | 当前成员不在产品可用范围内。 |

新增错误码必须同步维护 Web 端 `packages/utils/src/request/errorCodes.ts`，前端按错误码处理，不匹配 message 文本。

## 7. 权限与安全

新增租户 RBAC 资源 `tenant-products`，一期权限键为：

```text
tenant-products:get
tenant-products:update
```

建议仅向租户管理员授予这两项权限。现有“应用管理员”管理的是租户自建 `applications`，不能因此获得产品启停或全租户成员分发权限。

运行时产品访问不等同于管理权限：普通成员即使没有 `tenant-products:get`，只要命中产品范围，仍可使用被授权产品；反之，管理员通过产品中心看见产品也不能绕过产品自身业务权限。

所有范围写入均需在 Service 层验证部门、成员和产品配置属于同一租户。禁止以裸 ID 写关联表，也禁止只依赖 GORM 回调的“影响行数为 0”作为成功结果。

## 8. 事务、审计与初始化

### 8.1 写入事务

启停和范围更新均通过 `TxManager.WithinTransaction` 执行：

```text
请求
  → 读取并锁定租户产品配置
  → 校验 revision 与请求数据
  → 校验全部部门 / 成员同租户且有效
  → 更新 tenant_product_configs
  → 同步替换范围关联
  → 提交事务
  → best-effort 写入 audit_logs
```

Repository 必须经 `infrastructure.ResolveDB(ctx, db)` 取得连接，使全部读写加入上下文事务。审计不能置于事务内，避免主事务回滚后遗留错误的操作日志。

### 8.2 租户初始化

租户自助开通和后台创建租户的事务中，初始化全部当前 `active` 产品目录：

- 创建一条 `tenant_product_configs`；
- 默认 `enabled=true`、`scope_mode=all`；
- 不创建范围关联行；
- 与初始订阅、管理员成员建立保持同一事务边界。

新增产品目录时，需提供显式后台回填任务或 Migration 策略，为存量租户创建配置。默认启用与默认停用必须由产品需求明确；不得隐式改变存量租户可访问的产品集合。

## 9. Migration、模型与装配要求

建议新增版本化 Migration `000033_tenant_products.up.sql` 与对应 down 文件，包含：

- 产品目录、租户产品配置、范围关联表；
- 所有新增表和字段的中文 SQL 注释；
- 唯一索引、范围模式 CHECK 约束和必要的 `tenant_id` 查询索引；
- `lingyanyun` 产品目录 seed，以及存量租户配置回填策略；
- 租户管理员角色的 `tenant-products:get`、`tenant-products:update` 权限补授。

同步更新：

- `apps/evolyn-core/scripts/db.sql`；
- `internal/platform/tenantproduct/model` 的 GORM 映射与 DTO；
- repository、service、controller 的 interface；
- `internal/platform/server/server.go` 的依赖装配和 Controller 注册；
- Web 端 API 模块、类型、错误码，以及产品中心页面的数据源替换；
- Swagger 生成物仅通过 `make swagger` 本地生成，不手改也不提交。

## 10. 前端对接契约

前端应新增 `src/api/tenantProduct.ts`，由页面 `onMounted` 调用 `GET /tenant-products`，替换产品、成员数、范围、部门和成员的本地常量。

| 当前交互 | 对接后行为 |
| --- | --- |
| 启用开关 | 调用 `/enabled`；成功后使用响应替换卡片，409 时提示刷新后重试。 |
| 选择“全部成员” | 弹出确认或直接调用 `/access-scope` 提交 `mode=all`；不能只改本地 radio 状态。 |
| 选择“部分成员”并确认 | 先加载部门树和成员列表，确认后调用 `/access-scope` 全量提交。 |
| 成员数 | 只显示接口返回的 `eligibleMemberCount`；不可继续使用固定 `1`。 |
| 查看当前版本 | 跳转 `/tenant/edition`，而不是调用产品入口提示。 |
| 进入产品 | 仅在卡片 `enabled` 且当前成员可访问时展示或启用；产品后端仍需独立进行访问判定。 |

前端范围选择器的部门、成员 DTO 可从现有 `/departments/tree`、`/members` 映射而来；不要在前端提交展示名称，只提交稳定 ID。

## 11. 测试与验收

至少覆盖以下用例：

1. 新租户初始化后可读取默认产品，默认启用且范围为 `all`。
2. 租户 A 不能读取、修改或将租户 B 的成员、部门写入自己的产品范围。
3. `partial` 空范围、非法模式、无效成员、无效部门均返回稳定业务错误码。
4. 部门与成员重复提交时去重；范围更新后旧关联不再生效。
5. 两个管理员使用同一旧 `revision` 更新时，只有一个成功，另一个得到 409。
6. 产品停用后，原本命中范围的成员无法通过 `TenantProductAccessEvaluator`。
7. `all` 范围允许所有有效成员；`partial` 同时覆盖直接成员、选中部门成员和子部门成员。
8. 离职、禁用成员以及删除、停用部门不会继续获得产品访问权。
9. 当前版本名称来自 edition 域，而非产品配置表内的冗余字段。
10. 写入成功后有审计流水；事务失败时不产生成功审计。

提交前在 `apps/evolyn-core` 至少执行 `go test ./...`；涉及 Migration 和跨租户边界时补充 `make test-integration`。前端接线后执行 `pnpm -F @evolyn.do/web typecheck`、`pnpm -F @evolyn.do/web build` 与 `pnpm run lint:format`。

## 12. 实施顺序

1. 先确定产品目录是否一期落表；若暂不落表，固定代码注册表与目录接口契约仍需保持一致。
2. 完成 Migration、模型、Repository 与租户初始化，先以 Service 测试锁定范围语义。
3. 实现产品列表、启停、范围替换与错误码，接入 RBAC、乐观锁、审计。
4. 实现并在产品真实受保护路径接入 `TenantProductAccessEvaluator`。
5. 前端替换本地常量和提示交互，接入版本页跳转与范围选择器。
6. 完成跨租户、并发与真库集成测试后，再开放产品中心入口。
