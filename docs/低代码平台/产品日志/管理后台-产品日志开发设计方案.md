# 管理后台-产品日志开发设计方案

## 1. 目标与范围

产品日志是租户管理员查看**当前租户内各应用及其应用内资源操作**的管理后台模块，入口为 `/tenant/product-logs`。一期以只读列表与导出为目标，页面参考“日志范围、操作类型、操作人、操作时间、应用/对象”组合筛选与日志表格展示。

产品日志是追加写、只读的业务历史流水，不承载运行时技术日志、链路追踪日志、监控指标，也不用于记录成员登录行为。

### 1.1 与企业日志的边界

产品日志与企业日志共用业务审计事实表和写入链路，但查询范围互斥：

| 模块 | 包含范围 | 不包含范围 |
| --- | --- | --- |
| 企业日志 | 登录事件、成员管理、组织、角色权限、租户设置、套餐与产品中心配置等企业治理行为 | 应用内建模、应用数据和应用权限操作 |
| 产品日志 | 应用、菜单、表单、流程、应用数据、应用权限、应用发布等应用内操作 | 登录、企业成员、组织、租户与套餐治理操作 |

企业日志中既有的 `application` 操作分类仅保留“租户产品中心的应用启停、可用范围”等治理操作；应用内资源操作一律归入产品日志。该约定避免两个入口展示同一条流水。

## 2. 租户边界与权限

### 2.1 租户边界

所有接口均从 JWT 与请求上下文取得当前 `tenantId`，客户端不得传入、指定或切换租户。列表查询、筛选项、创建导出任务、读取任务状态和下载文件均须再次按任务所属 `tenant_id` 校验，确保任何跨租户数据不可见。

`application_id` 仅是当前租户内应用的进一步筛选维度，不可替代租户过滤。服务层必须先校验传入应用归属于当前租户；对于已删除应用，仍可按其历史快照展示日志，但不能借此读取其他租户的记录。

### 2.2 权限

新增资源权限：

- `product-logs:view`：查看产品日志与筛选项。
- `product-logs:export`：创建、读取并下载产品日志导出任务。

初始授予租户管理员角色。该资源不接受管理组的间接放行；后续如需委派，须另行设计应用范围或数据范围，不能默认放开所有应用日志。

## 3. 事件源与数据模型

### 3.1 唯一事实源

继续使用 `audit_logs` 作为所有业务操作的唯一事实源，禁止为产品日志页面复制写入一份流水。现有 `audit.Recorder` 仍在业务事务成功提交后 best-effort 写入；日志写入失败不得影响主业务操作。

产品日志读取的是 `audit_logs` 中受控投影后的数据，禁止将 `before_data`、`after_data`、请求编号、用户代理或内部资源 ID 原样出网。

### 3.2 审计字段扩展

企业日志方案定义的以下字段同样是产品日志的基础字段：

```text
event_code            varchar(100)  NOT NULL
category_code         varchar(64)   NOT NULL
actor_name_snapshot   varchar(128)  NOT NULL DEFAULT ''
target_name_snapshot  varchar(256)  NOT NULL DEFAULT ''
summary               varchar(1000) NOT NULL DEFAULT ''
```

为支持“所属应用”和应用删除后的历史展示，`audit_logs` 还须增加：

```text
application_id             bigint       NULL
application_code           varchar(128) NOT NULL DEFAULT ''
application_name_snapshot  varchar(256) NOT NULL DEFAULT ''
```

字段职责如下：

| 字段 | 用途 |
| --- | --- |
| `event_code` | 稳定机器语义，例如 `application.form.delete`，用于操作类型筛选与导出。 |
| `category_code` | 产品日志范围，例如 `application`、`form`、`workflow`、`data`、`app_permission`。 |
| `actor_name_snapshot` | 发生操作时的成员显示名，成员改名、离职或删除后仍保持历史一致。 |
| `target_name_snapshot` | 表单、流程、菜单、数据对象等被操作资源的历史名称。 |
| `summary` | 服务端生成且已脱敏的操作详情，可直接展示和导出。 |
| `application_id` | 查询与权限校验使用的应用标识；允许为空，以兼容应用创建前或历史数据。 |
| `application_code` / `application_name_snapshot` | 应用的稳定编码和历史名称快照，不依赖当前应用是否存在。 |

### 3.3 事件分类

一期产品日志的分类与事件码按下列规则登记，前端只能消费服务端下发的筛选项，不得硬编码：

| `category_code` | 典型 `event_code` | 说明 |
| --- | --- | --- |
| `application` | `application.create`、`application.update`、`application.publish` | 应用本体与发布操作。 |
| `application_menu` | `application.menu.create`、`application.menu.update`、`application.menu.delete` | 应用菜单配置。 |
| `form` | `application.form.create`、`application.form.update`、`application.form.delete` | 表单及表单设计变更。 |
| `workflow` | `application.workflow.enable`、`application.workflow.update` | 流程定义与启停。 |
| `data` | `application.data.create`、`application.data.update`、`application.data.delete` | 应用业务数据操作。 |
| `app_permission` | `application.permission.grant`、`application.permission.revoke` | 应用内角色、成员与权限范围变更。 |

事件码、分类、展示名称和摘要模板应由后端注册表统一维护。调用方传递语义参数与快照，审计服务按照模板生成摘要；禁止业务服务手工拼接不受控的展示文案。

示例：

```text
event_code: application.form.delete
category_code: form
application_name_snapshot: 测试应用
target_name_snapshot: 采购申请
summary: 删除了表单「采购申请」
```

### 3.4 脱敏与快照规则

禁止写入或出网密码、短信/邮箱验证码、访问令牌、私钥、完整手机号/邮箱、身份证明、连接串、原始敏感配置和大段业务数据。`before_data`、`after_data` 仅作受控内部审计快照，写入前执行字段白名单与脱敏处理。

`summary`、操作者、目标对象和应用名称均为写入时快照。查询时不可改为关联现有成员或应用名称，以免历史记录因改名、离职、删除而失真。

## 4. 后端模块设计

新增 `internal/platform/productlog/` 作为只读与导出编排域：

```text
productlog/
  controller/   HTTP 参数解析、身份与权限检查、统一响应
  service/      条件规范化、租户隔离、应用归属校验、导出任务编排
  repository/   audit_logs 的产品操作只读查询
  model/        查询条件、受控出参、筛选项和导出任务模型
```

该域不接管审计日志写入；业务审计仍在 `internal/platform/audit/`。这样产品日志页面不会反向耦合应用、表单、流程等所有写路径。

查询排序统一为 `(created_at DESC, id DESC)`。普通页面支持 `page/pageSize`，页大小最大 100；日志量增长后仓储内部优先采用“时间 + ID”的 keyset/cursor 查询，避免深分页扫描。

## 5. API 契约

### 5.1 查询与筛选项

```text
GET /api/v1/product-logs
GET /api/v1/product-logs/options
```

列表参数：

```text
categoryCode      可选，日志范围
eventCode         可选，操作类型
memberId          可选，当前租户成员 ID
applicationId     可选，当前租户应用 ID
keyword           可选，匹配应用、目标对象与摘要；不得查询原始快照
startAt           可选，东八区开始时间
endAt             可选，东八区结束时间
page/pageSize     页码与页大小
```

开始时间晚于结束时间、成员或应用不属于当前租户、未知事件码或未知分类，均返回稳定 `httpx.BizError`。时间筛选采用东八区闭区间语义，服务端转换为数据库半开区间。

列表出参仅包括：操作者（名称与头像可用时）、操作时间、日志范围、操作类型、所属应用、操作对象、脱敏后的操作详情和 IP。不得输出请求 ID、用户代理、原始快照、内部资源 ID。

`options` 返回当前租户内允许筛选的成员、有效应用、产品日志分类及事件码；历史已删除的应用只在列表结果中展示快照，不作为可选筛选项。

### 5.2 导出

```text
POST /api/v1/product-logs/exports
GET  /api/v1/product-logs/exports/:id
```

创建导出请求携带与列表完全一致的筛选条件。导出任务固化提交时的筛选条件、申请人、租户、数据量、状态、文件引用和过期时间；小数据量可同步生成，较大数据量采用异步任务。下载前重新校验 `product-logs:export` 与任务租户归属。

导出行为本身必须写入企业治理类操作审计，包含筛选时间范围和导出条数，不记录导出文件内容。

## 6. 前端交互对应

页面入口为 `/tenant/product-logs`，替换现有规划占位页。页面使用单页筛选与表格布局：

- 筛选区：日志范围、操作类型、操作人、操作时间、应用/对象；应用/对象支持搜索选择。
- 点击“查询”后从第一页重新拉取；修改筛选条件不自动请求。
- 表格列：操作人、操作时间、操作类型、所属应用、操作对象、操作详情、IP；默认按最新操作倒序。
- 表格内容区域独立使用 `el-scrollbar` 滚动，筛选区、工具栏和分页保持固定；数据表格采用 VTable。
- “导出”导出当前筛选条件下的全部已授权数据，而非当前页。
- 分类、操作类型、应用与成员均由 `options` 接口返回；空结果、加载失败和无导出权限应有明确状态反馈。

## 7. 数据库迁移与索引

与企业日志字段扩展合并为同一只增版本 SQL migration，避免对同一张 `audit_logs` 重复设计迁移；同步更新 `scripts/db.sql` 终态快照。新增或补齐索引：

```sql
CREATE INDEX idx_audit_logs_tenant_created
  ON audit_logs (tenant_id, created_at DESC, id DESC);

CREATE INDEX idx_audit_logs_tenant_category_created
  ON audit_logs (tenant_id, category_code, created_at DESC, id DESC);

CREATE INDEX idx_audit_logs_tenant_member_created
  ON audit_logs (tenant_id, member_id, created_at DESC, id DESC);

CREATE INDEX idx_audit_logs_tenant_application_created
  ON audit_logs (tenant_id, application_id, created_at DESC, id DESC);
```

应用维度查询仍必须以前置 `tenant_id` 为首列，禁止仅凭 `application_id` 查询审计日志。

## 8. 实施顺序

1. 与企业日志方案统一审计字段、分类边界和 SQL migration，补齐中文注释、索引与 `scripts/db.sql` 快照。
2. 扩展 `audit.Entry`、事件注册表和审计服务，支持产品分类、应用快照、目标快照及安全摘要。
3. 在应用、菜单、表单、流程、数据与应用权限写路径逐步接入结构化审计事件；未迁移历史记录以“历史操作记录”降级展示。
4. 实现 `productlog` 的 repository、service、controller、路由注册和权限种子；补充租户隔离、应用归属、日期筛选、脱敏与导出授权测试。
5. 新增前端 API 与产品日志页面，替换 `/tenant/product-logs` 规划占位页。
6. 最后接入异步导出、套餐留存策略、文件过期清理与容量监控。

## 9. 留存策略

日志保留期、最大可查询时间跨度、单次导出上限及导出文件有效期由平台或套餐策略决定，前端仅展示服务端返回的限制或错误。清理任务按租户策略执行，清理过程可审计；前端筛选、分页和导出不得改变原始日志留存。
