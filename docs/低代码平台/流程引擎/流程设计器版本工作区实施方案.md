# 流程设计器版本工作区实施方案

## 目标

流程设计器采用“一个启用版本 + 至多一个设计版本 + 多个历史快照”的版本模型。启用版本和历史版本不可直接修改；用户必须显式添加新版本后才能继续设计。该模型与运行实例固定绑定版本的既有语义一致，避免修改设计稿影响已经运行或即将发起的流程。

## 状态模型

| 工作区状态 | `has_draft` | `draft_version_no` | `published_version` | 允许操作 |
| --- | ---: | ---: | ---: | --- |
| 首次设计 | true | 1 | 0 | 编辑、保存、预览、测试、启用 |
| 已启用 | false | N | N | 只读查看、预览、测试、添加新版本 |
| 新版本设计中 | true | N+1 | N | 编辑、保存、预览、测试、启用、切换查看历史版本 |

同一流程定义同一时刻至多存在一个设计版本。发布快照仍由 `wf_definition_version` 追加写保存，任何接口不得覆盖历史快照。

## 接口约定

- `GET /workflows/:code`：返回 `hasDraft`、`draftVersionNo`、`publishedVersion` 与当前工作区文档。
- `POST /workflows/:code/draft-versions`：从当前启用版本或 `baseVersionNo` 指定的历史版本创建下一设计版本。
- `PUT /workflows/:code/draft`：仅允许保存设计版本；启用版本返回 `WORKFLOW_DRAFT_NOT_OPEN`。
- `POST /workflows/:code/publish`：把当前设计版本冻结为同版本号的不可变快照，并关闭设计工作区。
- `GET /workflows/:code/versions`：返回版本状态 `active` 或 `historical`。

## 并发与迁移

添加版本和启用版本都在事务内锁定 `wf_definition` 行，结合 `draft_revision` 乐观锁与 `(definition_id, version_no)` 唯一约束，防止双击或多窗口产生两个设计版本或重复版本号。

存量数据迁移时，若草稿与当前启用快照一致，则收口为只读启用版本；若不一致，则保留为下一设计版本，确保历史未发布编辑不会丢失。

## 前端交互

- 顶栏版本入口展示当前版本，并以“设计中 / 启用中”区分状态。
- 版本菜单提供切换、添加新版本和管理已有版本。
- 启用与历史版本只读；只有设计版本显示保存和启用流程按钮。
- 切换版本、离开路由或关闭页面前，如有未保存修改，提供“留在此页 / 不保存 / 保存并继续”三种选择。
- 管理已有版本弹窗展示启用状态、启用时间与查看/编辑入口。

## 分阶段实施状态

| 阶段 | 范围 | 状态 |
| --- | --- | --- |
| 0–1 | 协议基线、版本工作区、只读快照、未保存修改保护 | 已完成 |
| 2 | 截图同构的横向工具栏、节点素材、简略/详细视图、缩放与居中 | 已完成 |
| 3 | 拖拽创建、四向快捷添加、节点类型菜单、撤销重做、快捷键、对齐排列 | 已完成 |
| 4 | 草稿允许保存未连接节点、启用严格校验、连接完整性告警与帮助 | 已完成 |
| 5 | 节点属性页签、字段权限、节点操作、流转规则 | 已完成 |
| 6 | 逐级审批、子流程与插件节点的独立协议、配置和运行能力 | 进行中（设计协议与配置交互已完成） |
| 7 | 流程属性、提醒/撤回/自动提交等运行策略 | 待实施 |
| 8 | 运行预览、桌面/移动端切换、流程测试 | 待实施 |
| 9 | 截图级视觉回归、响应式校准与端到端验收 | 待实施 |

阶段 4 起明确区分两套校验口径：保存草稿只验证可重新加载的结构不变量，允许设计过程中的断开节点和未完成配置；启用流程执行引擎全量严格校验，任何不可达节点、无出口、环、非法表达式或缺失业务配置都不得进入不可变版本快照。

阶段 5 将审批节点属性拆分为三个独立配置面板：字段权限以“可见 / 可编辑 / 简报”矩阵编辑，节点操作控制提交、保存草稿、暂存、提交并打印和结束流程入口，流转规则配置节点提交条件。`summaryFields`、`operations`、`submitCondition` 均进入 DSL 与不可变版本快照，后端严格校验提交条件值域和简报字段命名/唯一性。

阶段 6 先完成设计协议与交互闭环：审批节点可在“常规审批 / 逐级审批”之间切换，逐级审批弹窗可配置发起人直接部门主管或通讯录最高级部门主管向下层级作为审批终点；横向工具栏与节点快捷菜单中的“子流程 / 插件节点”已从条件与 HTTP 服务节点中拆分，拥有独立 `subflow` / `plugin` 类型、配置块和属性面板。三类新能力均允许保存设计草稿；在顺序任务游标、子流程实例绑定和插件执行适配器落地前，严格发布校验会给出可定位的“仅可保存草稿”提示，不允许运行必失败的版本进入快照。
