# 管理后台-产品设置开发设计方案

## 1. 目的、范围与结论

本文定义租户管理后台“产品设置”（`/tenant/product-settings`）的后端设计。页面以租户为配置边界，供租户管理员配置产品协作、产品样式和产品集成能力。

一期页面包含以下交互：

- 应用分享：管理租户自建应用的对外安装链接；
- 应用管理组、待办委托、全局附件管控：租户级能力开关；
- 自定义工作台：选择应用导航样式；
- 产品风格：进入租户品牌/主题配置；
- 支付服务、知识库：租户级集成能力开关，支付服务另有深层配置入口。

设计结论：

1. 新建 `internal/platform/productsettings/` 领域，按 controller → service → repository 分层；它管理租户级产品能力策略，不和 `tenantproduct` 的产品启停、成员可用范围混用。
2. 可独立即时修改的能力采用“一能力一行”的配置表和独立 `revision`，避免管理员同时修改不同开关时整页覆盖。
3. 工作台导航样式采用独立的一对一偏好表；企业主题色和 Logo 归属品牌配置，不放入产品设置 JSON。
4. 应用分享必须绑定不可变的应用发布版本；没有应用发布/安装模型前，不得创建指向实时应用实体的公开链接。
5. 设置写入使用乐观锁、统一事务和提交后审计；支付密钥等敏感信息不写入普通 JSONB 配置。

本文不定义应用低代码运行时、支付渠道凭据、知识库正文、工作流委托规则的具体实现，只定义它们在产品设置页面上的开关与边界。

## 2. 与现有领域的边界

| 领域 | 事实与职责 | 产品设置的关系 |
| --- | --- | --- |
| `tenantproduct` | 平台内置产品是否启用、可用成员和部门范围 | 产品设置不能替代产品启停和成员分发。运行时先检查产品配置，再检查本领域能力开关。 |
| `application` | 租户自建应用及后续发布版本 | 应用分享只引用应用的不可变发布版本，不复制或改写应用定义。 |
| `edition` | 租户有效订阅、套餐权益和额度 | 能力是否“可配置”由权益投影决定；权益是事实源，产品设置只保存租户选择。 |
| `iam` | 成员、角色、管理组与授权 | 负责 `product-settings:*` 权限和应用管理组实际成员/范围；产品设置仅保存是否启用该能力。 |
| 租户品牌配置 | Logo、主题色、生效范围 | “产品风格”跳转或复用该领域，禁止形成第二套主题事实源。 |
| `audit` | 业务操作流水 | 每项配置成功提交后追加审计；不得记录密钥、外链原始令牌。 |

运行时统一遵循以下判定顺序：

```text
有效订阅权益
  → 平台产品已启用且当前成员在可用范围内
  → 租户产品能力开关已开启
  → 当前成员具备业务资源权限
```

前端隐藏入口只是体验优化，所有受保护接口必须在服务端重复执行相应判定。

## 3. 领域位置与依赖

```text
apps/evolyn-core/internal/platform/productsettings/
├── controller/
│   ├── product_settings.go
│   └── application_share.go
├── model/
│   ├── settings.go
│   └── dto.go
├── repository/
│   ├── interface.go
│   └── product_settings.go
├── service/
│   ├── interface.go
│   ├── product_settings.go
│   └── application_share.go
└── errors.go
```

- Service 依赖 `TxManager`，多表写入通过 `WithinTransaction` 完成；Repository 一律经 `infrastructure.ResolveDB` 取得连接。
- Controller 只解析请求、取得当前租户和成员、调用 Service，并写中文 Swagger 注释；不得把 Gin 类型传入 Service。
- 租户开通事务内调用 `InitializeInTx` 创建默认配置。权益种子由 edition 域读取，配置记录不是套餐权益快照。

## 4. 数据模型

### 4.1 `tenant_product_feature_settings`：租户产品能力设置

该表嵌入 `TenantBaseModel`；`tenant_id + feature_key` 是一个租户内一项能力的唯一事实源。

| 列 | 类型/约束 | 说明 |
| --- | --- | --- |
| `id` | `BIGSERIAL PK` | 内部稳定主键。 |
| `tenant_id` | `BIGINT NOT NULL` | 当前租户，受租户 Callback 过滤。 |
| `feature_key` | `VARCHAR(64) NOT NULL` | 稳定能力键。 |
| `enabled` | `BOOLEAN NOT NULL DEFAULT FALSE` | 管理员选择的启用状态。 |
| `config` | `JSONB NOT NULL DEFAULT '{}'` | 仅保存该能力非敏感的扩展配置。 |
| `revision` | `BIGINT NOT NULL DEFAULT 1` | 单项能力乐观锁版本。 |
| 基础时间/软删字段 | `TenantBaseModel` | 保持统一生命周期。 |

首批能力键采用代码注册表定义并做请求白名单校验：

```text
application_management_group
workflow_delegation
global_attachment_control
payment_service
knowledge_base
```

建议约束：

```sql
CREATE UNIQUE INDEX uk_tenant_product_feature_settings_tenant_feature_active
    ON tenant_product_feature_settings (tenant_id, feature_key)
    WHERE deleted_at IS NULL;
```

`config` 不是任意业务数据仓库。支付服务只可保存例如 `provider`、`credential_ref` 等非敏感引用；商户密钥、私钥、令牌必须存入后续加密凭据存储。

### 4.2 `tenant_workspace_preferences`：租户工作台偏好

| 列 | 类型/约束 | 说明 |
| --- | --- | --- |
| `tenant_id` | `BIGINT UNIQUE NOT NULL` | 一租户一份偏好。 |
| `navigation_style` | `VARCHAR(16) NOT NULL` | `side`、`top`、`hybrid`，对应三个样式卡片。 |
| `revision` | `BIGINT NOT NULL DEFAULT 1` | 乐观锁版本。 |
| 基础时间/软删字段 | `TenantBaseModel` | 保持统一生命周期。 |

数据库以 `CHECK` 约束限制 `navigation_style` 的枚举值。新增样式时先扩展服务端注册表、迁移约束与前端枚举，再开放选择，避免客户端提交未知布局。

### 4.3 `tenant_application_share_links`：应用分享链接

| 列 | 类型/约束 | 说明 |
| --- | --- | --- |
| `id` | `BIGSERIAL PK` | 内部主键。 |
| `tenant_id` | `BIGINT NOT NULL` | 分享来源租户。 |
| `application_id` | `BIGINT NOT NULL` | 来源租户内应用，仅作归属与展示关联。 |
| `application_release_id` | `BIGINT NOT NULL` | 不可变发布版本；安装内容以此为准。 |
| `token_hash` | `VARCHAR(128) UNIQUE NOT NULL` | 随机原始令牌的哈希，数据库不存原始令牌。 |
| `status` | `VARCHAR(16) NOT NULL` | `active`、`revoked`、`expired`。 |
| `expires_at` | `TIMESTAMPTZ NULL` | 空表示由租户策略决定的长期链接。 |
| `created_by_member_id` | `BIGINT NOT NULL` | 创建人，用于审计与归责。 |
| `last_opened_at`、`install_count` | 可空时间/计数 | 运营展示字段，不作为授权依据。 |
| 基础时间/软删字段 | `TenantBaseModel` | 保持统一生命周期。 |

链接令牌使用高熵随机值，创建成功时只向调用方返回一次完整 URL；公开解析端点只按哈希查找有效链接。被撤销、过期或关联发布版本不可用时，均不得泄露应用或租户信息。

若 `application_release_id`、跨租户安装及其权限校验尚未落地，本期仅保留前端入口或返回受控的“能力暂未开放”，不得降级为分享实时 `application_id`。

## 5. 接口契约

所有管理接口位于既有租户 API 组，经过 Authentication → Tenant → TenantStatus → Authorization 链；使用统一响应 `{ code, msg, data }`。

### 5.1 聚合读取

```text
GET /api/v1/tenant/product-settings
```

需要 `product-settings:view`。返回与页面一一对应的三区块，并给出权益裁剪后的 `available`、`reason` 和 `revision`，使前端不需要自行推断套餐限制。

```json
{
  "features": [
    {
      "key": "knowledge_base",
      "enabled": true,
      "available": true,
      "revision": 4,
      "config": {}
    }
  ],
  "workspace": {
    "navigationStyle": "hybrid",
    "revision": 2
  },
  "brandSettingsEntry": "/tenant/brand-settings"
}
```

### 5.2 单项能力即时更新

```text
PATCH /api/v1/tenant/product-settings/features/:featureKey
```

请求体：

```json
{ "enabled": true, "config": {}, "revision": 4 }
```

Service 必须先验证能力键存在、当前订阅允许配置、调用人拥有 `product-settings:update`，再以 `tenant_id + feature_key + revision` 条件更新。零行更新需重新区分“配置不存在”和“版本冲突”；冲突返回 `TENANT_PRODUCT_SETTINGS_REVISION_CONFLICT`（HTTP 409）。成功后返回该项最新配置。

### 5.3 工作台样式更新

```text
PATCH /api/v1/tenant/product-settings/workspace
```

请求体：

```json
{ "navigationStyle": "hybrid", "revision": 2 }
```

该接口对应前端样式浮层的“确定”。“取消”不产生请求；前端在保存成功前保留原样式，失败时不改变当前全局布局。

### 5.4 分享链接管理

```text
GET    /api/v1/applications/:applicationId/share-links
POST   /api/v1/applications/:applicationId/share-links
DELETE /api/v1/applications/:applicationId/share-links/:linkId
```

需要 `application-shares:manage`，并在 Service 内校验应用属于当前租户、调用方对该应用有管理权限、版本已发布且允许分享。创建时返回一次 `shareUrl`；列表仅返回脱敏 URL 或链接标识；删除执行可恢复的状态撤销并记录审计。

公开安装入口单独设计为不带租户会话的受控端点，例如：

```text
GET /api/v1/public/application-shares/:token
```

它只负责校验链接并引导登录/选择目标租户；真正安装操作必须在目标租户上下文中再次做套餐、配额、应用安装权限和幂等性校验。

## 6. 权限、事务与审计

| 资源 | 权限 | 说明 |
| --- | --- | --- |
| 产品设置读取 | `product-settings:view` | 管理后台页面初始化。 |
| 产品设置更新 | `product-settings:update` | 修改能力开关、工作台样式。 |
| 应用分享管理 | `application-shares:manage` | 创建、查看和撤销当前租户应用分享链接。 |

- 权限由 tenant 域授权链处理，Service 仍负责租户归属校验，禁止裸应用 ID 写入。
- 单表即时更新可在一个事务内完成；涉及发布版本、链接创建、配额或多张关联表的操作必须使用统一事务边界。
- 事务提交后 best-effort 记录审计：能力键、启停前后值、导航样式前后值、分享链接 ID 与关联发布版本。不得记录原始令牌和敏感配置。
- 租户注销、产品停用、权益到期不会删除配置；运行时会拒绝实际能力访问。重新恢复权益后可按保留配置恢复，是否允许由套餐策略决定。

## 7. Migration、初始化与测试

1. 新增版本化 SQL Migration（up/down），为三张表、唯一索引和枚举检查约束写中文 SQL 注释，并同步 `scripts/db.sql` 快照；不得依赖 AutoMigrate 建生产 Schema。
2. 增加 `TenantProductSettingsSeeder`，在租户自助开通和平台创建租户的同一外层事务中初始化能力行、工作台偏好。默认值来自能力注册表与当前订阅权益。
3. 单元测试覆盖：未知能力键、权益不允许、乐观锁冲突、默认初始化幂等、撤销/过期分享链接及原始令牌不落库。
4. 真库集成测试覆盖：跨租户修改和读取拒绝、事务回滚、并发更新、应用归属校验、公开链接过期与撤销。
5. 前端以聚合读模型渲染；每个开关提交时携带对应 revision，收到 409 后刷新该项或整页并提示管理员，不能仅在本地改状态。

## 8. 分期实施

### P1：租户设置基础闭环

落地能力注册表、`tenant_product_feature_settings`、`tenant_workspace_preferences`、聚合读取和两类 PATCH 接口，以及开关/工作台样式页面交互。支付和知识库只表达启停策略，不接入凭据和业务实现。

### P2：应用分享闭环

应用发布版本、应用安装、分享链接与公开受控入口同时落地；补足来源租户、目标租户、发布版本和配额的全链路审计。

### P3：深层能力配置

按能力分别引入支付渠道配置、委托规则、附件安全策略和知识库策略。每个能力仍以独立领域负责业务事实，产品设置只提供入口、权益裁剪和总开关。
