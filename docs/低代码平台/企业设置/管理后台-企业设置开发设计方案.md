# 管理后台-企业设置开发设计方案

## 1. 背景与目标

“企业设置”是管理后台的租户级配置中心，路由为 `/tenant/enterprise-settings`。页面按“企业安全、企业文化、企业协作”分区展示，采用行内开关、轻量设置浮层和配置弹窗的交互方式。

本方案只定义租户管理员可管理的配置，不承载平台运营配置。所有配置以当前 JWT 中的 `tenantId` 为归属和数据隔离边界，不能由客户端传入或切换目标租户 ID。

目标：

- 对已具备业务基础的水印、主题、语言、时区提供可持久化、可并发控制的设置能力。
- 为 MCP、AI 能力、登录页品牌化、提醒屏蔽、单点登录、企业微信服务号提供可扩展的数据与接口边界。
- 敏感认证凭证与普通展示配置隔离；配置修改具备审计能力。
- 保持账号×成员拆分：认证身份始终归 `accounts`，租户内展示和授权始终归 `users`。

## 2. 页面与领域边界

| 页面分区 | 设置项 | 数据归属 | 生效方式 |
| --- | --- | --- | --- |
| 企业安全 | 全局水印 | 租户基础设置 | 租户内应用与知识库读取水印配置 |
| 企业安全 | 单点登录 | SSO 专属配置 | 登录入口按协议、配置状态和租户成员映射执行 |
| 企业安全 | MCP 服务 | 功能开关 | MCP 网关在处理请求时校验启用状态与成员权限 |
| 企业文化 | 自定义登录页 | 登录品牌配置 | 租户登录入口读取已发布版本 |
| 企业文化 | 企业风格 | 租户基础设置 | 桌面端与移动端读取受控主题标识 |
| 企业协作 | 提醒屏蔽 | 屏蔽规则 | 通知分发前按成员和产品规则过滤 |
| 企业协作 | 系统语言、系统时区 | 租户基础设置 | 新会话默认展示与时间格式；不改写已存储 UTC 时间 |
| 企业协作 | AI 能力、企业微信服务号 | 功能开关 | 业务入口同时校验开关和外部依赖就绪状态 |

企业设置不负责产品可用范围。产品是否启用、成员或部门是否可访问，仍由 `tenantproduct` 域和 `TenantProductAccessEvaluator` 判断。

## 3. 后端模块与依赖

新增领域模块：

```text
apps/evolyn-core/internal/platform/tenantsettings/
  controller/     HTTP 入参校验与响应组装
  service/        配置更新、跨域校验、事务与提交后审计
  repository/     租户设置相关持久化
  model/          领域模型、枚举与出网视图
  interface.go    面向 tenant、iam、tenantproduct、file、audit 的窄接口
```

模块遵循 controller → service → repository 结构。多表变更由 Service 通过 `TxManager.WithinTransaction` 统一提交；Repository 使用 `infrastructure.ResolveDB(ctx, db)` 加入上下文事务。审计只在事务提交后以 best-effort 方式写入 `audit` 域。

依赖边界：

- `tenant`：只读取当前租户及其状态，不在本模块修改套餐、配额、注销状态。
- `iam`：校验成员是否属于当前租户；SSO 成功后仍以账号和成员双层模型完成身份解析。
- `tenantproduct`：校验提醒规则中的产品已被当前租户启用，且不绕过产品访问范围。
- `file`：登录页 Logo 与背景图只保存文件 ID，由文件域负责上传、访问和清理。
- `audit`：记录设置创建、修改、启停与发布，不记录密钥、证书或明文凭证。

## 4. 数据模型

### 4.1 租户基础设置 `tenant_settings`

为 `tenants` 建立一对一扩展表，保存稳定、低敏且高频读取的设置。现有 `tenants.config` 保留注册向导 `onboarding` 等企业画像；其中已有的水印、主题、语言、时区在本模块上线后以 `tenant_settings` 为唯一事实来源，迁移期间采用一次性回填兼容旧值。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `tenant_id` | BIGINT PK | 租户 ID，一租户一条记录 |
| `watermark_enabled` | BOOLEAN | 是否展示全局水印 |
| `watermark_color` | VARCHAR(16) | `light` / `dark` |
| `watermark_density` | VARCHAR(16) | `normal` / `compact` |
| `theme_color` | VARCHAR(32) | 受控主题标识，不保存任意 CSS 值 |
| `locale` | VARCHAR(32) | 例如 `zh-CN`、`en-US` |
| `timezone` | VARCHAR(64) | IANA 时区，例如 `Asia/Shanghai` |
| `revision` | BIGINT | 乐观锁版本号 |
| `created_at`、`updated_at` | TIMESTAMP | 创建和更新时间 |

主题色只允许服务端白名单中的值，前端将标识映射为 Element Plus 当前主题色及色阶，禁止存储或下发任意样式文本。

### 4.2 功能开关 `tenant_feature_switches`

将 MCP、AI、企业微信服务号等变化较快但结构相近的能力抽象为每租户、每功能一条记录。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `tenant_id` | BIGINT | 所属租户 |
| `feature_key` | VARCHAR(64) | `mcp`、`ai_capability`、`wechat_service` 等受控键 |
| `enabled` | BOOLEAN | 管理员期望启用状态 |
| `config` | JSONB | 功能特有且非敏感的扩展配置 |
| `revision` | BIGINT | 乐观锁版本号 |

对外读取时返回 `enabled`、`available` 和 `unavailableReason`。例如微信服务号已启用但凭证未完成时，应显示已开启但不可用的原因，不能向成员端假称服务已经可用。

### 4.3 单点登录 `tenant_sso_configs`

单点登录独立建表，支持一期 SAML 2.0，并预留 OIDC、CAS 协议。客户端密钥、私钥等敏感值必须经应用层加密后保存，任何读取接口都不得返回其明文。

| 字段 | 说明 |
| --- | --- |
| `tenant_id`（唯一） | 一个租户当前至多一套生效 SSO 配置 |
| `protocol` | `saml2` / `oidc` / `cas` |
| `enabled` | 是否参与该租户的登录认证链路 |
| `endpoint`、`issuer`、`slo_endpoint` | 服务端地址与签发方标识 |
| `idp_certificate` | 身份提供方公开证书 |
| `client_id`、`client_secret_ciphertext` | OIDC 等协议所需客户端信息；密钥仅存密文 |
| `attribute_mapping` | IdP 属性到账号唯一标识、姓名、邮箱等的受控映射 |
| `revision` | 乐观锁版本号 |

启用前服务端必须做协议、URL、证书格式、必填字段与属性映射校验。SSO 认证完成后按账号唯一标识查找或按受控规则创建 `accounts`，再在当前租户解析 `users` 成员；不得用 IdP 返回的租户字段绕过当前登录入口的租户边界。

### 4.4 登录页品牌 `tenant_login_brandings`

登录页采用草稿和已发布配置分离：编辑器右侧参数实时驱动预览，但只有发布后才影响租户登录入口。

| 字段 | 说明 |
| --- | --- |
| `tenant_id`（唯一） | 所属租户 |
| `enabled` | 是否启用自定义登录页 |
| `logo_file_id`、`background_file_id` | 文件域资产引用 |
| `login_methods` | 账号、验证码、SSO 等允许方式 |
| `auto_login_mode` | 自动登录展示策略 |
| `registration_visible`、`locale_visible` | 注册与语言入口可见性 |
| `draft_config`、`published_config` | JSONB 草稿和已发布快照 |
| `revision` | 乐观锁版本号 |

上传文件的大小、MIME 类型、访问鉴权和清理策略由文件域统一处理；品牌表只存文件 ID，不保存外部 URL 或二进制。

### 4.5 提醒屏蔽规则

提醒屏蔽不是单一开关，应建规则主表和成员、产品关联表：

```text
tenant_reminder_blocks
  ├─ tenant_reminder_block_members
  └─ tenant_reminder_block_products
```

一条规则表达“选定成员不接收选定产品的可屏蔽提醒”。安全通知、账号通知、法律或合规要求的强制通知不受该规则影响。写入时必须校验成员、产品均属于当前租户；产品须为租户已启用产品。

## 5. API 与并发规则

接口统一位于 `/api/v1/tenant-settings`，走 Authentication → Tenant → TenantStatus → Authorization 链路。所有更新请求携带读取时的 `revision`，更新 SQL 以 `tenant_id + revision` 为条件；影响行数为零时返回稳定错误码 `TENANT_SETTINGS_REVISION_CONFLICT`，前端提示刷新后重试。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/tenant-settings` | 聚合读取企业设置首页所需的脱敏视图 |
| PATCH | `/tenant-settings/basic` | 更新水印、主题、语言、时区 |
| PUT | `/tenant-settings/features/:featureKey` | 启停或更新单项功能开关 |
| GET / PUT | `/tenant-settings/sso` | 获取脱敏 SSO 配置、保存配置 |
| PUT | `/tenant-settings/login-branding/draft` | 保存登录页草稿 |
| POST | `/tenant-settings/login-branding/publish` | 发布已验证草稿 |
| GET / POST | `/tenant-settings/reminder-blocks` | 查询、新建提醒屏蔽规则 |
| PUT / DELETE | `/tenant-settings/reminder-blocks/:id` | 修改、删除提醒屏蔽规则 |

所有错误使用 `httpx.BizError`，接口 Swagger 注释使用中文，并明确标注可能的 `errCode`。写入日志中的变更快照仅保留安全的差异摘要，例如“已更新 SSO 配置”“已重新设置客户端密钥”，不得记录密钥、证书全文或登录页私有文件地址。

## 6. 权限设计

建议新增以下租户权限，由管理员角色按需授予：

- `tenant-settings:view`
- `tenant-settings:update`
- `tenant-settings:sso:update`
- `tenant-settings:branding:update`
- `tenant-settings:reminder-blocks:update`

普通成员没有企业设置读取或修改权限。SSO 与登录页发布属于高风险操作，建议与基础设置更新权限拆分；后续若引入更严格的双人复核，可以在 Service 层扩展审批状态，不改变数据归属。

## 7. 迁移与实施分期

### 第一期：可落地基础设置

1. 新增 `tenant_settings` 和 `tenant_feature_switches` 迁移及中文字段注释。
2. 从 `tenants.config` 一次性回填水印、主题、语言、时区；回填完成后只读兼容旧字段，新的读写均以 `tenant_settings` 为准。
3. 实现聚合读取与基础设置更新接口、乐观锁、权限、审计。
4. 前端将占位页替换为企业安全、企业文化、企业协作三分区页面；水印、主题、语言、时区接真实接口。

### 第二期：规则与品牌化

1. 新增提醒屏蔽规则三张表与 CRUD 接口。
2. 新增登录页草稿、预览、发布流程，并接入文件域。
3. 接入 MCP、AI、企业微信服务号的实际就绪状态检查。

### 第三期：单点登录

1. 新增 `tenant_sso_configs`、敏感字段加密与密钥轮换机制。
2. 先完成 SAML 2.0 配置校验、登录回调、成员映射与审计，再扩展 OIDC、CAS。
3. 为 SSO 失败、禁用、配置回滚与管理员应急登录建立明确流程。

## 8. 非目标与约束

- 不通过企业设置修改租户套餐、配额、生命周期或产品可用范围。
- 不允许前端直接写入 `tenants.config` 或传入 `tenantId`。
- 不以纯前端开关伪造已经生效的 MCP、AI、SSO 或企业微信能力；后端必须给出依赖就绪状态。
- 不在数据库、日志、审计记录、Swagger 示例或前端响应中泄露密钥、令牌、私钥和生产连接信息。
