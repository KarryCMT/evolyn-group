# 登录页公共配置：需求整理（对标简道云 get_public_configuration）

> 对标简道云登录页初始化接口 `portal/corp/common/get_public_configuration`
> 响应的分析结论整理（2026-08-18 定）。本文件只做需求归集与响应字段模型
> 定版意向，**不含前后端实现任务**；实现排期待后续批任务清单另行落盘
> （沿用 M1 任务清单模式）。

## 1. 接口定位

- **调用时机**：登录页渲染前、任何用户交互前，页面初始化阶段。
- **认证要求**：无（公共接口，不加认证中间件）。
- **职责**：单接口聚合登录页所需的全部公共配置——平台版本、国际区号表、
  验证码策略、密码加密公钥、功能开关、运营链接，一次请求登录页全部就绪。
- **配置层级**：**部署实例级**（SaaS 站点 / 私有化实例一套值），登录前无租户
  上下文。与租户级配置（架构文档 26.5 `Tenant.Config`：水印/主题/时区/语言，
  登录后生效）是两个层次，字段不混用、存储不共表。

## 2. 简道云响应字段解析

### 2.1 平台元信息

| 字段 | 类型 | 示例 | 语义 |
| --- | --- | --- | --- |
| `version` | string | `"11.7.2"` | 前端资源版本（灰度发布 / 缓存刷新标识），**不是 API 版本** |

### 2.2 国际区号 `calling_code_list`

级联（Cascader）数据源形态：

- 外层分组 `[{label, children}]`，`label` 空串表示当前不分组，结构为将来
  按洲/常用分组预留；
- 叶子节点为 `text`（zh_cn / en_us / zh_tw 三语内嵌）+ `value`（如 `"+86"`）；
- 多语言由后端下发而非前端 i18n 资源管理，简道云将区号表当运营数据维护；
- 用途：手机号登录 / 注册时选择国际区号。

### 2.3 安全能力（能力协商结构，最值得借鉴）

| 字段 | 结构 | 设计意图 |
| --- | --- | --- |
| `captcha` | `{type, params}` | 服务端声明启用哪种验证码（svg / 极验…），前端按 `type` 渲染对应组件，`params` 携带组件参数（如极验 captcha_id）。开关 + 策略合一，可热切换、新增类型不改接口形状 |
| `pki` | `{algorithm, keys.public_key}` | 下发 RSA 公钥（示例为 512-bit），前端加密密码后提交，TLS 之外对明文密码再加一层防护；`algorithm` 预留国密 sm2 等算法升级 |

### 2.4 功能开关（11 个平铺布尔）

| 字段 | 归类 | 语义 |
| --- | --- | --- |
| `tenant_register` | 注册流程 | 允许自助注册新企业（租户） |
| `register_persona` | 注册流程 | 注册时选择个人画像/角色（引导流程） |
| `qixin_search_service` | 注册流程 | 企查查（第三方）查企业工商信息自动填充 |
| `order_info` | 商业化入口 | 订单信息入口 |
| `product_center` | 商业化入口 | 产品中心入口 |
| `coin` | 商业化入口 | 金币/积分体系 |
| `platform_sms` | 通讯与集成 | 平台短信通道开关（相对第三方通道） |
| `member_auto_sync` | 通讯与集成 | 成员自动同步（企微/飞书通讯录集成方向） |
| `contact_phone` | 运营支撑 | 联系电话展示 |
| `support` | 运营支撑 | 在线支持/客服入口 |
| `corp_coop` | 协作 | 企业间协作 |

### 2.5 运营链接

| 字段 | 语义 |
| --- | --- |
| `customize_better_version` | "反馈更好版本"表单链接 |
| `howxm_project_id` | HowXM（第三方 NPS/CX 调研平台）项目 ID |
| `help_docs` | 帮助文档链接映射（`{coin: url}`） |
| `links` | 通用链接注册表（`{purchase_coin: ""}`） |

`help_docs` 与 `links` 是同一模式（键 → URL 映射）的两个实例，简道云未统一
属历史包袱，evolyn 侧合并为单一 `links`。

## 3. 设计模式提炼

1. **单接口聚合**：登录页一次请求全部就绪，避免多个小接口瀑布；代价是
   响应体耦合所有消费方字段，字段只增不减。
2. **能力协商**：`captcha` / `pki` 均为"枚举类型 + 扩展参数"结构，服务端
   控制策略、前端做适配器。
3. **开关平铺**：前端 `if (config.xxx)` 控制显隐，简单直接；但无分组、
   无默认值约定、无版本化。evolyn 收敛为 `features` 对象规避顶层形状膨胀。
4. **平台级 ≠ 租户级**：本配置登录前无租户上下文，只能是部署实例级；
   租户差异化配置（水印/主题等）登录后由租户接口下发。

## 4. evolyn 需求条目

| 编号 | 需求 | 结论 | 建议批次 |
| --- | --- | --- | --- |
| R1 | 公共配置聚合接口 `GET /api/v1/public/configuration`（未认证） | 采纳，接口骨架先行 | 认证补齐批 |
| R2 | `version` 字段 | 采纳，复用 `pkg/version`（Makefile ldflags 注入） | 随 R1 |
| R3 | 验证码策略 `captcha {type, params}` | 采纳结构，默认 `{type: "none"}` 占位；验证码本体暂缓 | 结构随 R1，本体另批 |
| R4 | 密码加密公钥 `pki {algorithm, keys}` | 采纳意向，**独立 ADR 定夺**（涉及前端登录/注册/改密三处加密、后端解密与明文兼容过渡） | 安全增强批，不绑 M1 |
| R5 | 功能开关收敛为 `features` | 采纳重构；首批仅 `tenant_register`（M1 P2-2 注册链路的显式开关） | 随 R1 |
| R6 | 运营链接统一 `links` 映射 | 采纳重构（合并简道云 `help_docs`/`links`） | 随 R1 |
| R7 | 国际区号 `calling_codes` | 暂缓，随手机号/短信验证码登录批；落地时用扁平结构 + 多语言走前端 i18n 资源，不学后端内嵌三语 | 短信登录批 |
| R8 | 平台配置运营化（`platform_configs` 表 + Redis 缓存 + 后台改配失效） | 暂缓，SaaS 化批；私有化默认走 `config/app.yaml` | SaaS 化批 |

### 裁剪（当前产品形态无此概念，不引入）

`coin`、`order_info`、`product_center`、`customize_better_version`、
`howxm_project_id`、`register_persona`、`corp_coop`、`qixin_search_service`
——均为简道云 SaaS 商业化运营配置。

### 暂缓再议（有规划但非近期）

- `platform_sms`：随短信验证码登录；
- `member_auto_sync`：随企微/飞书通讯录集成里程碑；
- `contact_phone` / `support`：运营支撑类，SaaS 化或私有化交付需要时再议。

## 5. 响应字段模型（定版意向）

> 实现时按 controller → service 分层落到 `internal/model`（响应模型），
> 此处为需求定版意向，非实现承诺。

```go
// I18nText 多语言文本（仅区号等动态数据用；静态文案走前端 i18n）
type I18nText struct {
	ZhCN string `json:"zh_cn"`
	EnUS string `json:"en_us"`
	ZhTW string `json:"zh_tw"`
}

// CallingCode 国际区号选项（扁平结构，简化简道云的级联分组）
type CallingCode struct {
	Value string   `json:"value"` // "+86"
	Text  I18nText `json:"text"`
}

// CaptchaConfig 验证码策略：type 决定前端组件，params 携带组件参数
type CaptchaConfig struct {
	Type   string         `json:"type"`   // none | svg | geetest ...
	Params map[string]any `json:"params"`
}

// PKIConfig 登录密码加密公钥下发：algorithm 预留 rsa/sm2 升级
type PKIConfig struct {
	Algorithm string            `json:"algorithm"` // rsa
	Keys      map[string]string `json:"keys"`      // {"public_key": "..."}
}

// PublicConfiguration 登录页初始化公共配置（未认证接口）
// GET /api/v1/public/configuration
type PublicConfiguration struct {
	Version      string            `json:"version"`            // 对齐 pkg/version
	CallingCodes []CallingCode     `json:"calling_codes"`      // R7 暂缓，字段先占位
	Captcha      CaptchaConfig     `json:"captcha"`            // 默认 {type: "none"}
	PKI          PKIConfig         `json:"pki"`                // R4 落 ADR 前可空
	Features     map[string]bool   `json:"features,omitempty"` // R5 开关收敛
	Links        map[string]string `json:"links,omitempty"`    // R6 运营链接
}
```

## 6. 存储与配置来源

- **私有化默认值**：`config/app.yaml` 新增 `public` 段（随镜像交付默认值），
  `app.example.yaml` 同步示例。
- **SaaS 运营可配（R8，远期）**：`platform_configs` 表（key 唯一 + value
  JSONB + 描述 + 时间戳），Redis 缓存 + 后台改配失效；与 M1"租户配置
  Redis 缓存本批不做"同口径延后。
- **边界**：不进 `tenants.Config`（那是租户级，登录后生效）。

```yaml
# app.yaml 追加段示意
public:
  captcha:
    type: none
  features:
    tenant_register: true
```

## 7. 边界与依赖

- **与 M1**：`tenant_register` 开关的消费者即 M1 P2-2 注册链路（创建账号 +
  默认租户成员）；M1"本批明确不做"清单（短信验证码登录、租户配置缓存）
  与本需求 R7/R8 的暂缓口径一致，无冲突。
- **R4（pki）**：独立安全增强，需先立 ADR 再动代码；工作量含前端三处
  加密点与后端明文兼容过渡，不与 M1 绑定。
- **R7（区号）**：依赖手机号登录落地（Account.Phone 字段 M1 P1-1 已备）。
- **前端消费**：登录/注册页；按 M1 决策 2，前端页面待 TS 脚手架稳定后
  另批落地，本需求不产生前端任务。

## 8. 本需求明确不做

- 不含任何前后端实现任务（实现批另行起任务清单）；
- 不引入简道云商业化运营字段（见第 4 节裁剪清单）；
- 不做验证码本体、短信通道、通讯录同步（仅保留接口形状与开关语义）。
