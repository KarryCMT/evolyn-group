> 状态：设计 v2.3（评审修订版），实施基线。v1 重构组绑定判定、JSONB 事实源、写入范围、

>

## 1. 背景与目标

应用后台权限设置允许管理员为表单资产创建「权限组」，声明**哪些成员（主体）可以对该表单的
数据做哪些操作（操作权限）、看到和编辑哪些字段（字段权限）、管理哪些范围的数据（数据权限）**。

现状差距：

- 后端不存在任何资产级权限组模型（租户级自定义 RBAC 管的是后台功能权限，与本设计正交）；
- 菜单读取、表单运行时、记录提交均无资产数据权限判定；
- 前端权限组面板为本地预览数据（`AssetPermissionGroup` 仅 `id/name/description/enabled/subjects`）。

本设计补齐表单维度的权限组全链路，并预留仪表盘资产类型扩展位。

## 2. 语义基线（v2 定版）

| # | 语义 | 结论 |
| --- | --- | --- |
| S1 | 权限组构成 | 权限组 = 主体范围（成员/部门/角色）× 操作集 × 字段矩阵 × 数据范围，四要素整体提交、整体生效 |
| S2 | **组绑定判定**（⚠ v1 修订） | **操作、字段、数据范围不得跨组扁平化并集**。每次具体判定按「命中组含此操作 ∧ 该组数据范围命中目标记录 ∧ 该组字段矩阵放行」的组内合取执行；并集仅允许出现在同一维度内的多组合成（如多个组的查询范围 OR）。杜绝「A 组可编辑 X 范围 + B 组可查看 Y 范围 → 可编辑 Y」的串联越权 |
| S3 | 管理员旁路（⚠ v1 修订） | 数据面旁路仅认**显式动作键 `form-data:admin`**（服务层判定专用，不挂 URL 门，先例同 `form-actions:switch-type` 非动词键）。配置面资源 `form-permissions`（CRUD 动词）**不**触发数据旁路——能配置权限组 ≠ 拥有全部数据权限 |
| S4 | 无权限组默认 | 表单**不存在任何权限组行**（含禁用组）时维持既有基线不变（表单按菜单可见、全体成员可提交 `form-records:create`），存量行为零变更 |
| S5 | 收口与禁用（⚠ 定版） | 表单存在 ≥1 个权限组行（**禁用组同样维持收口**）即进入授权模型：非管理员成员权限 = 其命中的**启用**组判定结果；未命中任何启用组 = 无权限（含查看），菜单同步隐藏。「停用组」语义 = 暂停该组授权而非回落基线（与前端「停用全部权限组」确认文案「停用后权限暂时失效」一致） |
| S6 | 数据范围空条件 | 权限组数据范围为空条件（未配置）= 全部数据 |
| S7 | 字段默认（⚠ v1 修订） | **deny-by-default**：字段矩阵中缺失的字段（表单重新发布后新增）默认**不可见且不可编辑**，由管理员在权限组中显式放行；配置弹窗对新字段默认勾选可见，但保存前未覆盖即按拒绝态生效。杜绝「发布新增敏感字段自动对受限组可见」的泄露路径。S4 基线场景无矩阵，不受影响 |
| S8 | 写入路径范围语义（⚠ v1 新增，v2.2 补入口规则） | `add` 不受数据范围约束（数据范围是**已有数据**的管理边界，「仅录入」场景合法：可添加但不可见）；`edit`/`delete`/`copy` 模板记录按**旧记录**做「操作 ∧ 数据范围」组级判定；编辑后记录允许落入范围外（下次不可见，自然语义），不做「编辑后必须仍命中」反锁。**入口判定 = `view ∨ add`**：菜单裁剪与运行时入口按「可查看或可填写」放行——仅 `add` 成员进入填写模式（无数据列表入口），保留「仅录入」产品场景；强制 `add ⇒ view` 会让纯收集表单被迫泄露数据列表，不采纳 |
| S9 | 编辑合并语义（⚠ v2.1 定版） | `edit` 提交采用**权限感知提交管线**（新函数，不复用 `ValidateSubmittedRecordValues`）：信封解包（visible 状态规则不变）→ 权限合并（不可编辑字段拒绝携带数据、以旧值回填）→ 既有终审复用。详见 §4「提交管线」；提交信封 wire 协议不变，`visible` 语义保持「发布快照可见性」，与资产权限隐藏解耦 |

## 3. 操作权限字典

操作键为稳定枚举（出网/存储均用键，中文文案由前端字典渲染）。按表单类型分两个合法集：

### 3.1 普通表单（form_type=standard）

| 键 | 中文 | 说明 |
| --- | --- | --- |
| `view` | 查看 | 打开表单查看数据（记录列表/详情入口） |
| `add` | 添加 | 提交新记录（对应 `POST /form-records`，不受数据范围约束，S8） |
| `copy` | 复制 | 以既有记录为模板新建（模板记录须命中范围，新记录同 `add`） |
| `edit` | 编辑 | 修改既有记录（旧记录范围判定 + S9 合并提交） |
| `delete` | 删除 | 删除记录（旧记录范围判定） |
| `batch_print` | 批量打印 | 批量打印记录（逐记录范围判定） |
| `batch_modify` | 批量修改 | 按选中记录批量改字段值（逐记录范围判定 + 字段可编辑矩阵） |
| `import` | 导入 | 批量导入记录（同 `add` 语义，矩阵外字段忽略） |
| `export` | 导出 | 批量导出记录（导出行集 = 查询范围结果，列集 = 字段矩阵） |

### 3.2 流程表单（form_type=workflow）

在普通表单 9 项基础上追加 3 项：

| 键 | 中文 | 说明 | 执行点现状 |
| --- | --- | --- | --- |
| `workflow_owner_transfer` | 调整流程负责人 | 调整流程实例当前负责人 | 流程引擎现有 Transfer 为**节点任务转办**，实例级负责人调整为预留能力（§8.4） |
| `workflow_terminate` | 结束流程 | 终止进行中的流程实例 | 已有 Terminate 动作（Phase 4），动作校验处叠加组级判定 |
| `workflow_activate` | 激活流程 | 将已结束/终止的实例重新激活 | 状态机无此迁移，纯预留键位 |

校验规则：创建/更新时按 `forms.form_type` 分派合法键集，`standard` 表单出现 `workflow_*` 键
整体拒绝（`FORM_PERMISSION_OPERATION_INVALID`）；未知键一律拒绝。

### 3.3 类型切换阻塞（⚠ v1 新增）

`POST /forms/:code/switch-type`（ADR-011）在 Service 层追加校验：目标类型为 `standard` 且
该表单存在任一权限组（含禁用组）的 `operations` 含 `workflow_*` 键时，**拒绝切换**
（`FORM_PERMISSION_BLOCKED_TYPE_SWITCH`），由管理员先清理对应组。不做原子移除——静默
收回授权会让权限收紧不可见；`standard → workflow` 方向合法集为超集，无需阻塞。

## 4. 字段权限

**语义**：声明该组内成员「可以查看和编辑数据的哪些字段」，作用于记录详情出网、记录编辑、
批量修改与提交校验。字段矩阵是**组属性**，与操作、数据范围保持组内关联（S2）。

- **字段清单事实源**：表单最新发布版本（`form_versions.field_keys` 顶层字段键有序数组 +
  `content` schema 取字段 label/type/required）；**未发布表单回落草稿** `draft_content` 提取
  （同一字段提取器）。字段键即协议 `widgetName`（与流程引擎节点字段权限 `FormPermissions`
  键位口径一致）。
- **存储**：JSONB 数组 `[{field, visible, editable}]`，由前端在保存时按弹窗勾选写入；后端
  逐项校验 field 存在于字段清单。
- **deny-by-default 合并**（S7）：判定时以当前字段清单 ∖ 矩阵覆盖 = 默认不可见不可编辑；
  矩阵中已不存在于清单的字段条目忽略。
- **与必填校验的协调**（⚠ v1 新增，v2.1 定版为「提交管线」，针对 `value.go` 信封校验
  「`visible` 必须等于发布快照可见性、必填终审强制」的现有行为）：
  - **配置期规则**：`visible=false` 仅允许非必填字段（按字段清单 required 判定，违反报
    `FORM_PERMISSION_FIELD_INVALID`）；权限组 `operations` 含 `add` 时，必填字段必须
    `editable=true`（否则添加路径无值可填，提交必败）。
  - **提交管线**（新增 `ValidateSubmittedRecordValuesWithPermission(content, submitted,
    fields FieldGate, previous map[string]any)`，不复用现有函数）：

    | 阶段 | 规则 |
    | --- | --- |
    | ① 信封解包 | 与现有规则一致：每个数据字段必须携带 `visible` 且**等于发布快照可见性**（资产权限隐藏不改变信封 `visible`，前端对权限隐藏字段照常携带快照可见性 + 空 data）；隐藏/布局字段不得携带数据 |
    | ② 权限合并 | 逐字段按 `fields`（`FieldsFor(op, record)` 结果）判定：`editable=false` 且请求携带非空 data → **整体拒绝**（越权，按 widgetName 回填错误）；`editable=false` 字段进入 rawValues 前以 `previous` 旧值回填（edit）或置 null（add，配置期规则已保证必填可编辑） |
    | ③ 终审复用 | 以合并后的 rawValues 调用既有 `ValidateRecordValues` 完成类型/范围/必填终审（必填由旧值自然满足），随后同事务行锁落库 |

  - 越权拒绝口径对齐流程引擎 `UpdateData`（整体拒绝，不做静默裁剪）。
- **约束传递**：`visible=false` 时该字段值**不出网**（列表/详情服务端裁剪）且 `editable`
  必须为 `false`（校验器拒绝矛盾组合）。
- **系统字段预留**：提交时间/提交人等系统列后续以 `sys_` 键段进入同一矩阵，本期不落地。

## 5. 数据权限（⚠ v1 重构）

**语义**：声明该组内成员「可以管理哪些数据」。数据范围是组属性，只参与**行级**判定
（查询过滤 + 旧记录操作判定，S2/S8），不与操作集扁平化合并。

存储结构（JSONB，整体校验后落库）：

```jsonc
{
  "match": "all",            // all = 且（默认）；any = 或
  "conditions": [
    { "field": "department", "operator": "in", "value": ["sales", "operation"] },
    { "field": "amount", "operator": "gte", "value": [1000] }
  ]
}
```

### 5.1 operator 字典

按字段类型白名单（类型系统复用表单值校验器 `service/value.go`）：

| operator | 中文 | 适用类型 |
| --- | --- | --- |
| `eq` / `ne` | 等于 / 不等于 | 文本、数字、日期、单选、成员、部门 |
| `gt` / `gte` / `lt` / `lte` | 比较 | 数字、日期 |
| `contains` | 包含 | 文本、多选 |
| `in` / `not_in` | 属于 / 不属于 | 单选、多选、成员、部门 |
| `empty` / `not_empty` | 为空 / 不为空 | 全部（value 须为空数组） |

### 5.2 JSONB 查询编译（⚠ v1 定版，v2.1 修订安全转换）

`form_records.values` 为键 = widgetName 的 JSONB，**无字段实体列**，且记录可引用任意历史
发布版本（`form_version_id`）。编译规则定版如下：

- **安全转换，不依赖行快照 JOIN**（⚠ v2.1 修订：`(values->>'F')::numeric` 遇脏值/跨版本
  改类型会**抛异常**而非返回 NULL，且「按行快照类型解释」无法自动改变强转分支）。定版为
  **guard 正则 + 条件转换**：转换前以正则守卫值形态，不满足守卫的表达式整体返回 NULL
  （不进入 cast），杜绝运行时异常：

  | 类型类 | 守卫 + 转换（`F` 为字段键，值一律参数绑定） |
  | --- | --- |
  | 数值 | `CASE WHEN values->>'F' ~ '^[+-]?([0-9]+\.?[0-9]*|\.[0-9]+)$' THEN (values->>'F')::numeric END` |
  | 日期时间（datetime 系，⚠ v2.2 修订） | **全部定宽文本比较，无 cast、无时区参与**。协议为单一 `datetime` widget + `format` 属性（`date`→`YYYY-MM-DD`、`datetime`→`YYYY-MM-DD HH:mm:ss`、`month`→`YYYY-MM`、`time`→`HH:mm`，均定宽零填充且无时区）：守卫按形状正则（如 datetime `^[0-9]{4}-[0-9]{2}-[0-9]{2} [0-9]{2}:[0-9]{2}:[0-9]{2}$`），比较直接用 `values->>'F'` 文本序——定宽零填充格式的字典序 = 时间序，确定性不受数据库 TimeZone 影响；不引入 `timestamptz`（无时区值强转会落入 session 时区陷阱） |
  | 文本/枚举 | 直接 `values->>'F'`，无需守卫 |

  条件配置期按字段 `widget.type`（datetime 系再按 `props.format`）分派类型类并校验比较值
  形状；行值不满足形状守卫（跨版本改类型/改 format/脏值）→ NULL 语义。

- **跨版本类型变更语义**：条件的类型类在**配置期**按当前快照校验；行值不满足该类型类守卫
  （历史版本类型不同、脏值）时转换结果为 NULL，进入下方 NULL 语义表——即「旧类型行不命中
  新类型条件」，无需 JOIN 行快照，语义与实现一致且无异常路径。`?`/`?|` 存在性运算符对
  标量/数组天然兼容（PG 语义：标量匹配自身），单选↔多选跨版本不产生分支。
- **规范化文本值 `V(F)`**（⚠ v2.3 定版，全部标量模板的统一取值表达式）：

  ```sql
  V(F) := CASE WHEN values->'F' IS NULL            -- 缺键
                OR jsonb_typeof(values->'F') = 'null'  -- JSON null 字面量
               THEN NULL ELSE values->>'F' END
  ```

  把「缺键」与「JSON null」统一归为 SQL NULL，同时**保留用户文本 `"null"`**（typeof=string，
  不误判为空——v2.1 的 `COALESCE(...,'null')` 写法会误伤，废弃）。
- **表达式模板**（operator × 类型类白名单在配置期校验后，运行期按下表编译；标量一律经
  `V(F)` 取值）：

  | operator | 表达式（语义） |
  | --- | --- |
  | `eq` | `V(F) = $n` |
  | `ne` | `V(F) <> $n`（V 为 SQL NULL 时结果 NULL → 不命中，三值逻辑，禁止 COALESCE 放行） |
  | 数字比较 | `CASE WHEN V(F) ~ '^[+-]?([0-9]+\.?[0-9]*|\.[0-9]+)$' THEN V(F)::numeric END` 与 `$n::numeric` |
  | 日期比较 | `V(F)` 先过形状守卫，再与同形状绑定值定宽文本比字典序 |
  | `contains` | `V(F) LIKE '%' || $n || '%'`（转义）；多选 `values->'F' ? $n` |
  | `in` | `V(F) = ANY($n::text[])`；多选 `values->'F' ?| $n::text[]` |
  | `not_in` | **`V(F) IS NULL OR V(F) <> ALL($n::text[])`**（⚠ v2.3：NULL 显式命中；不能写 `NOT (V = ANY(...))`——对 NULL 取反仍为 NULL，会漏掉应命中的行）；多选 `(empty) OR NOT (values->'F' ?| $n::text[])` |
  | `empty` | `V(F) IS NULL OR V(F) = '' OR (jsonb_typeof(values->'F') = 'array' AND jsonb_array_length(values->'F') = 0)`（⚠ v2.3 终版补正空串分支：`V(F)` 对 JSON 空串返回空文本但不为 NULL，缺 `= ''` 会误判为非空。精确覆盖：缺键、JSON null、空串、空数组；用户文本 `"null"`/`"[]"` 为 typeof=string，**不**视为空） |
  | `not_empty` | `NOT (empty)` |

- **NULL 语义**：经 `V(F)` 归一后，「缺键 / JSON null / 守卫不通过（跨版本/脏值）」均按
  SQL NULL 参与判定——`eq/gt/contains/in` 不命中；`ne` 不命中（三值逻辑）；`empty` 命中；
  `not_empty` 不命中；`not_in` **命中**（模板已显式 `V IS NULL OR …`，非取反实现）。
- **字段生命周期与授权漂移阻塞**（⚠ v2.2 新增）：字段删除或类型/形状变更（`widget.type`
  或 datetime `props.format` 变化）会使引用它的 data_scope 条件进入 NULL 语义——尤其
  `not_in` 对 NULL 命中、`empty` 命中，可能把受限范围**静默扩大**。定版为**发布阻塞**：
  表单发布时（publish 服务）比对新版本与当前发布版的字段清单与类型/形状，被删除或变更的
  字段若被任一**启用**权限组的 `data_scope` 引用，发布拒绝（`FORM_PERMISSION_BLOCKED_
  PUBLISH`，错误信息列出冲突字段），由管理员先调整权限组再发布。不采纳「自动禁用相关组 +
  审计」——静默收回授权属于不可见的可用性损失；阻塞是显式、可预期的。字段矩阵对已删字段
  条目本就被忽略（S7 deny-by-default，无泄露面），不纳入阻塞范围。
- **索引策略**（⚠ v2.2 修订：移除根列 GIN）：模板谓词均作用于 `values->'F'` 表达式，
  根列 `GIN (values)` 无法命中（GIN 只服务整列操作符），且 `ne`/`not_in`/`empty` 等负向
  谓词本就不可用——保留它只有写放大没有收益，迁移 **不建** GIN。P2 记录列表查询在
  `(tenant_id, form_id, id DESC)` 既有索引范围内取行集 + 行内 JSONB 条件过滤（单表单行数
  有限）。性能演进统一收敛到 §5.2 投影表方案（真实列 + btree 索引），触发条件不变。
- **可筛选字段投影表（演进路径，P2 触发）**：单表单记录量 > 10 万或列表查询 P95 > 500ms 时，
  引入写时维护的 `form_record_filter_values (record_id, field, text_value, number_value,
  ts_value)` 投影表（仅投影被该表单任一 data_scope 引用的字段，提交/编辑事务内同步维护，
  写入时按提交行的值与守卫同规则转换），查询切至投影列。存储与判定语义（本节）在两种物理
  路径下保持一致。
- **多组 OR**（S2）：行可见 = ∃ 命中组 g：`view ∈ g.operations ∧ 行满足 g.data_scope`，
  编译为各组的 OR 合取；同组内 `match=all/any` 为组内 AND/OR。

## 6. 数据模型（迁移 000058，⚠ v1 修订）

表名采用泛化命名 `asset_permission_groups`（`asset_type` 现仅 `form`；**类型白名单由
Service 层资产类型注册表承载，不设数据库 CHECK**——仪表盘扩展无需 DDL，约束与代码同源）：

```sql
-- 资产权限组：主体范围 × 操作集 × 字段矩阵 × 数据范围的整体授权单元
CREATE TABLE asset_permission_groups (
    id              BIGSERIAL PRIMARY KEY,
    tenant_id       BIGINT       NOT NULL,
    application_id  BIGINT       NOT NULL,                    -- 冗余归属，Service 校验与资产一致
    asset_type      VARCHAR(16)  NOT NULL DEFAULT 'form',     -- form（类型白名单在 Service 注册表）
    asset_id        BIGINT       NOT NULL,                    -- form → forms.id（内部主键）
    code            VARCHAR(64)  NOT NULL,                    -- fpg_ 前缀服务端生成，出网稳定标识
    name            VARCHAR(64)  NOT NULL,
    description     VARCHAR(200) NOT NULL DEFAULT '',
    enabled         BOOLEAN      NOT NULL DEFAULT TRUE,       -- 禁用组维持收口（S5）但不授权
    operations      JSONB        NOT NULL DEFAULT '[]',       -- 操作键数组（§3 字典）
    field_permissions JSONB      NOT NULL DEFAULT '[]',       -- [{field,visible,editable}]（§4）
    data_scope      JSONB        NOT NULL DEFAULT '{}',       -- {match,conditions}（§5）
    revision        BIGINT       NOT NULL DEFAULT 1,          -- 整组乐观锁（PUT 全量提交口令）
    created_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    deleted_at      TIMESTAMPTZ,
    CONSTRAINT uq_asset_permission_groups_code UNIQUE (code)
);
CREATE INDEX idx_asset_permission_groups_tenant
    ON asset_permission_groups (tenant_id, asset_type, asset_id);

-- 权限组主体：成员 / 部门 / 角色，判定侧按主体反查
CREATE TABLE asset_permission_group_subjects (
    id           BIGSERIAL PRIMARY KEY,
    tenant_id    BIGINT      NOT NULL,
    group_id     BIGINT      NOT NULL,
    subject_type VARCHAR(16) NOT NULL,
    subject_id   BIGINT      NOT NULL,          -- users.id / departments.id / roles.id
    created_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CONSTRAINT uq_asset_permission_group_subjects UNIQUE (group_id, subject_type, subject_id),
    CONSTRAINT ck_asset_permission_group_subjects_type
        CHECK (subject_type IN ('member', 'department', 'role')),
    CONSTRAINT fk_asset_permission_group_subjects_group
        FOREIGN KEY (group_id) REFERENCES asset_permission_groups (id) ON DELETE CASCADE
);
CREATE INDEX idx_asset_permission_group_subjects_lookup
    ON asset_permission_group_subjects (tenant_id, subject_type, subject_id);
```

设计说明：

- **`code` 出网**（`fpg_` 前缀服务端生成）：对齐 `form_`/`menu_` 惯例（迁移 000045 口径），
  内部自增 ID 不出网。
- **`revision` 整组乐观锁**：弹窗四分区一次性「确定」提交（PUT 全量）；冲突返回
  `FORM_PERMISSION_REVISION_CONFLICT`（409）。
- **主体引用完整性**（⚠ v1 新增，v2.1 修订级联语义）：组删除走 `TenantBaseModel` 软删
  （`deleted_at`），**外键 `ON DELETE CASCADE` 只对物理 DELETE 生效**——因此 DELETE Service
  在同一事务内**显式硬删** subjects 行（授权关系无保留价值）；外键仅作为未来物理清理路径
  （租户注销清库、数据迁移）的兜底，保证任何物理删除不产生孤儿授权行。`subject_id` 不做
  FK（角色/部门删除时判定侧容错：解析不到的主体不命中），写入时经 Service 校验同租户
  存在性。
- **软删**：组随 `TenantBaseModel` 软删。

## 7. API 设计（⚠ v1 修订）

### 7.1 权限资源（标准 CRUD 动词）

路由鉴权仅支持 get/list/create/update/patch/delete 六类动词（`utils/request`），配置面资源
**`form-permissions`** 使用标准 CRUD 动词，URL 门与路由一一对应：

| 路由 | 鉴权键 |
| --- | --- |
| GET `/forms/:code/permission-groups` | `form-permissions:list` |
| POST `/forms/:code/permission-groups` | `form-permissions:create` |
| PUT `/forms/:code/permission-groups/:groupCode` | `form-permissions:update` |
| DELETE `/forms/:code/permission-groups/:groupCode` | `form-permissions:delete` |
| GET `/forms/:code/permission-fields` | `form-permissions:list` |

- 补授：按管理员规则签名（000034/000035「members:*+roles:*+departments:*」基线签名模式）
  补授上述四动词；`form-permissions` 资源不经管理组放行（与 forms 同口径）。
- **数据面旁路键 `form-data:admin`**：独立动作键（服务层判定专用，不挂 URL 门），同样按
  基线签名补授租户管理员。持 `form-permissions:*` **不**获得数据旁路（S3 分离）。
  **通配展开接入**（⚠ v2.1 定版）：`PermissionsOf` 当前的 `AllOperation` 展开只对
  `form-actions` 资源迭代 `menuActionCodes`，`form-data:*` / `*:*` 规则不会产出
  `form-data:admin`。实施时将 `form-data` 纳入统一的**动作资源注册表**（资源 → 动作码集，
  `form-actions` 为既有注册项，`form-data` 追加注册动作码 `admin`），`PermissionsOf` 与
  `Authorize` 的通配展开迭代该注册表。三者等价产出 `form-data:admin`：精确授权
  `form-data:admin`、资源通配 `form-data:*`（AllOperation）、全局通配 `*:*`
  （All + AllOperation）。
- 配置接口是管理后台能力，普通成员不读取；成员侧判定全部在服务端执行点内联完成。

## 8. 判定器与执行点（⚠ v1 重构）

### 8.1 FormPermissionEvaluator（form 域内，组绑定结果）

```go
// MatchedGroup 成员命中的单个启用权限组：保留组内四要素关联，
// 禁止消费方跨组扁平化（S2 的代码化表达）。
type MatchedGroup struct {
    Code       string
    Operations map[string]bool
    Fields     map[string]FieldPermission // 经 S7 deny-by-default 合并后的矩阵
    DataScope  DataScope
}

type ResolvedFormPermission struct {
    Admin    bool           // form-data:admin 旁路（S3）
    Baseline bool           // S4：表单无任何权限组行，执行点按基线语义放行
    Matched  []MatchedGroup // 启用且主体命中的组（S5）

    // 判定方法（消费方只经方法判定，不自行并集；字段判定必须携带操作维度，
    // 防止跨操作混合字段权限）：
    // AllowsOperation(op, record) bool
    //   = Admin || Baseline || ∃ g ∈ Matched: op ∈ g.Operations ∧ record ∈ g.DataScope
    // AllowsNewRecord(op) bool  —— add/import/copy 新记录：Admin || Baseline ||
    //   ∃ g: op ∈ g.Operations（S8：不受数据范围约束）
    // FieldsFor(op, record) map[string]FieldPermission
    //   = Admin/Baseline 全量可编辑；否则 ∪{ g.Fields : g 命中 op 且 record ∈ g.DataScope }
    // FieldsForNew(op) map[string]FieldPermission
    //   = Admin/Baseline 全量；否则 ∪{ g.Fields : g 含 op }（新记录无范围可判）
    // ListScopeFilter(op) —— 列表行过滤：OR over Matched（op ∧ scope），§5.2 编译
}

type FormPermissionEvaluator interface {
    Evaluate(ctx context.Context, member *iammodel.User, formID uint) (*ResolvedFormPermission, error)
    EvaluateForForms(ctx context.Context, member *iammodel.User, formIDs []uint) (map[uint]*ResolvedFormPermission, error)
}
```

- **主体解析**：成员 → 直接成员命中 ∨ 部门命中（成员所属部门的**任一祖先链**上的部门被
  配置即命中，即「部门含子部门」，语义对齐 `TenantProductAccessEvaluator`）∨ 角色命中。
  member/department/role 读取经窄端口复用 iam 仓储，不直连表。
- **写路径事务与锁**（S8）：`edit`/`delete` 的旧记录加载与写入同一事务，记录行
  `SELECT ... FOR UPDATE`，判定与写入原子，杜绝「判定后记录被并发改出范围」的 TOCTOU。

### 8.2 执行点分期

| 执行点 | 语义 | 分期 |
| --- | --- | --- |
| 菜单快照裁剪 | application 域菜单读取的 `assetVisible` 链路扩窄端口 `FormPermissionDirectory.VisibleFormIDs(ctx, memberID, formIDs)`（方向 application → form，装配模式同现有 `FormDirectory`）；入口判定 = `view ∨ add`（S8，仅录入表单对仅 add 成员可见），无任何命中（S5 含禁用组收口）的表单节点隐藏，空分组随既有 `hasVisibleDescendant` 裁剪 | P1 |
| 记录提交（add） | `POST /form-records`：`AllowsNewRecord("add")` 为假 → `FORM_PERMISSION_DENIED`；请求对不可编辑字段携带数据 → 整体拒绝；可编辑字段集 = 含 `add` 组矩阵并集 | P1 |
| 表单运行时 | `GET /applications/code/:code/forms/:formCode/runtime`：`view ∨ add` 均无 → `FORM_PERMISSION_DENIED`；出网投影追加 `permissions` 块（⚠ v2.1 定版，v2.3 修订字段矩阵拆分）：`operations`（记录无关操作可用性，记录级操作由记录接口逐行判定）+ **`viewFields` 与 `addFields` 两个独立矩阵**——`viewFields = FieldsForNew("view")`（列表/查看模式列基准），`addFields = FieldsForNew("add")`（填写模式可填字段）；查看与填写的字段集可能不同（如仅录入组只见必填收集字段、查看组反见只读汇总字段），**不得合并或按模式二选一返回**。前端按当前模式取对应矩阵；P2 记录接口在行级以 `FieldsFor(op, record)` 精化。**合成规则**：渲染以 `effectiveVisible = 快照可见 ∧ 权限可见`、`effectiveEditable = 快照可见 ∧ 权限可编辑` 为准（快照隐藏/布局字段恒不可编辑）；提交信封 `visible` 仍按快照可见性携带（§4 管线①），服务端以同一矩阵复核——前端无法渲染出被拒绝字段，「不可见」在渲染层即生效 | P1 |
| 记录列表/详情 | 行过滤 = `ListScopeFilter("view")`；行值投影 = 逐行按「该行可经哪些组可见」的矩阵并集裁剪（§5.2）；无 `view` → 空列表/403 | P2（随记录查询里程碑） |
| 记录编辑/删除/复制 | S8 旧记录组级判定 + S9 合并提交 + 同事务行锁 | P2 |
| 批量打印 / 批量修改 / 导出 | 逐记录 `AllowsOperation` + 字段矩阵（batch_modify 可改字段 = 各命中组 editable 并集，逐行范围判定）；导出行集 = 范围过滤结果、列集 = 矩阵并集 | P2/P3（随各自端点落地） |
| 流程特有操作 | `workflow_terminate`：workflow 域 Terminate 动作校验处经窄端口对实例关联记录做组级判定（workflow → form 窄端口，拒绝码 `FORM_PERMISSION_DENIED`）；`workflow_owner_transfer`/`workflow_activate` 随流程引擎实例级能力落地 | P3 |

### 8.3 性能

- 判定数据面小（组数 ≤ 50/表、主体行少），P1 不引入缓存：单请求一次组+主体加载，请求内
  memo；菜单快照走 `EvaluateForForms` 批量路径。
- 预留：量级上来后在 form 域内加租户级组快照缓存（失效点：组写事务后失效），不跨域失效。
- 数据范围查询性能演进见 §5.2（GIN → 投影表触发条件）。

### 8.4 与流程引擎的对接边界

- 流程表单的权限组**不替代**流程引擎自身的任务分配/审批人解析（assignment/Resolver 链路）；
  权限组只管「数据与操作入口」。
- `workflow_terminate` 判定叠加在 Task Engine 动作校验处，先于 `WORKFLOW_ACTION_NOT_ALLOWED`
  判资产权限，拒绝码用 `FORM_PERMISSION_DENIED`，避免语义混入状态机。
- 审批编辑字段权限（节点 `FormPermissions`）与本权限组字段矩阵**并存不合并**：前者作用于
  审批任务编辑场景，后者作用于表单数据场景；两处校验器共享字段键合法性检查工具函数。

## 9. 与既有机制的边界

| 机制 | 关系 |
| --- | --- |
| 租户级自定义 RBAC / 管理组 | 管后台功能权限，正交；`form-permissions`（配置面）与 `form-data:admin`（数据面）是其资源/动作键 |
| 菜单节点 `hidden` | 管理员主动导航隐藏（ADR-011），与数据权限裁剪叠加生效、语义独立 |
| 流程引擎审批编辑字段权限 | 场景不同（§8.4），并存不合并 |
| 成员信息管理字段可见性（000031） | 成员档案场景，正交 |
| 产品中心访问判定 | 应用入口级门禁，正交（产品门 → 菜单裁剪 → 资产权限逐层收口） |

## 10. 实施分期

- **P1（本设计落地范围）**：迁移 000058（含 `scripts/db.sql` 快照同步、外键与 CHECK 约束；
  **不建 GIN**，§5.2）→ 动作资源注册表接入 `form-data`（§7.1 通配展开）→ 域内
  controller/service/repository 小三层与错误码 → 权限组 CRUD + 字段清单接口（§4 配置期
  校验含必填协调）→ `FormPermissionEvaluator`（组绑定判定）→ 权限感知提交管线
  `ValidateSubmittedRecordValuesWithPermission`（§4）+ 运行时 `permissions` 投影
  （operations + viewFields/addFields 双矩阵合成）+ 菜单裁剪窄端口（view ∨ add）→
  switch-type 阻塞校验 → **发布阻塞校验**（§5.2 字段生命周期，publish 服务内比对字段清单
  与启用组 data_scope 引用）→ 审计事件 → swagger（中文注释）→ `SEC-FPERM-*` 真库集成
  用例（越权提交、未命中组隐藏、**串联越权回归用例**（A 组编辑 X + B 组查看 Y 不得编辑
  Y）、禁用组收口、deny-by-default 新字段、乐观锁冲突、跨租户、switch-type 阻塞、
  发布阻塞、仅 add 成员入口与填写模式、`form-data:*`/`*:*` 通配展开等价性）。
- **P2**：记录列表/详情/编辑/删除/复制执行点（含 §5.2 JSONB 编译与行锁）；批量修改/导出。
  投影表按 §5.2 触发条件演进。
- **P3**：流程特有操作执行点（`workflow_owner_transfer`/`workflow_activate` 随流程引擎实例
  级能力落地）；仪表盘资产类型（`asset_type=dashboard`，无 DDL，Service 注册表扩展）。

- 判定器：**组绑定**（A 组编辑 X + B 组查看 Y 的串联越权回归）、`FieldsFor`/`FieldsForNew`
  按操作维度隔离、部门含子部门（祖先链命中）、角色命中、`form-data:admin` 旁路、
  `form-permissions:*` 不触发旁路、无权限组基线（S4）、有组未命中（S5）、禁用组收口不授权。
- 通配展开：精确 `form-data:admin`、`form-data:*`、`*:*` 三者等价产出；`form-actions` 既有
  展开回归不受注册表重构影响。
- 写路径：add 不受范围约束（S8）、edit 旧记录范围判定 + 行锁、编辑后移出范围下次不可见。
- 数据范围编译：**守卫转换**（脏值/跨版本类型变更行不抛异常、按 NULL 语义表判定）、
  **datetime 四形状定宽文本比较**（date/datetime/month/time 各形状守卫与字典序=时间序、
  与数据库 TimeZone 无关）、`V(F)` 归一（缺键与 JSON null 归 NULL、**用户文本 `"null"`/`"[]"`
  不误判为空**、**空串 `""` 判空**）、NULL 语义表逐项（eq/ne/empty/not_empty/**not_in 显式 `IS NULL OR` 模板
  命中 NULL**）、多选 `?`/`?|` 标量数组兼容、match all/any、多组 OR。
- 生命周期联动：发布阻塞（删除/改类型被启用组引用 → 拒绝并列出字段；禁用组引用不阻塞）、
  仅 add 成员的菜单可见与运行时填写模式。
- 运行时投影：`viewFields`/`addFields` 双矩阵独立出网（view+add 并存时两矩阵不一致的用例）、
  `effectiveVisible/Editable` 合成、信封 visible 仍按快照。
- 集成：菜单裁剪联动（含空分组收敛）、
  PUT 乐观锁并发、组删除 subjects 同事务硬删（软删不触发外键）、跨租户盲写拒绝、
  switch-type 阻塞与放行两向、审计事件落库。
