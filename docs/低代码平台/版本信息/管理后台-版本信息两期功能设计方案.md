# 管理后台「版本信息」两期功能设计方案

## 1. 文档目的

本文定义租户管理后台「版本信息」的两期建设范围、功能规则、数据边界与接口契约。目标是先建立真实、可追溯的订阅、权益与资源概览基础，再建设交易与结算闭环。

本文只覆盖当前租户管理后台及必要的平台运营配套能力，不包含表单、流程、数据工厂、AI 等尚未落地领域本身的业务实现。

## 2. 现状与设计原则

### 2.1 现有基础

- `tenants.plan` 现有 `free`、`trial`、`pro` 三个历史套餐代码。
- `tenants.quotas` 保存租户对默认配额的覆盖值。
- `apps`、`members`、`storage_gb` 已具备部分计量或拦截基础。
- `GET /api/v1/auth/userinfo` 可返回当前租户、套餐与五项生效配额。

目前没有套餐有效期、订阅、权益、用量概览、订单、支付、钱包、计费流水或凭证模型。版本页中的名称、到期日、余额、容量和权益均不得作为真实业务数据。

### 2.2 套餐建模结论

企业订阅不能只是一组整数配额。它至少同时表达年度基础套餐、包含席位、额外席位、周期资源额度、功能权益、服务等级与附加能力。

| 类型 | 语义 | 示例 | 计量方式 |
| --- | --- | --- | --- |
| 存量配额 | 时点上不得超过的数量 | 成员、应用、当前存储占用 | 实时计数或事务内预留 |
| 周期额度 | 自然年、月或订阅期内的累计数量 | 年度上传量、月度流程量 | 幂等使用事件与周期聚合 |
| 点数额度 | 可消费、可结转规则明确的单位 | AI 点数 | 不可变额度流水 |
| 功能权益 | 是否允许使用某能力及其参数上限 | 集成、打印、审计 | 权益解析与业务授权复核 |
| 服务权益 | 人工服务或部署方式 | 服务等级、私有部署 | 订阅快照，不参与实时拦截 |

`trial` 是订阅的授予方式（`grant_type`），不是目标模型中的长期套餐商品。现有 `tenants.plan = trial` 仅在迁移期作为兼容值。

### 2.3 设计原则

1. **真实优先**：没有可靠计量来源的指标不展示伪造数值。
2. **套餐与用量分离**：订阅快照决定上限，计量服务决定已用值。
3. **一期建立版本化事实源**：一期即引入套餐版本、订阅和权益规则，不以代码常量作为长期套餐事实源。
4. **兼容现有执行**：一期保留 `tenants.plan`、`tenants.quotas` 与 `QuotaService` 的既有语义；活动订阅是新事实源，旧字段是过渡投影。
5. **一期不引入交易**：一期可人工授予订阅，但不开放支付、充值、凭证审核或超额扣费。
6. **不可变记录**：周期用量、账务、充值、退款均使用不可变记录，读模型和余额必须可重建。
7. **服务端判定有效期**：过期、降级与当前状态由服务端时钟和事务决定，前端倒计时只用于展示。
8. **租户隔离与权限前置**：租户接口走 Authentication → Tenant → TenantStatus → Authorization；平台运营接口只走平台链。

## 3. 总体分期

| 阶段 | 名称 | 面向用户的结果 | 不包含的内容 |
| --- | --- | --- | --- |
| 第一期 | 订阅、权益与资源概览基础 | 真实订阅、有效期、已接入用量和权益；运营可人工授予、调整与到期降级 | 自助购买、支付、钱包、超额扣费、凭证审核 |
| 第二期 | 交易、附加包与结算闭环 | 可购买、续费、增购，查看订单、用量与账务；按审计口径结算 | 未建设业务领域的实际执行能力 |

## 4. 第一期：订阅、权益与资源概览基础

### 4.1 功能范围

将静态版本页替换为真实概览，并建立可扩展的套餐版本、订阅与权益基础。平台运营可人工授予免费、试用或付费订阅，但不产生订单或支付。

页面仅展示有可靠来源的成员、应用和当前附件存储占用。表单、流程、年度上传量、总数据量、AI 点数、管理员数量等资源，在所属领域没有可靠计量前返回“待计量”，不得显示样例数值。

### 4.2 用户与权限

| 用户 | 可执行操作 |
| --- | --- |
| 租户管理员 / 租户所有者 | 查看当前订阅、资源用量、权益和咨询升级入口。 |
| 普通成员 | 不显示版本信息菜单；直接访问返回 `FORBIDDEN`。 |
| 平台运营管理员 | 查看当前及历史订阅；人工授予、替换、延长、取消订阅和配置特批权益。 |

新增租户侧权限 `editions:get`，仅授予租户基线管理员角色。读取接口使用 `GET /api/v1/editions/current`，使现有“首资源段 + HTTP 方法”的授权推导得到 `editions:get`，无需改动授权器。

### 4.3 页面与业务规则

#### 4.3.1 当前订阅

- 展示套餐名称、状态、授予方式、开始时间、到期时间、到期处理规则和席位摘要。
- 新试用订阅必须有 `ends_at`；免费或长期人工授予订阅可没有到期日。
- 当前时间达到 `ends_at` 时，读取接口立即投影为 `expired`，即使定时任务尚未执行。
- `expired` 到降级事务提交之间，订阅记录仍用于展示历史套餐，但所有资源上限和功能权益立即按免费版解析，响应标记 `limitSource = expiry_fallback`；不得继续按已过期快照展示或放大权益。
- 定时任务在一个事务内关闭过期订阅、创建或激活降级后的免费订阅、同步兼容字段；重复执行不得产生第二条活动订阅。
- 无可验证到期日的存量 `trial` 回填为 `legacy_pending_review`，页面显示“有效期待确认”，不显示倒计时，也不参与自动降级；运营补录后才能变为活动订阅。
- 一期不产生到期提醒事件；提醒和 Outbox 随消息中心或二期可靠任务体系建设。
- 咨询升级跳转至公开配置中的联系入口；未配置时只提示联系平台管理员。

#### 4.3.2 容量与用量

| 资源键 | 分类 | 一期状态 | 口径 / 页面行为 |
| --- | --- | --- | --- |
| `members` | 存量配额 | 已接入 | 当前租户中 `active` 或 `disabled` 且未软删的成员数；显示进度。 |
| `apps` | 存量配额 | 已接入 | 当前租户未软删的应用数；显示进度。 |
| `storage_bytes` | 存量配额 | 已接入 | `uploading` 按声明大小预留、`ready` 按实际大小累加；显示“当前附件存储占用”。 |
| `forms` | 存量配额 | 待计量 | 可显示上限和“暂未启用统计”，不返回已用值。 |
| `workflow_runs_month` | 周期额度 | 待计量 | 暂不显示用量和进度。 |
| `annual_upload_bytes` | 周期额度 | 待计量 | 不得以当前存储占用替代年度累计上传量。 |
| `data_records` | 存量/周期额度 | 待计量 | 表单数据领域落地后再确定总量和单表口径。 |
| `admin_seats`、`ai_credits` | 席位/点数额度 | 待计量 | 先定义权益，待成员角色或 AI 事件可可靠计量后启用。 |

统一返回资源键、显示名称、分类、单位、生效上限、已用值、使用率、统计时间、重置周期、上限来源和计量状态。`-1` 表示不限量，`0` 表示不可用；不限量和待计量不返回使用率。只有周期额度返回 `resetCycle`，成员、应用和当前存储不返回该字段。

`storage_bytes` 是套餐版本、订阅和覆盖记录中的唯一存储权益键，单位为字节；现有 `tenants.quotas.storage_gb` 仅是 `QuotaService` 过渡期的兼容键，单位为 GiB（`1 GiB = 1024 × 1024 × 1024` 字节）。一期为保证两侧投影和实际拦截完全一致，存储上限只允许 `-1`、`0` 或 GiB 的整数倍：发布套餐版本、人工授予和保存存储特批时均须校验 `storage_bytes % GiB == 0`，不接受 500 MiB 等非整 GiB 值。后续 `QuotaService` 改为直接使用统一权益解析器后，才允许解除该限制。

#### 4.3.3 权益展示

- 返回套餐版本定义的权益组、权益键、名称、可用状态、参数上限和说明。
- 一期只列出后端已实际可用、可稳定授权的能力；未实现领域不能标为“可用”。
- 权益用于展示与前端入口裁剪，不能替代 RBAC、租户状态和业务服务的实际授权。
- “可增购”一期仅进入咨询，不创建附加包订单。

### 4.4 数据设计

#### 4.4.1 事实源与兼容边界

活动订阅及其套餐版本是当前权益的事实源。`tenants.plan` 保留为既有调用方和配额服务的过渡投影；`tenants.quotas` 保留为历史和临时兼容覆盖。订阅变更必须在同一事务内更新活动订阅、兼容 `tenants.plan` 投影与必要的配额覆盖，禁止任一侧单独写入。

在 `QuotaService` 切换为统一权益解析器前，兼容投影仅允许 `free`、`trial`、`pro`。新增套餐版本必须声明 `compatibility_plan_code`，不能由前端猜测映射关系。资源投影逐键执行：`members`、`apps` 等同单位键原样写入；`storage_bytes = -1` 投影为 `storage_gb = -1`，`storage_bytes = 0` 投影为 `storage_gb = 0`，正数按 `storage_gb = storage_bytes / GiB` 精确换算。因为发布和授予校验已经拒绝非整 GiB 值，禁止采用向上或向下取整。

过期窗口不能只在页面降级：`QuotaService` 的成员、应用和存储检查须在读取旧 `tenants.plan` 前调用到期守卫。守卫发现活动订阅已到期时，以免费版的 `compatibility_plan_code` 计算本次生效上限；定时任务随后负责把该即时投影物化为免费订阅和旧字段。这样页面与写路径在任务延迟期间同样使用 `expiry_fallback`，不会出现页面已降级但仍可按旧档位创建资源的窗口。

#### 4.4.2 套餐与版本

| 表 | 核心字段 | 说明 |
| --- | --- | --- |
| `edition_plans` | `code`、`name`、`status`、`kind` | 稳定套餐目录；区分基础套餐与附加能力，不保存价格。 |
| `edition_plan_versions` | `plan_id`、`version`、`display_name`、`billing_cycle`、`compatibility_plan_code`、`entitlements`、`published_at`、`retired_at` | 不可变权益快照。 |

`entitlements` 的资源规则至少含 `key`、`category`、`limit`、`unit`、`reset_cycle`；功能规则至少含 `key`、`available`、`parameters`。已发布套餐版本只能新增，不可修改。

首次建表迁移必须同时初始化目录，不能依赖人工预置：写入基础套餐 `free`、`trial`、`pro`，每个套餐写入不可变的 `version = 1` 已发布快照，并分别设置 `compatibility_plan_code = free`、`trial`、`pro`。三个快照的 `apps`、`members`、`forms`、`workflow_runs_month` 上限与现有 `DefaultQuotas` 保持一致，`storage_bytes` 分别为 `1 GiB`、`5 GiB`、`-1`；迁移以稳定套餐编码和版本号幂等插入，不得覆盖已发布快照。历史租户回填和人工授予只可引用这些已发布版本。

#### 4.4.3 `tenant_subscriptions`

| 列 | 类型 / 约束 | 说明 |
| --- | --- | --- |
| `id` | `BIGSERIAL PK` | 订阅主键。 |
| `tenant_id` | `BIGINT NOT NULL` | 租户归属；同租户最多一条活动基础订阅。 |
| `plan_version_id` | `BIGINT NOT NULL` | 指向不可变套餐版本。 |
| `status` | `VARCHAR(32) NOT NULL` | `active` / `expired` / `replaced` / `cancelled` / `legacy_pending_review`。 |
| `grant_type` | `VARCHAR(16) NOT NULL` | `system` / `manual` / `self_service` / `trial`。 |
| `starts_at`、`ends_at` | `TIMESTAMPTZ` | 有效期；试用必须有结束时间。 |
| `operator_account_id`、`remark` | 账号 / 文本 | 平台人工操作信息，仅运营面可读。 |

必须有“同租户最多一条 `active` 基础订阅”的部分唯一索引和 `ends_at IS NULL OR ends_at > starts_at` 约束。存量 `free`、`pro` 回填为长期兼容订阅；无法验证到期日的 `trial` 回填为 `legacy_pending_review`，不得产生 `active + ends_at NULL` 的试用记录。

#### 4.4.4 `tenant_entitlement_overrides`

特批覆盖记录包含 `tenant_id`、`entitlement_key`、`value`、`reason`、`source`、`starts_at`、`ends_at`、`operator_account_id`。`source` 只允许以下枚举：`legacy`（迁移期从旧 `tenants.quotas` 映射，只读，不可由运营新建）、`manual`（平台运营人工特批）和 `trial`（试用授予产生的临时特批，必须与订阅同日到期）。降级时移除已到期或 `source = trial` 的覆盖，保留仍有效的 `manual` 覆盖。

响应的 `limitSource` 固定为 `plan_version`（当前有效套餐版本）、`tenant_override`（有效的 `manual` 或 `trial` 覆盖）、`legacy_quota`（尚未迁移完毕的旧覆盖）或 `expiry_fallback`（订阅已到期、等待物化免费版）。该字段只表达当前上限的解析来源，不能直接等同于覆盖记录的 `source`。

读历史覆盖时，`storage_gb` 必须映射为 `storage_bytes`：`-1 → -1`、`0 → 0`、正数为 `storage_gb × GiB`，并在乘法前做 `int64` 溢出校验；其他旧键按同名同单位读取。写入新的存储特批只保存 `storage_bytes`，并沿用整 GiB 校验；同一事务中的兼容投影再写回等值 `storage_gb`，不能让 `storage_bytes` 和 `storage_gb` 同时作为独立覆盖来源。

### 4.5 接口设计

#### 4.5.1 租户读取

```text
GET /api/v1/editions/current
Authorization: Bearer <JWT>
权限：editions:get
```

响应包含 `subscription`、`quotas`、`features` 与响应级 `asOf`。资源级字段为 `key`、`category`、`name`、`unit`、`limit`、`usage`、`usagePercent`、`meteringStatus`、`limitSource`、`asOf` 和可选 `resetCycle`。当订阅到期但任务尚未落库时仍返回 `status = expired`，资源和功能按免费版返回，并使用 `limitSource = expiry_fallback`；`meteringStatus = pending` 时省略 `usage`、`usagePercent` 和资源级 `asOf`，不返回伪零值。

#### 4.5.2 平台运营接口

```text
GET /api/v1/platform/tenants/{id}/edition
PUT /api/v1/platform/tenants/{id}/edition
GET /api/v1/platform/edition-plan-versions?kind=base&status=published
```

租户读取返回当前订阅、历史订阅、有效覆盖和计量摘要。套餐版本列表只返回可授予的已发布基础套餐版本，至少包含 `id`、`planCode`、`displayName`、`version`、`billingCycle`、`compatibilityPlanCode`、权益摘要和适用的授予方式；运营界面必须先读取该列表，再提交 `planVersionId`。写入使用 `planVersionId`、`grantType`、`startsAt`、`endsAt`、`remark` 与明确覆盖项，不接受客户端直接写 `tenants.plan` 或任意 `quotas` JSON。

写入事务：锁定租户 → 关闭旧活动订阅 → 校验套餐版本和授予规则（包括存储整 GiB 限制）→ 创建新订阅 → 写入覆盖 → 同步兼容投影。提交后写入 `audit_logs`。

一期不提供套餐目录或套餐版本的新增、编辑、发布、下架接口；目录初始化和任何权益调整均通过版本化 SQL 迁移新增快照完成。运营面只能查询可授予版本并授予租户，不能修改已发布版本或构造未发布版本 ID。二期商品管理落地后，再增加受审计的版本管理流程。

#### 4.5.3 内部计量契约

新增 `EditionUsageReader`，以稳定资源键获取当前租户用量。成员、应用、存储复用已有仓储计数，不在控制器中写 SQL。表单、流程、年度上传量、数据量和 AI 等资源只有在所属领域能提供幂等计量后才能注册；未注册统一返回 `pending`。

### 4.6 第一期实施清单与验收

| 范围 | 工作项 |
| --- | --- |
| 数据库 | 新增套餐、套餐版本、订阅、特批覆盖的 up/down 迁移、中文注释、索引、历史回填，并以迁移 seed `free`、`trial`、`pro` 三档已发布快照，同步 `scripts/db.sql`。 |
| 后端领域 | 在 `internal/platform/edition/` 建立 controller → service → repository；实现权益解析、订阅查询、人工授予、过期投影和幂等降级任务。 |
| 配额兼容 | 原子同步订阅与旧字段；`storage_bytes` 与 `storage_gb` 按整 GiB 精确换算，不改变已有创建/上传路径的事务和拦截语义。 |
| 安全与审计 | 注册 `editions:get` 权限；人工授予、替换、降级在提交后写审计。 |
| API 契约 | 所有一期业务失败均使用 `httpx.BizError` 稳定返回 `errCode`；至少定义 `EDITION_PLAN_VERSION_NOT_FOUND`、`EDITION_PLAN_VERSION_NOT_GRANTABLE`、`EDITION_GRANT_INVALID`、`EDITION_OVERRIDE_INVALID`、`EDITION_STORAGE_LIMIT_INVALID`。控制器 Swagger 的 `@Tags`、`@Summary`、`@Description` 使用中文，并逐接口以 `@Failure` 标明相应错误码；同步维护 `packages/utils/src/request/errorCodes.ts`，前端仅按 `errCode` 分支，不匹配 `msg` 文本。 |
| 前端 | 新建 `api/edition.ts`，先读取可授予套餐版本列表后提供人工授予；移除静态版本、余额、容量和权益常量，按订阅状态、`meteringStatus` 与 `limitSource` 渲染。 |
| 验证 | 覆盖初始化目录、到期窗口的页面/写路径同档位降级、幂等降级、存量试用回填、临时覆盖清理、覆盖来源枚举、存储双键精确换算与非整 GiB 拒绝、稳定错误码与跨端映射、真实用量口径、权限与跨租户隔离。 |

验收标准：页面权益和上限可追溯到套餐版本与覆盖；已接入用量可与数据库复核；到期读取立即反映失效；未知到期日的历史试用不被错误降级；普通成员和跨租户请求无法读取版本信息。

## 5. 第二期：交易、附加包与结算闭环

### 5.1 功能范围

二期在一期套餐版本与订阅基础上建设商品价格、订单、支付、附加包、周期用量、账单与使用日志。钱包/点数账本仅在产品确认存在真实按量消费场景后启用，不作为套餐页的默认前置能力。

### 5.2 功能设计

1. **商品、价格、席位与附加包**：可售商品关联套餐版本；商品快照保存价格、币种和周期。支持基础套餐、续费、额外席位、资源附加包和功能附加包；权益合并优先级为活动基础订阅 → 活动附加包 → 有效租户特批覆盖。
2. **订单、支付与凭证**：订单保存商品快照、金额、币种、税额、状态、幂等键和关闭时间。支付适配器必须提供创建、验签回调、主动查单、退款和对账契约。人工凭证引用已完成上传的文件 ID，审核通过后才激活订阅。
3. **公开支付回调**：`POST /api/v1/billing/payment-callbacks/{provider}` 直挂公开路由组，不经过 JWT、Tenant、TenantStatus 或 Authorization；处理必须完成验签、订单定位、幂等校验和审计。
4. **周期用量与账单**：业务域以幂等 `usage_events` 记录资源使用，按日、月、年或订阅周期聚合为 `usage_aggregates`。使用日志可按周期、资源键和事件类型筛选。
5. **可选钱包**：启用点数或按量付费时，充值、赠送、扣费、退款和人工调整均写不可变账本；余额只是可重建读模型，金额与点数使用最小单位整数。

### 5.3 数据设计

| 表 | 核心字段 | 用途 |
| --- | --- | --- |
| `billing_products`、`billing_product_prices` | 商品、套餐版本、币种、金额、周期、生效时间 | 可售商品与价格历史。 |
| `billing_orders`、`billing_payments`、`billing_vouchers` | 订单、渠道交易、凭证审核、快照、幂等键 | 购买和支付闭环。 |
| `tenant_subscription_addons` | `subscription_id`、`plan_version_id`、`quantity`、`ends_at` | 席位、资源或功能附加包。 |
| `usage_events`、`usage_aggregates`、`billing_charges` | 事件、周期聚合、收费关联 | 可追溯计量与账单。 |
| `wallets`、`wallet_ledger_entries` | 余额读模型、方向、金额、业务号、余额后值 | 仅启用钱包时创建。 |

### 5.4 接口与授权设计

现有授权器按首资源段与 HTTP 方法推导权限，二期接口必须使用可推导权限名，不使用无法由当前路径生成的 `billing-orders:list`、`usage-logs:list`。

| 接口 | 用途 | 权限 |
| --- | --- | --- |
| `GET /api/v1/editions/current` | 订阅、权益与资源概览 | `editions:get` |
| `GET /api/v1/billing/products` | 可购买商品 | `billing:get` |
| `POST /api/v1/billing/orders` | 创建购买、续费或增购订单 | `billing:create` |
| `GET /api/v1/billing/orders`、`GET /api/v1/billing/orders/{id}` | 查询订单 | `billing:get` |
| `POST /api/v1/billing/orders/{id}/payment`、`/vouchers` | 发起支付、提交凭证 | `billing:create` |
| `POST /api/v1/billing/payment-callbacks/{provider}` | 支付渠道回调 | 公开路由 + 渠道验签 |
| `GET /api/v1/usage/logs` | 使用日志 | `usage:get` |
| `GET /api/v1/wallet/summary`、`GET /api/v1/wallet/ledger` | 钱包信息 | `wallet:get` |
| `GET/POST/PATCH /api/v1/platform/billing/*` | 商品、审核、调账、对账运营面 | 平台运营权限 |

所有创建型用户请求必须支持 `Idempotency-Key`。错误码至少包括 `PRODUCT_NOT_AVAILABLE`、`ORDER_STATE_INVALID`、`PAYMENT_VERIFY_FAILED`、`VOUCHER_REVIEW_REQUIRED`、`WALLET_INSUFFICIENT_BALANCE`、`USAGE_EVENT_DUPLICATED`。

### 5.5 可靠任务、实施与验收

订阅到期、用量聚合、结算、对账和补偿不得使用进程内 goroutine 或 ticker。二期新增持久化任务表，至少包含 `type`、`payload`、`dedupe_key`、`status`、`run_after`、`lease_until`、`attempts`、`last_error`；由独立 worker 以租约抢占执行。业务事务通过 Outbox 写入任务，worker 按幂等键重试。

| 范围 | 工作项 |
| --- | --- |
| 领域与迁移 | 新建 `internal/platform/billing/` 和独立任务执行器；为商品、价格、订单、支付、附加包、计量、账单、任务及可选钱包提供版本化迁移。 |
| 支付与计量 | 实现验签、回调幂等、查单、退款对账、密钥注入和脱敏日志；每个可计费资源先完成事件、幂等、回填与对账。 |
| 前端 | 实现商品选择、订单确认、支付跳转/轮询、凭证提交、订单详情、使用日志及按产品决定是否展示的钱包。 |
| 验证 | 覆盖重复回调、并发订单、到期与续费竞争、事件重放、跨租户隔离、退款、任务租约恢复和账本可重建。 |

验收标准：重复回调不重复激活订阅或记账；任一订单和账单可追溯至套餐版本、订单、资源事件和聚合记录；套餐改价不改变历史快照；无 JWT 的支付回调可安全验签，而其他租户接口仍严格隔离；启用钱包后余额可由账本重建。

## 6. 实施顺序与风险控制

1. 建设一期套餐版本、订阅、权益覆盖和历史租户回填，明确旧 `plan` 的兼容投影。
2. 接入成员、应用、当前存储三个真实计量器，发布租户和平台运营读取接口。
3. 建设到期投影与幂等降级任务，替换前端静态版本页；支付、凭证、钱包入口保持隐藏。
4. 建设二期商品、价格、订单、支付与附加包，以公开回调路由完成验签。
5. 建设持久化任务、用量事件、周期聚合、账单和使用日志；确认按量消费场景后再启用钱包。

- 不把功能可见误认为功能已可用；权益展示与实际请求授权分别验证。
- 不把 `audit_logs` 或登录日志当作计费用量日志。
- 不使用浮点数存金额、点数或余额；统一使用最小单位整数。
- 不依赖前端倒计时、静态常量或页面状态决定订阅有效性。
- 二期之前不开放“支付成功”“已充值”“凭证通过”等不可逆提示。
