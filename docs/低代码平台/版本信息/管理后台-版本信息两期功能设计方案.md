# 管理后台「版本信息」两期功能设计方案

## 1. 文档目的

本文定义租户管理后台「版本信息」的两期建设范围、功能规则、数据边界与接口契约。目标是先让管理员看到**真实、可追溯的当前版本与资源用量**，再建设订阅、支付和云币等商业化闭环。

本文只覆盖当前租户的管理后台；平台运营人员配置套餐、人工授予试用等能力仅作为配套管理面描述。它不包含表单、流程、数据工厂、AI 等尚未落地领域本身的业务实现。

## 2. 现状与设计原则

### 2.1 现有基础

后端已存在以下可复用能力：

- `tenants.plan`：`free`、`trial`、`pro` 三个套餐代码；
- `tenants.quotas`：租户对套餐默认配额的覆盖值；
- `apps`、`members`、`storage_gb` 的计量或拦截基础；
- `GET /api/v1/auth/userinfo`：可返回当前租户、套餐与五项生效配额。

但尚无套餐有效期、套餐权益、用量概览、订单、支付、云币、计费流水或凭证模型。当前页面的版本名称、到期日、云币余额、容量卡片和权益清单均不得作为真实业务数据。

### 2.2 设计原则

1. **真实优先**：没有可靠计量来源的指标不展示伪造数值；页面明确标注“暂未启用统计”或不展示该卡片。
2. **套餐与用量分离**：套餐决定“允许多少”，计量服务决定“已使用多少”；二者不可互相推算。
3. **一期不引入支付**：一期可以由平台运营人工授予或调整版本，但任何“充值”“支付”“上传凭证”都不能伪装为已完成交易。
4. **计费事件不可覆盖**：二期的扣费、充值、退款均以不可变流水记账，余额只是可重建的汇总结果。
5. **租户隔离与权限前置**：所有租户侧接口均进入 Authentication → Tenant → TenantStatus → Authorization 链；平台侧配置接口只进入平台运营链。
6. **兼容现有配额执行**：一期不改变已上线的 `tenants.plan`、`tenants.quotas` 与 `QuotaService` 的生效语义，避免版本页面上线影响创建应用、添加成员和上传文件。

## 3. 总体分期

| 阶段 | 名称 | 面向用户的结果 | 不包含的内容 |
| --- | --- | --- | --- |
| 第一期 | 版本与资源概览 | 管理员看到真实套餐、有效期、已接入资源用量和权益状态；运营可人工调整版本 | 在线支付、云币、超额扣费、发票、复杂附加包 |
| 第二期 | 订阅与计费闭环 | 用户可购买/续费，查看订单、支付和云币流水；系统按可审计计量完成结算 | 尚未建设的业务资源本身，例如数据工厂或 AI 的实际执行服务 |

## 4. 第一期：版本与资源概览

### 4.1 目标与范围

一期将静态「版本信息」页替换为真实只读概览，并补齐试用期生命周期。页面只显示已具备可靠数据来源的资源：成员、应用和附件存储容量；表单数与月度流程发起量作为“已定义、待计量”的预留项，不显示虚假的已用数量。

一期的套餐配置仍使用代码内受版本控制的目录，套餐代码与现有 `free`、`trial`、`pro` 保持一致。这样可以在不改写现有配额校验的前提下上线页面；套餐价格、周期和可售性留给二期的数据化商品目录处理。

### 4.2 用户与权限

| 用户 | 可执行操作 |
| --- | --- |
| 租户管理员 / 租户所有者 | 查看当前版本、有效期、资源用量、权益和升级咨询入口。 |
| 普通成员 | 不显示管理后台版本信息菜单；直接访问时返回 `FORBIDDEN`。 |
| 平台运营管理员 | 查看租户版本信息；人工开通试用、调整套餐、延长或终止试用。 |

新增租户侧资源权限 `editions:get`，仅授予租户基线管理员角色。接口采用 `GET /api/v1/editions/current`，使现有“首资源段 + HTTP 方法”的授权推导可以得到 `editions:get`，无需改变授权器。

### 4.3 功能清单

#### 4.3.1 当前版本卡片

- 展示套餐名称、状态、开始时间、到期时间和到期后的处理规则。
- `trial` 显示试用倒计时；到期前 7 天、3 天、1 天分别产生站内提醒事件（消息中心未落地前只记录待投递事件，不展示伪消息）。
- 试用到期后，由定时任务将租户套餐从 `trial` 原子降为 `free`，保留原配额覆盖记录并写入审计日志。
- `free` 不显示到期日；`pro` 在一期只支持运营手工设定到期日或“长期有效”，不开放用户购买。
- “咨询升级”跳转到可配置的联系入口；未配置时说明“请联系平台管理员”，不得制造成功提交记录。

#### 4.3.2 系统容量卡片

统一字段为：资源键、显示名称、计量单位、生效上限、已用值、使用率、统计时间、重置周期和统计状态。

| 资源键 | 一期状态 | 口径 | 页面行为 |
| --- | --- | --- | --- |
| `members` | 已接入 | 当前租户中状态为 `active` 或 `disabled` 且未软删的成员数 | 显示已用/上限和进度条。 |
| `apps` | 已接入 | 当前租户未软删的应用数 | 显示已用/上限和进度条。 |
| `storage_gb` | 已接入 | `uploading` 按声明大小预留、`ready` 按实际大小累加；单位为字节后换算展示 | 显示“附件存储容量”，不是“年度上传量”。 |
| `forms` | 预留 | 尚无表单资产模型和计数器 | 显示套餐上限与“暂未启用统计”，不显示已用值或百分比。 |
| `workflow_runs_month` | 预留 | 尚无流程执行事件 | 显示套餐上限与“暂未启用统计”，不显示已用值或百分比。 |

约定：`-1` 展示为“不限量”，`0` 展示为“不可用”，正数为上限；计算使用率时，不限量和暂未计量均不返回百分比。使用率达到 80% 显示提示，达到 100% 显示超限状态；提示不替代写路径中的配额校验。

#### 4.3.3 版本权益

- 返回套餐对应的权益组、权益名称、是否可用、可选数值上限和状态说明。
- 一期权益目录只列出后端已实际可用、可稳定授权的能力；尚未落地的表单、AI、数据工厂等不得标记为“可用”。
- 权益仅用于展示与前端入口裁剪，**不替代**现有 RBAC。真正的请求授权仍由权限规则、租户状态和业务服务共同决定。
- 未包含在当前套餐中的权益显示为“当前版本不可用”，点击后进入咨询升级入口；一期不创建订单。

#### 4.3.4 详情与刷新

- 容量卡片可打开详情弹窗，展示计量口径、上限来源（套餐默认 / 租户覆盖）、统计时间和状态。
- 页面进入时请求一次；用户手动刷新可再次请求。避免每秒轮询数据库计数。
- 接口响应中的 `asOf` 表示统计快照生成时间。成员、应用、存储一期可以实时聚合，`asOf` 即响应生成时间。

### 4.4 数据设计

#### 4.4.1 保留的既有数据

`tenants.plan` 仍是当前套餐代码的唯一事实来源，`tenants.quotas` 仍是生效配额覆盖的唯一事实来源。现有 `DefaultQuotas` 和 `QuotaService` 不在一期迁移至新表。

#### 4.4.2 新增 `tenant_edition_periods`

该表只补齐“当前套餐的生效周期”，不复制套餐代码或配额，避免双写事实源。

| 列 | 类型 / 约束 | 说明 |
| --- | --- | --- |
| `id` | `BIGSERIAL PK` | 记录主键。 |
| `tenant_id` | `BIGINT NOT NULL` | 租户归属；同一租户同一时刻最多一条 `active` 记录。 |
| `plan_code` | `VARCHAR(32) NOT NULL` | 周期开始时的套餐快照，用于历史审计；必须等于当时的 `tenants.plan`。 |
| `status` | `VARCHAR(16) NOT NULL` | `active` / `expired` / `replaced` / `cancelled`。 |
| `source` | `VARCHAR(16) NOT NULL` | `system` / `manual` / `trial`。 |
| `starts_at` | `TIMESTAMPTZ NOT NULL` | 生效时间。 |
| `ends_at` | `TIMESTAMPTZ NULL` | 空表示长期有效；试用必须非空。 |
| `operator_account_id` | `BIGINT NULL` | 平台人工操作的账号；系统操作为空。 |
| `remark` | `VARCHAR(512) NOT NULL DEFAULT ''` | 运营备注，不对租户普通成员泄露。 |
| `created_at`、`updated_at` | 时间 | 审计时间。 |

索引和约束：

- `tenant_id, status, starts_at DESC` 查询索引；
- 部分唯一索引保证每个租户最多一条 `status = 'active'`；
- `ends_at IS NULL OR ends_at > starts_at`；
- 迁移中为现有租户回填活动周期：`trial` 没有历史到期信息时，以“长期有效、待运营补录”标记，不能凭空推断到期日。

#### 4.4.3 套餐目录与权益目录（代码配置）

在 `internal/platform/tenant/model/plan.go` 扩展只读目录结构，除现有默认配额外增加：套餐展示名、描述、到期降级规则和权益列表。目录的套餐代码必须与 `IsValidPlan` 保持一一对应。

一期目录变动必须经代码评审、测试和发布；不得提供租户侧写接口。二期建立商品目录后再迁移为数据库配置。

### 4.5 接口设计

#### 4.5.1 租户管理后台读取

```text
GET /api/v1/editions/current
Authorization: Bearer <JWT>
权限：editions:get
```

响应 `data`：

```json
{
  "subscription": {
    "planCode": "trial",
    "planName": "试用版",
    "status": "active",
    "startsAt": "2026-08-01 00:00:00",
    "endsAt": "2026-08-28 23:59:59",
    "expiresAction": "downgrade_to_free"
  },
  "quotas": [
    {
      "key": "members",
      "name": "可用人数",
      "unit": "person",
      "limit": 30,
      "usage": 1,
      "usagePercent": 3.33,
      "meteringStatus": "ready",
      "limitSource": "plan_default",
      "asOf": "2026-08-26 10:00:00"
    },
    {
      "key": "forms",
      "name": "表单数",
      "unit": "count",
      "limit": 50,
      "meteringStatus": "pending"
    }
  ],
  "features": [
    {
      "group": "基础管理",
      "key": "application_management",
      "name": "应用管理",
      "available": true
    }
  ],
  "asOf": "2026-08-26 10:00:00"
}
```

`usage`、`usagePercent` 和 `asOf` 在 `meteringStatus = pending` 时省略；服务端不返回 `null` 与伪零值混淆真实“使用 0”。

#### 4.5.2 平台运营人工授予

```text
PUT /api/v1/platform/tenants/{id}/edition
```

请求字段：`planCode`、`startsAt`、`endsAt`、`source`、`remark`。操作在同一事务内完成：关闭旧活动周期 → 更新 `tenants.plan` → 按需更新 `tenants.quotas` → 创建新活动周期。完成后记录 `audit_logs`。

约束：

- `trial` 必须提供 `endsAt`；
- `free` 不允许传 `endsAt`；
- 手工 `pro` 可传空 `endsAt` 表示长期有效；
- 不允许通过该接口修改已过期的历史记录；
- 更新套餐不会自动删除现有资源；资源超过新上限时页面显示超限，新增操作由已有配额校验拒绝。

#### 4.5.3 内部计量契约

新增 `EditionUsageReader`，以稳定资源键获取当前租户的用量。成员、应用、存储分别复用已有仓储计数，不在控制器中写 SQL。表单与流程计量器在其领域落地后注册；未注册即返回 `pending`。

### 4.6 后端与前端实施工作

| 范围 | 工作项 |
| --- | --- |
| 数据库 | 新增 `tenant_edition_periods` 的 up/down 迁移、中文 SQL 注释、索引、历史租户回填，并同步 `scripts/db.sql`。 |
| 后端领域 | 在 `internal/platform/edition/` 建立 controller → service → repository 与接口契约；实现周期查询、实时用量聚合、权益目录投影、人工授予和过期任务。 |
| 配额复用 | 将成员、应用、存储的读计量封装为 `EditionUsageReader`；不改变现有创建/上传拦截语义。 |
| 安全与审计 | 注册 `editions:get` 资源和租户管理员基线权限；人工授予、到期降级均在提交后写审计。 |
| API | 编写中文 Swagger 注释、稳定错误码（如 `EDITION_PERIOD_INVALID`、`EDITION_NOT_FOUND`），并同步前端错误码。 |
| 前端 | 新建 `api/edition.ts`，在进入页面时加载真实概览；移除所有静态版本、余额、容量和权益常量；按 `meteringStatus` 渲染待计量状态。 |
| 交互 | 咨询入口由公开配置控制；充值、支付、凭证和云币入口在一期隐藏，不保留只弹成功提示的按钮。 |
| 验证 | 覆盖套餐覆盖优先级、到期降级、并发授予、成员/应用/存储口径、权限隔离和跨租户访问；前端完成 typecheck、build。 |

### 4.7 第一期验收标准

- 同一租户在页面与 `GET /editions/current` 中看到的套餐和上限一致。
- 成员、应用、存储用量均可与对应数据库计数复核；没有指标以样例数值展示。
- 试用到期只执行一次降级，重复运行任务不会重复创建活动周期或审计记录。
- 普通成员、无租户会话和跨租户请求均不能读取版本信息。
- 一期页面不存在云币余额、支付成功、凭证已上传等无后端事实支撑的提示。

## 5. 第二期：订阅与计费闭环

### 5.1 目标与范围

二期将套餐从代码目录迁移为可运营的商品目录，并建立订阅、订单、支付、云币、用量事件、结算和凭证闭环。二期支持用户自助购买、续费与查看账务，但任何外部支付渠道必须在签名验签、幂等和对账完成后才可上线。

### 5.2 功能清单

#### 5.2.1 商品、价格与套餐权益

- 平台运营人员维护商品、套餐版本、计费周期、价格、可售状态、配额规则和权益规则。
- 已售出的订阅关联不可变“套餐版本快照”；后续调价或改权益不回写历史订单。
- 支持基础套餐、续费包和资源附加包；附加包通过权益合并增加配额或能力，不直接篡改原套餐定义。
- 试用资格规则（一次性、指定渠道、有效期）由服务端计算，不由前端决定。

#### 5.2.2 订阅生命周期

- 支持 `pending`、`active`、`grace`、`expired`、`cancelled` 状态。
- 支付成功后创建或续展活动订阅；支付失败、订单关闭不改变当前有效订阅。
- 到期后进入宽限期或降级，规则以套餐版本快照为准；不得直接删除租户资源。
- 租户当前权益由“活动基础订阅 + 活动附加包 + 租户特批覆盖”合并计算，并作为配额与功能裁剪唯一读取入口。

#### 5.2.3 订单、支付与凭证

- 订单包含商品快照、金额、币种、税额、支付状态、幂等业务号和关闭时间。
- 支付适配器对接前必须定义创建支付、回调验签、主动查询和退款四个契约；回调只接受渠道签名验证后的结果。
- 每次回调以“渠道 + 交易号”幂等处理；订单状态迁移必须带版本或条件更新，防止重复通知。
- 人工转账凭证作为订单附件提交，进入 `pending_review`；运营审核通过后才可激活订阅。文件仅引用已完成上传的文件 ID，不能直接信任 URL。

#### 5.2.4 云币钱包与消费

- 一个租户一个钱包，展示可用余额、冻结余额和最近流水。
- 充值、赠送、扣费、退款、人工调整全部生成不可变账本分录；不允许直接更新余额字段。
- 高价值扣费先冻结再结算；失败或取消必须释放冻结金额。
- 资源超额后的扣费规则由套餐版本定义；没有有效价格规则时，资源应拒绝新增或明确允许免费，不得“默认扣费”。

#### 5.2.5 计量、结算与使用日志

- 各业务域以幂等事件写入 `usage_events`：事件 ID、租户、资源键、数量、发生时间、来源对象与幂等键。
- 聚合任务按日/月/订阅周期写入 `usage_aggregates`，页面读取聚合结果；需要强一致拦截的创建路径仍使用事务内实时计数或预留。
- “使用日志”展示可解释的资源事件和账务影响，默认脱敏对象信息，并支持按周期、资源键、事件类型筛选。
- 一期未计量的 forms、workflow、数据记录、AI 调用等，只有在所属领域可产生幂等事件后才可加入商品计费。

### 5.3 数据设计

| 表 | 核心字段 | 用途 |
| --- | --- | --- |
| `billing_products` | `code`、`name`、`kind`、`status` | 可售商品目录。 |
| `billing_plan_versions` | `product_id`、`version`、`billing_cycle`、`snapshot`、`published_at` | 不可变套餐、价格和权益快照。 |
| `billing_subscriptions` | `tenant_id`、`plan_version_id`、`status`、`starts_at`、`ends_at`、`grace_ends_at` | 租户订阅生命周期。 |
| `billing_subscription_addons` | `subscription_id`、`plan_version_id`、`quantity`、`ends_at` | 资源附加包。 |
| `billing_orders` | `order_no`、`tenant_id`、`amount`、`currency`、`status`、`snapshot`、`idempotency_key` | 购买意图和结算状态。 |
| `billing_payments` | `order_id`、`provider`、`provider_trade_no`、`status`、`paid_at`、`raw_payload_digest` | 支付渠道交易记录。 |
| `billing_vouchers` | `order_id`、`file_id`、`status`、`reviewer_account_id` | 人工凭证审核。 |
| `wallets` | `tenant_id`、`available_balance`、`frozen_balance`、`version` | 钱包读模型与并发控制。 |
| `wallet_ledger_entries` | `wallet_id`、`direction`、`amount`、`type`、`business_id`、`balance_after` | 不可变资金账本。 |
| `usage_events` | `event_id`、`tenant_id`、`resource_key`、`quantity`、`occurred_at`、`idempotency_key` | 原始可追溯计量事件。 |
| `usage_aggregates` | `tenant_id`、`resource_key`、`period_start`、`period_end`、`quantity` | 页面与结算的周期读模型。 |
| `billing_charges` | `tenant_id`、`usage_aggregate_id`、`amount`、`status`、`ledger_entry_id` | 用量到扣费的连接记录。 |

一期的 `tenant_edition_periods` 迁移为订阅历史的只读来源：历史记录导入 `billing_subscriptions` 后保留表和数据一段兼容期；切换完成后，当前套餐与有效期只从活动订阅推导，并在一个 ADR 中明确废除 `tenants.plan` 的写入职责。

### 5.6 第二期验收标准

- 相同支付回调重复投递不会重复激活订阅、充值或扣费。
- 任一钱包余额都能由账本流水重建，并与读模型一致。
- 任一账单扣费都能追溯到订阅快照、资源事件、聚合记录和账本分录。
- 套餐改价或权益调整不改变已成交订单和存量订阅快照。
- 用户只可访问本租户订单、钱包和使用日志；平台人工调账、凭证审核均有审计记录。

## 6. 实施顺序与里程碑

1. 完成一期数据迁移、套餐目录、周期管理和到期任务。
2. 接入成员、应用、存储三个真实计量器，发布 `GET /editions/current`。
3. 替换前端静态版本页并完成一期验收；支付与云币入口保持隐藏。
4. 完成二期商品目录与订阅模型，将一期周期历史迁移为订阅。
5. 建设订单、支付、凭证、钱包和账本，再接入事件计量与聚合。
6. 最后开放自助购买和超额计费；每新增可计费资源均需先完成事件口径、幂等和对账验证。

## 7. 非目标与风险控制

- 不把“功能展示可见”误认为“功能已可用”；权益展示与实际请求授权必须分别验证。
- 不把历史 `audit_logs` 或登录日志当作计费用量日志；它们的保留期、字段和审计目的不同。
- 不允许用浮点数存金额或云币；金额和余额统一使用最小货币单位的整数，展示层再格式化。
- 不允许依赖前端倒计时决定到期；所有状态变更以服务端时钟、定时任务和事务状态为准。
- 不在二期之前开放“支付成功”“已充值”“凭证通过”等不可逆业务提示。
