# M1 任务清单：账号×成员拆分与租户体系补齐

> 对标简道云 `get_login_user` 响应的差距分析结论落地（2026-08-18 定）。
> 进度跟踪文件：完成后勾选对应项；本文档随任务推进同步更新，重大变更回链架构设计文档。

## 决策背景

对标简道云登录响应的分析结论：租户/成员/角色/配额骨架方向同源，主要差距为
租户配置、套餐配额模型、部门树，以及账号与租户的关系模型。已拍板两项决策：

1. **拆分平台账号与租户成员**（架构级变更，落 ADR-006）：简道云为「平台账号 ×
   多企业成员」（一个手机号可属多家企业，登录后选企业）；原 26.4「首期租户内
   封闭」表述由本决策取代。
2. **本批范围：后端全链路 + 文档**；前端页面待 `apps/evolyn-web/apps/web/`
   TS 脚手架稳定后另批落地。
3. **后端工程结构对齐**（架构文档第 5 章定版结构的落地，随 M1 同批做，落
   ADR-007）：从技术三层（controller/service/repository 全局共享）改为域模块化
   单体（platform/iam/tenant 域内小三层）；**解散顶层 `pkg/`，全部收进
   `internal/`**（单模块私有仓库无可复用层需求，且现存 pkg 反向依赖
   internal/model）。

前置状态（已入库）：租户 P0 地基（`8c82062`）、ctx 线程化使租户隔离生效
（`f5f44bf`）。

## 任务清单

### P0 工程结构对齐（先于模型改造，一次迁移到位）

目标结构（第 5 章定版 + 现状收敛）：`internal/platform/{server,middleware,auth,iam,tenant}`
+ `internal/infrastructure`；`engine/` 目录留给 M2 随引擎逐个建，不预建空包。

- [x] **P0-1 目录骨架迁移**：建 `internal/platform/`（server/middleware 从原
      internal/ 迁入）与 `internal/infrastructure`（原 internal/database 迁入，
      含租户 Callback）；`cmd/api` 装配路径同步。
- [x] **P0-2 iam 域收敛**：user/group/rbac 的 controller+service+repository+model
      从全局三层迁入 `internal/platform/iam`（域内保留 controller→service→
      repository 小三层），repository 巨型聚合接口按域拆分。
- [x] **P0-3 解散 pkg**：`pkg/authentication` → `internal/platform/auth`；
      `pkg/common` 按职责拆（context 助手归 platform/middleware、response 归
      platform）；`pkg/utils` → `internal/utils`；`pkg/version` → `internal/version`
      并同步 Makefile ldflags 注入路径；全量 import 路径更新，消除 pkg→internal
      反向依赖。
- [x] **P0-4 拆除 authorization 全局单例**：`var store` 包变量改为显式依赖注入，
      为 M1 后 Casbin 接入（P1-7 原计划）铺路。

### P1 模型与迁移

- [ ] **P1-1 Account 平台账号模型**：`model/account.go`，新表 `accounts`（平台级、
      无 TenantID，配 AccountBase 时间三件套）：Name（全局唯一登录名）、Nickname、
      Phone（全局唯一可空）、Email、Password、Avatar、AuthInfos（AuthInfo 归属从
      user 改挂账号，加 `AccountId` 字段）。
- [ ] **P1-2 User 语义改为租户成员**：保留 `users` 表名，字段收敛为 AccountId、
      Nickname（租户内展示名）、Groups/Roles/Departments 关联与 BaseModel；移除
      Name/Password/Email/Avatar/AuthInfos 字段声明（AutoMigrate 不删存量列，残留
      无害；db.sql 面向新库更新）。
- [ ] **P1-3 Tenant 扩展与套餐模型**：`OwnerAccountId`（开通者账号，is_owner 语义
      锚点）、`Config` JSONB（水印/主题/时区/语言，沿用 rbac.go Rules 的
      Scan/Value 模式）、`Quotas` JSONB（键值配额覆盖，空则用套餐默认）；新增
      `model/plan.go`：套餐常量 free/trial/pro + 默认配额 map（apps/forms/members/
      storage_gb/workflow_runs_monthly，-1 不限，键值可扩展对齐简道云 pack 形态）。
- [ ] **P1-4 Department 部门树**：`model/department.go`：ParentId/Name/Order/Status
      + BaseModel 邻接表；`User.Departments` m2m `department_users`（多部门，对齐
      简道云 member.dept 数组）。
- [ ] **P1-5 存量回填与 db.sql 同步**：`repository.Init()` 幂等 seed（沿用
      SeedDefaultTenant 模式）：accounts 按 users 同 ID 复制 → `users.account_id`
      回填 → `auth_infos.account_id` 回填 → 默认租户 owner 指向 admin 成员账号；
      `scripts/db.sql` 新表与种子同步（两口径保持一致）。

### P2 认证与租户上下文

- [ ] **P2-1 JWT claims 改造**：claims 改为 `{accountId, memberId, tenantId, name}`，
      `pkg/authentication/jwt.go` CreateToken/ParseToken 改造，`jwt_test` 更新。
- [ ] **P2-2 登录链路**：`/auth/token` 账号名/手机号+密码 → 全局查账号校验 → 取
      默认成员（第一个成员关系，可用 tenantCode 指定）→ 签发；注册 `/auth/user`
      创建账号 + 默认租户成员；OAuth 首登创建账号 + 默认租户成员。
- [ ] **P2-3 租户选择与切换**：新增 `GET /auth/tenants`（账号的成员关系列表：
      租户 id/name/is_owner，对齐简道云 owned_tenant_list）与
      `POST /auth/token/switch`（切换租户重签 token）。
- [ ] **P2-4 中间件适配**：AuthenticationMiddleware 按 claims 的 memberId+tenantId
      加载成员（预载 groups/roles）→ SetUser；TenantMiddleware/
      AuthorizationMiddleware/租户 Callback 链路不动。
- [ ] **P2-5 登录聚合接口**：`GET /auth/userinfo`，对齐简道云 get_login_user
      形态：一次返回账号资料 + 当前租户（config/套餐配额）+ 成员身份
      （is_admin/is_owner/部门），作为前端启动引导的单请求（来源：登录页 API
      集合差距分析，见 `docs/接口API参考/登录页/API集合.md`）。
- [ ] **P2-6 权限布尔集**：`GET /auth/permissions`，按 Role.Rules 推导当前成员
      的权限开关（resource → verb 布尔集），供前端菜单/按钮级控制使用。

## 风险与对策

- 存量迁移用**同 ID 复制**策略，幂等可重跑；旧列/旧索引（如 users.name 全局
  唯一）AutoMigrate 不删，代码不再声明即无业务影响，新库由 db.sql 保证干净。
- P0 结构对齐涉及全量 import 路径变更（含 Makefile ldflags）；与 M1 模型改造
  同批推进，每步 build/test 保持绿，避免纯搬家的二次回归成本。
- 工作量约 30+ 文件，按 P0→P5 顺序推进，每个 Phase 结束跑一次 build/test 保持
  可提交状态。
