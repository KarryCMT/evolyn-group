# 企业级低代码平台技术架构设计

> 当前架构版本：**不包含 AI / Eino**\
> 核心技术路线：**Vue3 + Element Plus + VisActor + LogicFlow + Go/Gin +
> PostgreSQL + Redis + RustFS + Java/Flowable**

------------------------------------------------------------------------

## 1. 架构定位

平台定位为企业级低代码开发平台，核心覆盖：

-   应用设计
-   动态表单
-   页面设计
-   数据管理
-   工作流审批
-   仪表盘与数据分析
-   数据权限
-   公式计算
-   关联数据
-   自动化
-   JSONB 动态数据
-   PostgreSQL 物理表
-   开放 API

整体采用：

``` text
前端设计态 / 运行态
        ↓
Vue3 + TypeScript + Element Plus
        ↓
Go + Gin 平台核心
        ↓
Schema / Query / Permission / Relation / Formula / Dashboard
        ↓
GORM + pgx
        ↓
PostgreSQL
        ↓
Redis + RustFS

流程体系独立：
Java + Spring Boot + Flowable
        ↓
PostgreSQL Workflow DB
```

核心设计思想：

> **Schema → Engine → DSL → AST → Planner → Compiler → Runtime**

避免把业务能力硬编码在页面、Controller 或具体数据库结构中。

## 8. JSONB 动态数据模式

适合：

-   OA
-   审批
-   问卷
-   行政
-   人事
-   轻量 CRM
-   快速变化的业务表单

示例：

``` sql
CREATE TABLE form_record (
    id UUID PRIMARY KEY,
    tenant_id UUID NOT NULL,
    app_id UUID NOT NULL,
    form_id UUID NOT NULL,
    data JSONB NOT NULL,
    creator_id UUID,
    owner_id UUID,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

业务数据：

``` json
{
  "field_a81": "客户A",
  "field_b92": 120000,
  "field_c82": "华东"
}
```

特点：

``` text
新增字段
   ↓
更新 Schema
   ↓
通常无需 ALTER TABLE
```

高频字段可以通过：

-   GIN Index
-   Expression Index
-   Partial Index

进行优化。

## 9. Physical Table 物理表模式

适合：

-   MES
-   ERP
-   WMS
-   BOM
-   采购
-   库存
-   订单
-   生产
-   设备
-   大数据量核心业务

例如：

``` sql
CREATE TABLE app_x82_order (
    id UUID PRIMARY KEY,
    tenant_id UUID NOT NULL,
    f_a812 VARCHAR(200),
    f_b923 NUMERIC(18,2),
    f_c723 VARCHAR(32),
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

优势：

``` text
标准 SQL
JOIN
INDEX
GROUP BY
ORDER BY
复杂聚合
大数据量分页
外部系统集成
```

用户字段名称与数据库列名必须解耦：

``` text
field_id         = field_01J82
field_name       = 合同金额
physical_column  = f_01j82
```

即使：

``` text
合同金额
 ↓
订单金额
 ↓
含税订单金额
```

数据库列仍保持：

``` text
f_01j82
```


## 11. Query Engine

Query Engine 是 Data Engine 的核心。

前端禁止直接传递 SQL。

统一使用 Query DSL：

``` json
{
  "filter": {
    "logic": "and",
    "conditions": [
      {
        "field": "field_amount",
        "operator": "gt",
        "value": 10000
      }
    ]
  },
  "sort": [
    {
      "field": "created_at",
      "direction": "desc"
    }
  ]
}
```

执行链：

``` text
Query DSL
    ↓
Parser
    ↓
AST
    ↓
Schema Validation
    ↓
Permission Injection
    ↓
Relation Planner
    ↓
Query Planner
    ↓
Storage Resolver
    ↓
PostgreSQL Compiler
    ↓
pgx
    ↓
PostgreSQL
```

JSONB：

``` sql
(data->>'field_amount')::numeric > $1
```

Physical：

``` sql
f_0182 > $1
```

前端及上层业务无需感知底层存储方式。

## 12. DDL / Schema Migration Engine

物理表模式必须拥有独立的 Schema Migration Engine。

禁止：

``` text
HTTP Request
   ↓
Controller
   ↓
直接 ALTER TABLE
```

推荐：

``` text
Designer
   ↓
Save Draft
   ↓
Schema Version
   ↓
Schema Diff
   ↓
Migration Plan
   ↓
DDL Task
   ↓
DDL Executor
   ↓
PostgreSQL
   ↓
Publish Schema
```

支持：

``` text
ADD_COLUMN
ALTER_COLUMN
CREATE_INDEX
DROP_INDEX
SOFT_DELETE_COLUMN
UPDATE_METADATA
```

字段删除默认采用软删除：

``` text
用户删除字段
   ↓
Schema 标记 Deleted
   ↓
新版本不再展示
   ↓
物理列暂时保留
   ↓
延迟清理 / 人工确认
   ↓
DROP COLUMN
```

后续应支持：

-   Schema Version
-   发布
-   回滚
-   DDL 审计
-   异步执行
-   失败重试
-   大表变更
-   Migration 状态管理

## 23. 核心架构原则

### 23.1 前端不感知底层存储

``` text
Vue3
 ↓
Query DSL
 ↓
Query Engine
 ↓
Storage Resolver
 ├── JSONB
 └── Physical Table
```

### 23.2 Schema 是平台核心协议

``` text
Designer
   ↓
Schema
   ↓
Engine
   ↓
Runtime
```

### 23.3 动态 SQL 必须经过 Query Engine

``` text
DSL
 ↓
AST
 ↓
Validation
 ↓
Permission
 ↓
Planner
 ↓
Compiler
 ↓
pgx
```

禁止前端提交任意 SQL。

### 23.4 DDL 必须经过 Migration Engine

``` text
Schema Diff
 ↓
Migration Plan
 ↓
DDL Task
 ↓
Executor
```

不能把 DDL 散落在业务 Service 中。

### 23.5 设计态与运行态分离

``` text
Designer Component
≠
Runtime Component
```

### 23.6 先模块化单体，再按压力拆服务

第一阶段优先保证：

``` text
研发效率
事务简单
调试方便
部署简单
模块边界清晰
```

而不是追求微服务数量。

> 作为平台后端主体；GORM 管理固定平台模型，pgx 承担动态 DDL/DML、Query
> Engine 与 Aggregation；PostgreSQL 统一承载平台元数据、JSONB 动态数据与
> Physical Table 重业务数据；Redis 提供缓存和分布式基础能力；RustFS
> 提供对象存储；Java + Spring Boot + Flowable 独立承担 BPM 工作流。**
