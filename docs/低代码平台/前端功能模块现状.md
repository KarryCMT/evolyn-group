# 前端功能模块现状

> 盘点基线：2026-08-23 当前工作区代码。范围为 `apps/evolyn-web/apps/web/src` 及其直接使用的 `packages/{dashboard,form,workflow,data}`。本文以“页面已实现”为准，不把仅存在于后端或仅有 API 封装的能力误记为已完成对接。

## 1. 状态口径

| 标记 | 含义 |
| --- | --- |
| ✅ 已完成对接 | 前端页面会调用对应后端接口，并消费真实响应或提交真实请求。 |
| 🟡 部分对接 | 该模块同时包含已接入的子功能和本地样例、占位或未接入的子功能。 |
| ⚪ 静态实现 / 未对接 | 页面、组件或交互已实现，但数据仅来自常量、内存状态或 `localStorage`，或操作只提示“后续提供”。 |
| ⛔ 未实现 | 路由入口、页面主体或业务交互尚未落地。 |

“静态实现”不表示不可用：它代表视觉和局部交互可以验收，但不能作为租户内真实业务数据或权限的最终实现。

## 3. 已完成对接的功能明细

### 3.1 认证与会话

| 页面 / 入口 | 已调用接口 | 说明 |
| --- | --- | --- |
| 登录页：密码登录 | `POST /auth/token` | 密码先经 `GET /app/conf` 下发的 RSA 公钥加密；成功后保存 JWT 并拉取登录聚合信息。 |
| 登录页：短信登录 | `POST /auth/sms/send`、`POST /auth/token` | 验证码场景为 `login`，支持“下次自动登录”。 |
| 注册向导 | `POST /auth/sms/send`、`POST /auth/register` | 三步采集在最终提交时一次性注册账号并开通租户。 |
| 找回密码 | `POST /auth/sms/send`、`POST /auth/password/reset` | 新密码同样使用 RSA 加密。 |
| 多租户选择 / 切换 | `GET /auth/tenants`、`POST /auth/token/switch` | 切换后替换令牌并刷新账号、成员、租户聚合信息。 |
| 退出登录与会话初始化 | `DELETE /auth/token`、`GET /auth/userinfo` | 无论登出接口结果如何均清理本地令牌。 |

前端入口位于 `pages/auth/`、`components/auth/`、`stores/auth.ts` 和 `api/auth.ts`。

### 3.2 个人设置

| 页面 / 入口 | 已调用接口 | 说明 |
| --- | --- | --- |
| 个人资料编辑 | `PUT /accounts/me` | 保存后刷新 `auth` store 中的登录聚合信息。 |
| 修改密码 | `PUT /accounts/me/password` | 支持免密注册账号首次设置密码；成功后主动清会话并回登录页。 |
| 登录日志 | `GET /accounts/me/login-logs` | 支持日期筛选、分页，并使用 VTable 渲染。 |

实现入口为 `pages/dashboard/account.vue`、`composables/useAccountSettings.ts`、`components/dashboard/account/LoginLogDrawer.vue` 和 `api/account.ts`。

### 3.3 应用最小闭环

| 页面 / 入口 | 已调用接口 | 说明 |
| --- | --- | --- |
| 工作台“我的应用” | `GET /applications` | 支持名称前端过滤、加载状态与无权限时的空列表降级。 |
| 创建空白应用 | `POST /applications` | 提交名称和图标；已对 `QUOTA_EXCEEDED` 做专门提示。 |
| 应用首页 | `GET /applications/code/:code` | 使用公开 `appCode` 读取名称、图标、运行时能力，并处理不存在与加载失败。 |

实现入口为 `components/dashboard/widgets/AppsWidget.vue`、`pages/app/index.vue`、`composables/useApplicationHome.ts` 和 `api/applications.ts`。

`api/applications.ts` 还已封装更新和软删除接口（`PATCH`、`DELETE /applications/:id`），但当前没有页面操作入口，因此不计为前端功能完成。

## 4. 静态页面与未对接明细

### 4.1 工作台、收藏与消息

- 默认工作台由 `dashboard/defaultWorkbench.ts` 提供；问候、待办、图表、快捷入口等卡片是展示模型，不对应后端业务数据。
- 自定义工作台通过 `useDashboardWorkspace.ts` 把编排结果写入 `localStorage` 的 `evolyn.dashboard.workspace`。拖拽和保存交互可用，但无法跨浏览器、账号或租户同步。
- 收藏应用使用 `favoriteCatalog.ts` 的固定目录与模块级内存状态；刷新后重置，且不与真实应用列表关联。
- 消息中心使用 `messageCenter.constants.ts` 的初始消息和偏好，标记已读、修改偏好、增删收件人都只改当前页面内存。

### 4.2 应用运行时与菜单

- `pages/app/index.vue` 已真实读取应用详情，但 `workspace=form` 分支仍消费 `applicationWorkspacePreview.ts` 的“项目档案 / 项目进度看板 / 计划管理”样例资产。
- 侧栏的资产搜索、我的待办、我发起的、我处理的、抄送我的和我的仪表盘尚未绑定路由或数据源。
- 当前工作区后端已经存在 `GET /applications/code/:code/menu` 的菜单读取控制器，但 Web 端尚未定义菜单类型、API 封装或调用；因此菜单接口不能视为已完成前后端对接。
- 应用后台的全部子路由通过 `pages/app/setting-feature.vue` 复用说明壳渲染，尚未实现实际设置表单或请求。

### 4.3 租户管理

租户页面以 `pages/tenant/feature.vue` 说明壳为主。后端已有成员、部门、分组、角色等路由，但 Web 端没有对应 API 模块或管理页面调用；不要把“后端已有接口”标注成“前端已对接”。

### 4.4 表单、流程和数据

- `@evolyn.do/form`、`@evolyn.do/workflow`、`@evolyn.do/data` 已沉淀设计器 / 工作区组件、Schema 和本地状态管理能力，属于可复用前端基础设施。
- 表单设计器画布显式为空，所有工具栏操作都会给出“后续提供”提示；没有真实表单 ID、名称或 Schema 的读取 / 保存。
- 流程设计器加载 `createDefaultWorkflowDocument()` 的本地文档；保存、预览和测试没有请求。
- 数据管理直接声明两条 `sourceRecords` 样例记录；搜索与分页只对这两条记录生效。
- 数据协作页的“保存”只显示成功消息；成员发布页和其余扩展 / 发布子页未接权限、公开链接或配置接口。

### 4.5 全局入口及认证中的未接项

- GitHub、微信登录按钮仅提示“待 OAuth 配置下发后开放”。尽管已有 `/auth/token` 的 OAuth 换令牌契约，前端尚缺提供商配置和授权跳转 / 回调处理。
- 顶栏的产品切换、模板中心、通讯录和帮助入口尚未落地。
- 个人安全页中的二次验证、禁止同时登录均为禁用状态；第三方账号仅显示当前聚合信息，未提供绑定管理。

## 5. 接口与页面差距矩阵

| 后端能力 | 前端现状 | 需要补齐的前端工作 |
| --- | --- | --- |
| 应用菜单 `GET /applications/code/:code/menu` | 未调用，仍使用硬编码预览资产 | 定义菜单 DTO / API；以 `entryMap`、`rootEntryIds` 渲染侧栏；空树展示引导；按菜单修订号刷新。 |
| 应用更新 / 删除 | API 已封装，无 UI 消费者 | 在应用后台或工作台加入名称、图标、归档、删除操作，并按 `capabilities` 控制。 |
| 成员、部门、分组、角色 | 后端路由已存在，租户后台仍为说明页 | 新建 `api` 模块及列表 / 编辑页面，接入权限、分页、错误码和空状态。 |
| 应用资产、表单 Schema、表单数据、流程服务 | 当前没有可消费的后端业务接口 | 先确定 API 契约与权限模型，再为 form / workflow / data 包提供按 `appCode`、`formId` 的 persistence adapter。 |
| 工作台、收藏、消息 | 当前没有相应后端接口 | 设计成员 / 租户范围、持久化模型、读取与写入接口；再替换本地 adapter 和样例目录。 |
| OAuth 提供商配置与回调 | 换令牌 API 已有，授权入口未实现 | 配置提供商元数据、授权 URL、回调路由及失败回跳；不在前端硬编码 client ID。 |

## 6. 建议实施顺序

1. **应用菜单接线**：这是当前应用详情已接通后最短的闭环。先替换硬编码资产导航，再处理空菜单和菜单刷新。
2. **租户组织管理**：优先接成员、部门、角色 / 分组等已有后端能力，替换租户后台的说明页。
3. **工作台服务端持久化**：明确工作台、收藏、消息的作用域和权限后，替换 `localStorage` / 内存样例。
4. **表单资产与 Schema 契约**：完成表单创建、详情和保存接口后，为现有 form 包接入 persistence adapter；再推进数据、发布和扩展配置。
5. **流程服务与 OAuth**：分别依赖跨服务 API 和公开配置 / 回调设计，应在契约稳定后接入，避免继续扩展前端样例状态。

## 7. 维护规则

- 新页面先在此文档的总览中登记，并标记“静态”“部分对接”或“已完成对接”。
- 只有页面实际调用接口并使用真实响应后，才可从“静态 / 未对接”改为“已完成对接”。仅新增后端路由、前端类型或 API 函数不足以变更状态。
- 移除样例数据或 `localStorage` adapter 时，同步更新第 4 节和第 5 节的差距说明。
