# Proposal

## Why

标签设计能力需要一个可信、可并发编辑且可追溯的模板生命周期，才能把设计态草稿安全地交付给后续预览与正式渲染能力。当前仓库已有标签模板相关在制代码和总体设计文档，但尚未形成可评审的行为契约与完成标准，需要先收敛为一个独立 OpenSpec 变更。

## What Changes

- 为租户成员提供标签模板的创建、列表、详情和软删除能力，并将模板绑定到当前租户内的有效表单。
- 以稳定公开编码标识模板，同一租户内每个有效表单至多绑定一个有效标签模板。
- 以 `LabelSchema 1.0` 完整文档保存设计草稿，并通过 `draftRevision` 乐观锁拒绝过期写入。
- 发布前校验草稿协议、表单归属和字段引用，并要求当前草稿版本已完成一次真实记录预览。
- 每次发布生成不可变、连续编号的完整模板快照；后续草稿修改不影响已经发布的版本。
- 对模板管理、真实数据预览和后续正式渲染分别执行租户隔离、资源权限、表单记录权限和字段权限校验。
- 补齐数据库迁移、稳定错误码、审计记录、前端 API 接入以及覆盖关键并发和越权场景的测试。
- 不在本变更中实现 PNG/PDF 导出、批量生成任务、对象存储、扫码 Token、打印机语言、复杂设计器交互或表达式执行器。

## Capabilities

### New Capabilities

- `label-template-lifecycle`: 标签模板从创建、草稿编辑、真实数据预览、发布版本到软删除的可观察行为，以及相应权限、租户隔离和并发语义。

### Modified Capabilities

无。当前 `openspec/specs` 尚无已归档能力，本变更将首次建立标签模板生命周期规范。

## Impact

- 后端：`apps/evolyn-core/internal/platform/label`、`internal/engine/label`、表单数据窄端口、服务装配与 RBAC 资源注册。
- 数据库：`apps/evolyn-core/migrations/000084_label_templates.*.sql` 中的模板表、不可变版本表、约束、索引和管理员基线授权。
- 前端：`apps/evolyn-web/apps/web/src/api/label.ts`、表单扩展中的二维码标签配置页，以及共享 `@evolyn.do/label` 协议与校验能力。
- API：`/api/v1/label-templates` 下的创建、列表、详情、草稿保存、真实数据预览、发布和删除接口。
- 错误契约：标签模板不存在、表单已绑定、草稿修订冲突、协议无效、未完成真实预览、字段不存在或无权查看等稳定业务错误码。
- 文档：保留 `docs/低代码平台/二维码标签/二维码打印引擎前后端功能开发设计.md` 作为总体设计来源，并在完成时同步其阶段状态与实现边界。
