# Design

## Context

现有标签域已经具备模板生命周期、SVG/PDF 渲染、异步批量任务、对象存储和多页 PDF 合并；数据管理页也已有稳定的行选择状态。当前缺口集中在运行态授权与编排：批量接口要求管理员级标签资源权限，记录适配器只验证查看权限，任务读取未使用已保存的请求人归属，页面声明的可下载尺寸与实际 `LabelSchema.page` 不一致，数据工作台动作模型也不支持截图所需的“更多”菜单。

实现遵循 [二维码打印引擎前后端功能开发设计](../../../../docs/低代码平台/二维码标签/二维码打印引擎前后端功能开发设计.md) 的既有 Renderer/Worker 分层，并以本 change 的规格补齐数据管理运行态能力。

## Goals / Non-Goals

**Goals:**

- 复用现有发布快照和批量渲染基础设施，建立按 `formCode` 使用的运行态接口。
- 将 `batch_print`、记录数据范围和任务所有权作为服务层强制边界。
- 让模板版本成为输出尺寸的唯一事实源，预览和最终 PDF 使用相同缩放规则。
- 在数据管理页提供可测试、可恢复、与截图一致的批量下载交互。

**Non-Goals:**

- 不允许运行态请求任意模板编码、任意 DPI 或任意页面尺寸。
- 不改造标签编辑器的元素模型和二维码扫码协议。
- 不增加同步大文件渲染、PNG ZIP、打印机直连或服务器端任务取消。

## Decisions

### 1. 运行态接口按表单定位，模板编码由服务端解析

新增按 `formCode` 定位的 profile、preview 和 batch-render 路径。服务端在当前租户内解析该表单唯一有效的已发布模板；普通成员只拿到运行态展示数据，不读取草稿。

选择该方案而不是复用模板列表接口，是因为模板列表属于 `label-templates` 管理面，授权给数据使用者会扩大权限；继续接收任意 `templateCode` 也会把跨表单校验责任推给客户端。

现有 `/labels/batch-render` 可在全部调用方迁移后删除或收窄为管理面兼容入口；本变更不保留两套不同授权语义的长期实现。

### 2. 表单域通过窄端口提供 `batch_print` 记录授权

标签域定义面向批量打印的记录读取端口，由表单域适配器执行既有权限组主体匹配、操作集、数据范围和字段矩阵逻辑。创建任务时对全部记录进行授权预检；Worker 在执行时再次通过同一端口读取，处理创建后发生的记录删除或权限变化。

创建时发现任一越权记录即拒绝整批，避免以 `partial_success` 形成记录存在性侧信道。任务执行期的数据变化或单页渲染问题才允许部分成功。

备选方案是把 `batch_print` 加入表单详情的记录无关 `operations` 投影并仅在前端控制入口；该投影可用于显示，但不能替代记录级服务端校验。

### 3. 输出尺寸预设随发布快照保存

在标签协议的发布设置中增加 `outputPresets`，每项包含稳定 `id`、展示名、宽、高、单位和 DPI。运行态请求只提交预设 ID。发布校验要求预设物理宽高与设计画布保持相同比例，Renderer 按单一比例缩放元素几何和字体到目标页面。

像素尺寸由后端按 `round(mm / 25.4 * dpi)` 计算并返回，前端仅展示结果。这样可消除设置页硬编码文案与实际 PDF 页规格不一致，也避免各端使用不同舍入规则。

任务行冻结 `output_preset_id`、宽、高、单位和 DPI；模板版本快照仍是协议事实源。显式冻结任务规格可以让排队、重试和审计不依赖后续代码默认值。

存量已发布模板迁移时根据画布方向生成一个 `original` 预设，保证历史模板可继续使用；用户重新发布后才能获得设计器配置的新尺寸集合。回滚时保留新增列和快照字段，旧服务忽略它们，不删除已生成任务数据。

### 4. 任务读取采用“请求人或租户标签管理员”规则

任务查询与下载在租户隔离查询之后检查 `requestedByMemberId == currentMemberId`；不相等时再检查标签管理权限。对无权访问和跨租户任务统一返回任务不存在，避免泄露任务归属。

对象存储下载继续通过现有文件服务签发，不向客户端暴露存储路径。任务文件沿用既有生命周期与清理策略。

### 5. 前端使用通用层级动作与独立弹窗状态机

扩展数据工作台 `DataAction`，允许动作携带 `children`，由工具栏统一渲染一级“更多”和二级菜单；页面只声明业务动作，避免为二维码下载硬编码专用菜单。既有扁平动作保持兼容。

下载弹窗维护 `idle/profile-loading/preview-loading/ready/submitting/processing/success/partial-success/failed` 状态。预览按当前记录与尺寸懒加载并缓存；任务提交期间禁用按钮；轮询使用单一可清理计时器，弹窗关闭和组件卸载都中止预览请求、停止轮询并释放对象 URL，但不调用服务器取消。

“修改二维码标签”由 profile 返回的 `canManageTemplate` 决定。视觉样式只使用现有 CSS 变量；桌面端按截图左右布局，小屏幕退化为上下布局。

### 6. 错误与可观测性

新增稳定错误覆盖：运行态模板不可用、输出预设无效、批量打印无权限和任务不可访问；前端 `errorCodes.ts` 与 API 类型同步。任务继续记录总数、成功数、失败数、进度和条目错误；日志携带 tenant、member、form、task，不记录字段值或二维码令牌。

队列不可用、对象存储不可用和 Renderer 基础设施错误沿用现有重试与最终失败收口。创建任务保持“事务提交后入队”，入队失败将任务标记为失败。

## Risks / Trade-offs

- [逐条预检最多 1000 条记录可能增加创建延迟] → 由表单域提供批量授权查询，单次加载授权范围并按输入顺序返回，避免 N+1。
- [等比缩放可能改变字体换行和截断结果] → 预览与最终 PDF 共用同一缩放服务，发布与弹窗都显示截断警告，并用大小尺寸建立黄金测试。
- [存量模板只有原始尺寸，无法立即出现截图中的两种尺寸] → 迁移只保证可用性；设置页明确引导管理员配置并重新发布预设，不伪造可能失真的比例。
- [通用层级动作会影响其他数据工作台使用方] → children 为可选字段，保留原有扁平渲染和事件协议，并补充组件回归测试。
- [任务完成后权限被撤销] → 下载时仍验证任务所有权和当前租户身份；本期不因表单权限后来撤销而删除已生成文件，与其他异步导出语义保持一致。

## Migration Plan

1. 先部署数据库迁移和兼容读取：任务冻结规格字段可空，存量版本缺少预设时投影 `original`。
2. 部署后端协议、窄端口、运行态接口和 Worker 缩放支持；保留现有任务处理能力并完成集成测试。
3. 部署前端类型、通用更多菜单和下载弹窗，切换数据管理调用到按表单接口。
4. 清理旧的硬编码尺寸文案和不再使用的普通用户批量入口，更新设计文档与接口文档。
5. 回滚前端时后端新接口和可空字段可继续存在；回滚后端时停止创建带新预设的任务，已入队任务需由新 Worker 清空后再回滚。

## Verification Strategy

- 单元测试：输出预设协议与比例校验、毫米到像素舍入、缩放、任务所有权、输入去重和弹窗状态转换。
- 后端集成测试：同租户成功、无 `batch_print`、记录范围外、跨租户、部分成功、任务请求人查询下载、模板重发布后旧任务不变。
- 前端组件测试：选择状态、更多菜单、无模板提示、预览翻页、尺寸切换、重复提交防护、轮询成功/部分成功/失败和关闭清理。
- 端到端测试：创建并发布含两种尺寸的模板，数据页选择多条记录，预览后下载多页 PDF，核对页数、页面物理尺寸和二维码可扫描性。
- 人工视觉确认：在目标分辨率下对照截图检查弹窗布局、间距、选中态、禁用态和窄屏退化。
