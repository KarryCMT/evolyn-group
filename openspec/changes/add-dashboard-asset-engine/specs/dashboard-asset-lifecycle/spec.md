## ADDED Requirements

### Requirement: 仪表盘预创建
系统 SHALL 在有权限的成员发起新建仪表盘时立即创建具有稳定公开编码的仪表盘资产和空草稿，并返回可用于进入设计工作区的详情；资产、草稿和应用菜单节点 MUST 原子提交。

#### Scenario: 在应用根级预创建仪表盘
- **GIVEN** 当前成员属于目标应用所在租户且拥有仪表盘创建权限
- **WHEN** 成员以默认名称和目标应用发起新建仪表盘
- **THEN** 系统返回唯一且稳定的仪表盘公开编码、初始草稿修订号和未发布状态
- **AND** 应用菜单中出现指向该公开编码的根级仪表盘节点

#### Scenario: 在指定分组中预创建仪表盘
- **GIVEN** 目标分组属于同一租户和同一应用且仍然有效
- **WHEN** 成员携带该分组的菜单编码新建仪表盘
- **THEN** 系统在同一事务内创建仪表盘并把菜单节点挂到该分组下

#### Scenario: 目标分组失效时整体回滚
- **GIVEN** 客户端携带的父分组已删除、属于其他应用或不是分组节点
- **WHEN** 成员发起新建仪表盘
- **THEN** 系统返回稳定的父分组无效错误
- **AND** 不留下仪表盘、草稿、菜单节点或已消耗的配额

### Requirement: 创建请求幂等
系统 MUST 接受客户端生成的创建请求幂等标识，并在同一租户和操作者范围内保证同一请求最多创建一个仪表盘。

#### Scenario: 创建响应丢失后安全重试
- **GIVEN** 第一次创建已经成功但客户端未收到响应
- **WHEN** 同一成员使用相同幂等标识和相同请求内容重试
- **THEN** 系统返回第一次创建的同一仪表盘详情
- **AND** 不创建第二个菜单节点或重复扣减配额

#### Scenario: 幂等标识与请求内容冲突
- **GIVEN** 一个幂等标识已经绑定到已受理的创建请求
- **WHEN** 同一成员以该标识提交不同的应用、父分组或资产名称
- **THEN** 系统拒绝请求并返回稳定的幂等冲突错误

### Requirement: 仪表盘租户与权限边界
系统 MUST 要求仪表盘资产操作经过认证、租户状态校验和仪表盘资源授权，并 MUST 将跨租户资产表现为不存在。

#### Scenario: 同租户有权限成员读取详情
- **GIVEN** 仪表盘属于当前租户且当前成员拥有详情读取权限
- **WHEN** 成员按仪表盘公开编码读取详情
- **THEN** 系统返回该仪表盘的元数据、草稿和修订信息

#### Scenario: 无权限成员被拒绝
- **GIVEN** 当前成员属于同一租户但没有对应的创建、更新、发布或删除权限
- **WHEN** 成员执行受保护操作
- **THEN** 系统返回稳定的禁止访问错误
- **AND** 不改变资产、菜单或版本状态

#### Scenario: 跨租户访问不泄露资产
- **GIVEN** 当前会话租户与目标仪表盘所属租户不同
- **WHEN** 会话按目标公开编码读取或修改仪表盘
- **THEN** 系统按资产不存在处理
- **AND** 不泄露名称、应用归属、发布状态或版本信息

### Requirement: 草稿乐观并发
系统 SHALL 以草稿修订号保护全量草稿保存；保存成功 MUST 返回递增后的修订号，过期修订 MUST 被拒绝且不得覆盖较新的草稿。

#### Scenario: 使用当前修订号保存有效草稿
- **GIVEN** 成员加载了当前草稿及其修订号
- **WHEN** 成员提交通过协议校验的完整草稿和当前修订号
- **THEN** 系统原子保存草稿并返回新的修订号

#### Scenario: 过期草稿保存冲突
- **GIVEN** 另一编辑者已经保存并推进了草稿修订号
- **WHEN** 当前编辑者仍使用旧修订号保存
- **THEN** 系统返回 HTTP 409 和稳定的仪表盘草稿冲突错误
- **AND** 已保存的新草稿保持不变

#### Scenario: 无效草稿被终审拒绝
- **GIVEN** 草稿含未知组件、重复标识、非法布局或无效数据绑定
- **WHEN** 成员保存草稿
- **THEN** 系统拒绝保存并返回包含稳定路径和问题码的校验问题清单
- **AND** 草稿修订号不递增

### Requirement: 资产元数据与菜单一致性
系统 MUST 在修改仪表盘名称、图标、颜色或删除仪表盘时，在同一事务内同步对应应用菜单节点及菜单修订号。

#### Scenario: 修改仪表盘展示信息
- **GIVEN** 成员拥有仪表盘修改权限且资产属于当前应用
- **WHEN** 成员更新名称、图标或颜色
- **THEN** 仪表盘详情和应用菜单快照展示相同的新信息
- **AND** 菜单修订号只递增一次

#### Scenario: 删除仪表盘
- **GIVEN** 成员拥有仪表盘删除权限
- **WHEN** 成员删除仪表盘
- **THEN** 系统软删除资产并原子摘除菜单节点及相关个人收藏
- **AND** 后续详情、设计态和运行态入口均不再返回该仪表盘

### Requirement: 仪表盘配额与审计
系统 MUST 在并发安全的配额判定通过后创建仪表盘，并 MUST 对创建、修改、发布、复制和删除记录可追溯的业务审计事件。

#### Scenario: 配额达到上限
- **GIVEN** 当前租户的仪表盘数量已经达到有效权益上限
- **WHEN** 两个或更多创建请求并发到达
- **THEN** 系统只允许不超过剩余额度的请求成功
- **AND** 其余请求返回稳定的配额超限错误

#### Scenario: 成功操作写入审计
- **GIVEN** 一个仪表盘资产操作已经成功提交
- **WHEN** 管理员查询企业日志
- **THEN** 日志包含操作者、租户、应用、仪表盘公开编码、动作和必要的前后快照
