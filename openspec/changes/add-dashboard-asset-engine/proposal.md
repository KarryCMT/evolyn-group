## Why

应用工作区已经提供“新建仪表盘”入口，前端也已有 GridStack 布局、VChart/VTable 渲染基础，但仪表盘仍不是可持久化、可发布、可授权的应用资产，用户无法像创建表单一样预创建仪表盘并进入设计工作区。现在需要补齐从资产创建、数据查询、设计保存到发布运行时的完整纵向链路，避免继续把企业工作台布局文档误当成业务仪表盘协议。

## What Changes

- 新增仪表盘资产生命周期：点击“新建仪表盘”即以默认名称预创建资产，服务端生成稳定公开编码，并在同一事务内创建空草稿、挂载应用菜单节点、递增菜单修订号；支持详情、改名、删除和草稿乐观锁保存。
- 新增独立仪表盘工作区和路由，提供仪表盘设计、扩展功能、发布、预览入口；复用现有布局画布并补齐空画布、组件选择、属性编辑、保存冲突处理和未保存离开拦截。
- 扩展 `@evolyn.do/dashboard` 的领域协议，在通用布局之上增加受控 Dataset、Query DSL、字段绑定和组件配置；首批支持统计图和明细表，持久化平台语义而非原生 VChart/VTable 配置。
- 新增仪表盘查询链路：设计预览按已保存草稿查询，应用运行时按不可变发布快照查询；浏览器只提交组件标识、筛选值和分页参数，服务端完成租户隔离、字段与数据范围校验、查询编译和执行。
- 新增仪表盘发布与运行时：草稿通过服务端终审后生成不可变版本，应用菜单按当前成员权限和发布状态投影可见性，运行时只消费最后发布快照并复用同一渲染器。
- 扩展仪表盘高级能力：全局筛选、组件联动、独立移动端布局、应用内复制和发布成员范围；所有交互与范围配置进入版本化仪表盘文档并由服务端终审。
- 补齐 `dashboards`、`dashboard-actions` 等权限资源、稳定错误码、审计事件和套餐配额口径，并将菜单动作注册表中的 dashboard 占位能力切换为真实端点能力。
- 保持现有租户工作台 `/workbench` 的可观察行为不变；工作台继续使用其企业级配置与 revision，业务仪表盘使用独立资产、草稿和发布模型。

## Capabilities

### New Capabilities

- `dashboard-asset-lifecycle`: 仪表盘预创建、稳定编码、详情、改名、删除、草稿乐观锁以及与应用菜单原子一致的资产生命周期。
- `dashboard-authoring`: 独立设计工作区、空画布、组件配置、保存、冲突提示、预览入口和未保存离开保护。
- `dashboard-data-query`: Dataset、字段目录、Query DSL、统计图与明细表配置，以及受权限约束的设计态和运行态查询。
- `dashboard-publication-runtime`: 草稿发布、不可变版本、发布状态可见性、运行时 bootstrap 和应用内仪表盘渲染。
- `dashboard-interactions`: 全局筛选、组件联动、移动端布局、应用内复制和发布成员范围。

### Modified Capabilities

- 无。当前主规格尚未声明仪表盘能力；现有工作台与菜单实现作为本次新增能力的集成基础，其既有外部行为不变。

## Impact

- 后端新增 `internal/platform/dashboard` 资产域及必要的纯查询/协议内核，新增仪表盘资产、不可变版本、发布范围等版本化 SQL 迁移，并接入既有 `TxManager`、租户 Callback、审计、配额和统一业务错误码。
- `internal/platform/app` 增加仪表盘菜单维护与目录投影窄端口；`internal/platform/iam/authorization` 增加仪表盘资源、动作授权和基线补授；服务器装配注册新控制器、仓储和跨域适配器。
- 前端扩展 `packages/dashboard`，复用 `packages/engines/query` 与 `packages/ui` 的 VChart/VTable 封装；主应用新增 dashboard API、路由、设计/预览/发布页面和应用运行时适配器。
- 应用工作区的当前资产路由状态由表单专用语义收敛为通用资产语义，并移除仪表盘创建、编辑和运行时占位提示。
- 同步更新 Swagger、前端共享 DTO 与 `errorCodes.ts`、权限资源目录、`docs/低代码平台/前端功能模块现状.md` 及仪表盘长期设计文档。
